# ShockGraph AI 제품 목표와 예측 검증 이후의 선택

개정일: 2026-10-20. 이 문서는 [제품 명세](../shockgraph-ai-project-spec.md),
[TLT 모델 설계](tlt-volatility-model-design.md), [제품 화면](product-ui-direction.md),
[주주 인증 채팅](shareholder-community-roadmap.md)을 연결하는 **제품 의사결정 기준**이다.
목표와 실험 계획이며 이미 출시했거나 사용자 수요를 입증했다는 뜻은 아니다.

## 하나의 사용자 문제

첫 사용자는 미국 채권 ETF TLT를 보면서 CPI·FOMC 등 발표를 앞둔 개인투자자다.
사용자가 궁금한 것은 “시장이 당시 어떤 결과를 예상했고, 그 불확실성이 내 ETF의
위험에 대한 기존 판단을 실제로 개선했는가?”이다. 첫 분석 자산과 미래 정답은
**TLT의 향후 5·20거래일 실현 변동성**으로 고정한다. 주가의 방향, 수익률,
매수·매도 시점을 맞히는 서비스로 설명하지 않는다. 충분한 데이터와 성능이
확인되면 SPY·XLE 및 공동 포트폴리오 위험으로 확장한다. 한국 개별주식 방은
이 미국 거시·ETF 실험의 자동 확장이 아니다.

예측이 승인되면 검증된 미래 변동성 추정치와 당시 확률·성과를 제공한다.
그렇지 않으면 대안은 일기를 쓰는 서비스가 아니라 **발표 전 시장 기대 →
최초 발표치 → 시점이 맞는 TLT·금리의 사후 관측을 자동으로 결합하고,
유사한 과거 사건의 분포와 비교하는 분석 작업**이다. 이것도 사용자 가치와
자료 권리를 아직 입증하지 못한 후보일 뿐이다.

## 첫 연구와 판정

| 구분 | 같은 날짜에서 비교할 내용 | 결정에 쓰는 질문 |
|---|---|---|
| A | 최근 변동성·EWMA | 가격만으로 충분한가? |
| B | 가격·시점이 맞는 전통 거시 정보의 규제 모형 | 기존 정보의 추가 가치는? |
| C | B와 동일 모형에 **발표 전 확률 특징만 추가** | `C−B`로 확률의 추가 가치를 구분할 수 있는가? |
| D | C와 동일 입력의 작은 머신러닝 모형 | 비선형 모델이 C를 더 개선하는가? |

자료 권리, `available_at <= prediction_at < release_at`, 공통 날짜·발표 수와
새 독립 시험 기간이 먼저다. 5·20일 정답이 겹치므로 일별 행을 독립 사건 수로
세지 않는다. 2024년 이후 가격 탐색 결과는 이미 관찰해 새 모델의 최종 시험으로
다시 쓸 수 없다. 기존 가격 전용 Ridge가 EWMA보다 MAE에서 뒤진 것은
**확률 C의 실패가 아니다**. 과거 CPI 계약의 Brier 결과도 TLT 위험 성능이 아니다.

승인하려면 사전 고정한 독립 시험에서 C가 A·B보다 실용적으로 MAE를 낮추고,
짝지은 차이의 불확실성 구간이 0 아래이며 QLIKE가 뚜렷하게 악화하지 않아야 한다.
어느 기준을 통과했는지 자산·기간별로 표시하고, 불확실하면 성능을 주장하지 않는다.
D가 개선하더라도 그 이유를 **확률 정보**로 돌리려면 같은 머신러닝 모형에서
확률을 뺀 비교 후보도 별도로 시험해야 한다. 자료가 부족하면 복잡한 모델을
계속 추가하지 않는다.

## 성과에 따른 제품 경로

| 관찰 결과 | 제품 결정 | 사용자에게 보여줄 것 |
|---|---|---|
| 시점별 자료·권리·독립 시험 부족 | `HOLD`: 효과를 모른다. 수집·커버리지 검증에 집중 | 공개 가능한 일정·출처·결측 상태. 실증 예측 수치는 없음 |
| C가 A·B를 독립 시험에서 개선하고 이용권 확보 | 위험 분석 제품을 첫 진입점으로 출시 | 5·20일 추정 변동성, 오차·불확실성·실패 사례, 당시 확률과 관측시각 |
| C의 개선이 없거나 불확실함 | ‘더 잘 맞힌다’는 주장을 중단. **자동 사건·자산 영향 분석 리포트**가 실제 조사 시간을 줄이는지 별도 시험 | 발표 전 기대, 최초 발표치, 당시와 발표 후의 금리·TLT 관측, 과거 유사 사건의 분포·표본 수·출처. 미래 예측이나 단일 사건의 인과효과로 표현하지 않음 |
| 자동 분석도 기존 도구 대비 가치·반복 사용 미확인 | 대중 커뮤니티를 만들지 않고 해당 제품 가설을 중단하거나 고객 문제를 다시 정의 | 실패한 비교·자료 제약과 확인된 범위 |

**기록 자체는 차별점이 아니다.** Notion에는 이미
[투자·트레이딩 기록 템플릿](https://www.notion.com/templates/category/trading-journal)이
있다. 일정만으로도 [FRED의 발표 달력](https://fred.stlouisfed.org/releases/calendar),
금리 확률만으로도 [CME FedWatch](https://www.cmegroup.com/markets/interest-rates/cme-fedwatch-tool.html),
발표 일정·컨센서스만으로도 [Koyfin](https://www.koyfin.com/data-coverage/global-economics/)과
경쟁해야 한다. 이 서비스의 실험 가치는 그 원천을 **예측 당시 공개 시점과
자산별 관측 구간을 보존한 채 자동 결합·비교**하는 데서만 찾을 수 있다.
그 조합도 독점 기능이라고 주장하지 않는다.

사용자 시험은 투자 기록을 작성하는지보다 같은 CPI/FOMC 사건에 대해
기존 도구를 직접 오가며 작성한 리포트와 자동 리포트의 **완료 시간·오류·
재사용 의사**를 비교한다. 외부 사용자에게 같은 과제를 맡기고 평가 기준을
사전에 고정한다. 데이터 권리나 공통 표본이 없어 시점별 결합을 못 하거나,
실제 조사 시간이 줄지 않고 사용도 반복되지 않으면 대안 제품 가설을 접는다.
필요하면 Notion/Markdown으로 내보내도록 하고 별도 투자 노트 편집기를 만들지 않는다.

## 커뮤니티는 어떤 조건에서 여는가

처음부터 글쓰기·채팅을 사용자 유지 장치로 만들지 않는다. 실제 가치가
확인된 자동 사건·자산 분석 리포트를 먼저 공개하고, 사람들이 그 리포트의
자료 정의나 해석을 함께 검토해야 하는지 관찰한다. 발표 전 가설의 작성 시각,
사후 결과와 비교할 수 있는 구조는 **분석의 보조 기능**일 수 있지만 Notion을
대체할 별도 서비스 목표가 아니다. AI는 출처가 확인된 자료 요약만 돕고
목표가·매매 지시나 근거 없는 수치를 생성하지 않는다.

모든 주식의 실시간 채팅을 열지 않는다. 현재 네이버페이 증권은
[종목토론방의 주주 표시 및 주주오픈톡](https://help.pay.naver.com/faq/list.help?categoryId=11143)을
안내한다. 그러므로 **주주 인증만으로 차별화했다고 주장하지 않는다**. 특정
리포트의 데이터와 해석을 토론하고 싶다는 반복적인 요구가 입증되면
그때 비동기 의견 기능을 작게 시험한다. 실시간 방이 필요하다는 근거가
추가로 생겨도, 기존 설계의 주주 전용 방은
허가된 보유 확인 공급원과 권한·운영 테스트를 통과한 뒤에만 연다.

비동기 글도 허위 정보·광고·조작 시도를 다뤄야 하므로 신고, 차단, 삭제,
운영자 감사 기록과 반복 위반 대응을 출시 범위에 포함한다. 사용자 의견,
공식 통계, 모델 결과는 시각적으로 분리한다. 수익 보장·개별 종목 매매 지시·
유료 리딩방을 제품 가치로 팔지 않는다. 금융위원회는 온라인 양방향 유료
회원제 투자 조언이 투자자문업의 규율 대상이라고 설명한다. 광고나 유료
서비스를 붙이기 전에는 실제 제공 행위의 법적 성격과 운영 정책을 검토한다.
[금융위원회 안내](https://www.fsc.go.kr/no010101/82887)

## 구현·수익의 단계

1. 현재 단일 저장소의 데이터 수집·시점 검증·오프라인 평가를 진행한다.
   **웹 구현 전에** 같은 사건의 수동 조사와 자동 사건·자산 분석의 시간·오류를
   비교할 시범 리포트를 만든다. 허가된 자료로 차이가 확인되면 FastAPI는
   승인된 위험 스냅샷 또는 출처·시각이 있는 과거 사건 리포트를 구별해 반환한다.
   Next.js는 결과와 데이터 제약을 로그인 없이 표시한다.
2. 자동 분석 리포트가 반복 사용되고 토론 요구가 생기면 그 리포트에 연결된
   작은 비동기 의견·신고 기능을 시험한다. 처음부터 범용 게시판이나 별도
   실시간 채팅 서버·RabbitMQ·Kafka를 두지 않는다.
3. 이후 실시간 종목방 수요가 입증되고 인증 계약이 확보되면
   [주주 인증 채팅 계약](shareholder-community-roadmap.md)에 따라 서버 측
   신원·보유 권한을 조회/구독/전송마다 검사한다. `doChallenge`의 읽음 커서,
   다중 세션, Redis 캐시 등은 검토 대상이지 보안 검증 없이 이식할 코드가 아니다.
4. 공개 정보 페이지의 광고는 반복 방문과 표시 데이터의 이용권을 확인한 뒤
   사업 가설로 시험한다. 트래픽이 없는 단계의 광고 수익을 제품 성공의 근거로
   가정하지 않는다. 유료 개인별 종목 신호나 방 입장료는 초기 수익 모델에 넣지 않는다.

현재 구현된 것은 합성 가격 기준선과 비공개 가격 전용 탐색 비교다.
발표 전 확률 결합 모델, 승인된 실자료 위험 카드, 공개 웹, 커뮤니티,
보유 인증 및 광고 수익은 **모두 미구현·미검증**이다.
