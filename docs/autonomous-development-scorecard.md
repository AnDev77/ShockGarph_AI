# 자율 개발과 제품 방향 검증표

최초 작성: 2026-10-26. 이 문서는 **앞으로의 모든 작업**을 시작하고 마칠 때 에이전트가 먼저 읽고 갱신하는 판단 기준이다. [제품 목표](product-goal-and-fallback.md)와 [진행 기록](progress.md)을 우선하며, 이 문서만으로 성능·사업성을 승인하지 않는다. 금융 연구 자료는 새 작업을 시작할 때 발행일·개정일·연구 대상과 현재 구현의 차이를 다시 확인한다.

## 작업 반복 규칙

1. 시작 전에 현재 PR, 마지막 실행, 실패 원인과 변경 전 기준선을 확인한다. 작은 수정으로 포장하지 않고 하나의 사용자 가치 또는 검증 가능한 기술 위험을 고른다.
2. 구현과 동시에 적절한 사례의 시험을 추가한다. 금융 계산을 고칠 때는 실패하는 시험을 먼저 만든다. 원본 시각과 불변성, 정답 누수, 겹치는 정답, 권리 제한을 점검한다.
3. 코드 변경마다 wheel 빌드와 내용 검사, `make quality`, `make test`를 실행한다. PR의 비밀값 없는 품질 게이트가 같은 결과를 재현해야 한다. 실패하면 원인과 재현 절차를 기록하고 수정한다.
4. `docs/progress.md`에 이전 상태·이번 증거·남은 조건을, `docs/troubleshooting.md`에 실제 장애만, `docs/reviews/<핵심-기능>-review.md`에 객관적 평가를 남긴다. 결과 설명은 시험 대상·표본·수치·한계를 각각 명시한다.
5. PR은 초안으로 유지한다. 릴리스·합병·예측 성능 공개는 검증 조건을 충족한 별도 판단으로 다룬다.

## 이후 작업마다 확인할 연구·업계 근거

- [연준 FEDS 연구, 2025년 발행·2026년 9월 개정](https://www.federalreserve.gov/econres/feds/linear-and-nonlinear-econometric-models-against-machine-learning-models.htm)은 S&P 500과 미국 개별주식 40개의 실현 변동성에서 HAR·ARFIMA·상태전환 HAR와 XGBoost·신경망을 1주·월간 등 기간별로 비교했다. ML이 일부 HAR를 개선했지만 계량 모형 전체보다 일관되게 우월하지 않았다. **우리에게 적용:** 5일과 20일을 별개로 평가하고, EWMA·GARCH 외에 단순 HAR와 적절한 기간별 계량 후보를 사전 등록한 뒤 같은 표본으로 비교한다. 일봉만 가진 현재 자료를 논문의 고빈도 실현 변동성 입력과 동일하다고 부르지 않는다. 이 연구는 연준 저자의 연구 결과이며 연준의 공식 투자 지침은 아니다.
- 이 연구의 검증 지표는 MAE뿐 아니라 MSFE·QLIKE·모형 신뢰집합·Diebold–Mariano 검정·VaR/ES의 실용성도 포함한다. **우리에게 적용:** 먼저 같은 정의의 정답과 비중첩 또는 의존성 보정 구간을 확보한다. 현재 독립 표본이 희소하므로 지표 목록을 따라 계산했다는 이유만으로 우위를 선언하지 않는다.
- [BlackRock의 자본시장 가정](https://www.blackrock.com/institutions/en-global/institutional-insights/thought-leadership/capital-market-assumptions)은 단일 중앙 전망의 불확실성과 여러 거시 경로, 자산 간 위험·수익률·상관관계를 함께 다룬다. [위험 대시보드 방법론](https://www.blackrock.com/corporate/insights/blackrock-investment-institute/interactive-charts/geopolitical-risk-dashboard)은 사건에 민감한 자산과 역사적 유사 사례를 이용한 시나리오 충격을 제시한다. **우리에게 적용:** 개별 TLT·SPY 위험을 먼저 증명하고, 시나리오와 두 자산의 관계는 별도 설명으로 남긴다. 현재 자체 자료로 주가 방향이나 사건의 인과효과를 추정했다고 주장하지 않는다.

새 통계·딥러닝 후보를 추가하는 작업은 `연구 원문 → 목표 변수와 입력 빈도 → 현재 자료 충족 여부 → 기준선·시간순 평가 → 비용 대비 개선 → 제품에서 표현 가능한 범위`를 리뷰에 작성한다. 자료 빈도나 표본 수가 맞지 않으면 `HOLD`하고 먼저 수집·권리·시점 재현 문제를 해결한다. 업계 사례는 연구 질문을 만드는 근거이지 우리 모델의 성능 증거가 아니다.

## 오늘의 객관적 판단

빌드 시험에서 기존 wheel은 메타데이터만 들어 있는 것을 발견했다. 여섯 개 실제 Python 패키지를 명시적으로 포함하고 핵심 소스 파일이 산출물에 있는지 검사하도록 수정했다. 이는 **배포 가능성**의 문제를 해결하지만 데이터 사용 권리, 모델의 미래 성능 또는 사용자 수요의 증거를 추가하지 않는다. 현 단계에서 우선순위는 사전 빈티지를 계속 누적하는 것이며, HAR나 딥러닝의 추가는 기존 5·20일 평가 표본의 독립성이 확보된 뒤 결정한다.

## 향후 거래일 자동 수집 조건

예약은 뉴욕 시간 평일 07:10으로 설정한다. `--end`는 전날 날짜를 사용하므로 월요일에는 직전 금요일, 화요일에는 월요일의 마지막 완료 가격을 받는다. 원격 최신 index와 완료 거래일이 같으면 수집을 생략하고 읽기 검증만 한다. GitHub Actions의 `schedule`은 기본 브랜치에 해당 워크플로가 들어오기 전에는 실행되지 않으므로, 현재 초안 PR 단계에서는 **자동 수집이 가동 중이라고 주장하지 않는다**. 기본 브랜치 반영과 운영 권한·실행 로그 확인이 활성화 조건이다. 예약 실행의 지연 또는 누락은 가능하므로 누락된 날짜와 사전 시각 조건을 별도로 보고해야 한다.

[독립 PR 게이트](https://github.com/AnDev77/ShockGarph_AI/actions/runs/40257104426)에서 wheel 소스 7개, Ruff·Pyright 0건, 전체 178개 시험이 성공했다. 기존 index 개수 2개는 이번 실행에서도 2개로 유지됐고, 새로운 사전 정답 표본은 아직 0개다.

### 실제 원격 고유 시작일 검증

[보관 감사 실행](https://github.com/AnDev77/ShockGarph_AI/actions/runs/40258151489)에서 `audited_index_count=2`, `unique_origin_session_count=1`, `duplicate_forecast_index_count=1`을 확인했다. 보관된 거래일은 2026-10-23 하나이며 5·20일 성숙 정답과 외부 사용자 효용 검증은 0건이다. [품질 게이트](https://github.com/AnDev77/ShockGarph_AI/actions/runs/40258154805)는 wheel 소스 7개, 정적 오류·경고 0건, 전체 179개 시험을 통과했다. 250개 index 한도에 도달하기 전에는 원본 전체 재검증의 읽기 요청 비용·시간과 증분 감사 방식을 다시 설계한다.
