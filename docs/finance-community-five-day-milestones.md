# 거시 발표·성장주 ETF 관측과 대화방: 5일 완료 기준

작성일: 2026-10-27. 기간: 10월 27일(화)~31일(토), 한국 시간 기준 5일. 이 문서는 범위와 검증 기준을 고정한다. 계획 자체는 기능 완료를 의미하지 않는다.

10월 27일 사용자 결정: 첫 사용 경험은 **관심 자산 선택 → 관련 공식 발표 카드 → 같은 기간 자산 관측 → 카드에 연결된 대화**다. 메모는 사건 카드의 선택적 의견으로만 다루고 별도 투자 노트 서비스를 만들지 않는다. 근거와 수요의 한계는 [제품 결정](reviews/macro-event-investor-product-decision.md)에 기록했다. 현재의 사건 연결 코드는 도메인 계산이며 회원별 영속 관심 목록·API·실제 발표 수집·화면이 끝난 것은 아니다.

제품의 최종 우선순위와 근거는 [경제 발표·관심 자산 제품 결정](reviews/macro-event-investor-product-decision.md)에 기록했다. 첫 사용자는 미국 주식·ETF를 살펴보는 한국어 사용자이고, 사건 출처·한국 시각·동일 구간의 자산 관측을 먼저 검증한다. 한국 이용자의 반복 사용과 광고 수익은 아직 확인하지 않았다.

## 수요 판단과 첫 화면

장기 보유자가 단기 변동성 숫자 때문에 매일 ETF를 매도·재매수할 것이라는 가정은 채택하지 않는다. 첫 방문 이유는 관심 ETF의 구조와 현재 검증 가능한 정보 확인, 의견 교환이라는 가설로 둔다. 이 역시 검증된 수요가 아니므로 실제 이용자에게 다시 방문할 이유가 있는지 별도로 확인한다. 변동성 예측은 매도 신호가 아니라 자료 시각과 검증 상태를 붙인 보조 카드다. 특정 금리·거시 사건이 그날 ETF 가격을 움직였다고 인과적으로 단정하지 않는다.

사용자의 10월 27일 수정 제안에 따라 첫 방문 가설을 [FOMC·QQQ 관측 범위 리뷰](reviews/macro-tech-event-scope-review.md)로 조정했다. 관심 목록과 채팅만으로 재방문이 발생한다고 주장하지 않는다. 10월 28일 FOMC를 첫 사건 후보로 삼되 QQQ 원본·발표 원문·공개 권리가 확인되지 않으면 결과 수치를 만들지 않는다.

## 10월 31일에 보여줄 결과

- 사용자가 첫 FOMC 발표 카드에서 공식 발표 시각·출처, QQQ와 SPY의 동일 기간 관측 가능 상태, 관련 대화방을 볼 수 있다. 확인된 권리가 없으면 변화율 숫자 없이 원문 링크와 자료 상태를 표시한다. 기존 TLT·SPY 가격 기반 위험 예측은 별도 연구 카드로 유지한다.
- 아직 실제 결과가 없는 예측은 “결과 확인 전”이라고 표시한다. 실제로 검증하지 않은 B 모델, 인공지능의 우위, 매수·매도 신호를 표시하지 않는다.
- 로그인한 사용자가 종목별 대화방에 글을 쓰고 실시간으로 받으며, 새로 접속한 사용자가 과거 메시지를 읽을 수 있다. 서버는 토큰에서 작성자 신원을 얻고 전송·구독 권한을 검사한다.
- 재현 가능한 배포 환경에서 Nginx가 정상 버전에 트래픽을 보내고, 새 버전 상태 검사 실패 시 기존 버전을 유지한다. 실제 클라우드 배포는 호스트·도메인·비밀값을 사용할 수 있을 때만 완료로 판정한다.
- 화면의 실제 가격·원본 데이터 재배포는 공급원 이용 권리가 확인될 때까지 하지 않는다.

## 일정을 지키기 위한 제한

- 첫 서비스는 FOMC 한 사건의 공식 발표·QQQ/SPY 관측 상태와 로그인 대화방을 다룬다. 예측 위험 카드는 연구 경로로 보존하되 첫 화면의 주된 이유로 주장하지 않는다. 보유 인증, 주문, 추천, B 모델 성능 주장, 여러 증권사 연동은 포함하지 않는다.
- 기존 doChallenge 채팅 로직은 참조하되 운동 모임 회원 여부를 금융 종목의 접근 권한으로 재사용하지 않는다. 자산별 공개 읽기·로그인 글쓰기 정책을 명시해 서버에서 집행한다.
- 두 저장소를 일주일 안에 하나로 합치는 작업, Kubernetes·Jenkins 도입은 수행하지 않는다. Kafka는 허용하되 [검증된 수집 사건의 아웃박스 전달](kafka-event-pipeline-decision.md)로 별도 기능 PR을 만든다. 이 준비가 아직 안 돼도 5일간의 사용자 화면·채팅 경로는 진행한다. GitHub Actions로 품질과 배포 단계를 운영한다.
- Blue-Green은 애플리케이션 프로세스만 교체한다. DB는 공유 저장소로 두고 스키마 변경은 구버전과 신버전에서 모두 동작하도록 한다. WebSocket 연결까지 무중단이라고 주장하지 않는다.
- 실제 사전 예측의 미래 결과가 없으면 성능은 계속 판단 보류다. 10월 23일 기록의 첫 5거래일 결과는 10월 30일 뉴욕 장 종료 이후에야 확인 가능하고, 뒤따르는 수집·감사가 성공해야 채점된다.
- 호스트·도메인·비밀값 또는 공개 배포 권리가 없으면 10/31의 결과를 “로컬 전환·복구 검증”으로 정확히 표시하고 공개 배포 성공이라고 쓰지 않는다.

이용자 수요는 소규모 사용성 확인에서 관심 목록 선택, 대화방 진입, 재방문 의사를 별도로 기록한다. 예상 위험 수치의 정확도가 이 지표를 대신하지 않는다.

매일 작업 종료 시 완료 증거·막힌 원인·다음 날의 범위 조정을 이 표에 기록한다. 일정 때문에 통과하지 않은 시험이나 검증되지 않은 예측 성과를 완료로 표시하지 않는다.
