# 이벤트 분석 파이프라인 학습 가이드

## 이번 구현으로 확인할 수 있는 것

발표 이전에 관측한 이진 이벤트 확률을 이용해 자산 수익률 분포를 가중하고,
과거 수익률을 동일 가중한 기준 모델과 비교한다. 새 발표 자료를 입력에 추가해 다시 실행하면
각 예측시점에 이용 가능했던 과거 자료만 골라 분포를 다시 만든다.
현재는 로컬에서 명시적으로 실행하는 연구용 파이프라인이다.

한 번 실행할 때 아래 순서가 끝까지 연결된다.

1. 정규화 입력 JSON의 UTC·식별자·확률·가격·포트폴리오 비중 검증
2. 발표 전 확률과 정확한 수익률 시작·종료시각의 가격 연결
3. 발표별 사용 가능 여부와 제외 이유 기록
4. 예측시점마다 이미 확정된 과거 이벤트만 사용해 경험적 분포 재구성
5. 과거 분포와 이벤트 확률 가중 분포를 같은 시험 이벤트에서 평가
6. 원본 파일·정규화 데이터 체크섬, 모델 버전, 학습 이벤트 목록, 결과 저장

## 1. 먼저 실행하기

Python 3.12의 프로젝트 가상환경을 사용한다. Windows에서는 `.venv/Scripts/python`,
macOS·Linux에서는 `.venv/bin/python`으로 아래 `python`을 바꿔 실행할 수 있다.

```bash
python scripts/run_event_research.py --input data/fixtures/analytics/synthetic_cpi.json --min-train 4
```

Make를 사용할 수 있다면 `make PYTHON=.venv/bin/python research-demo`도 같다.
결과는 `artifacts/event-research/<실행 해시>/report.json`에 저장된다.
같은 입력·설정·결과는 같은 경로를 사용하고, 기존 결과와 내용이 다르면 덮어쓰지 않는다.
입력 파일은 수정하지 않는다. 결과와 연구용 원천 자료는 공개 커밋 대상이 아니다.

동봉한 자료는 실제 시장에서 가져온 값이 아닌 합성 자료다.
12회의 가상 CPI 발표, 3개 자산, 주식·채권·금의 임의 수익률을 포함한다.
처음 4회를 학습에 사용하고 나머지 8회를 순서대로 평가한다.
`synthetic_only`는 실행 검증에 성공했다는 뜻이며 실증 예측력은 나타내지 않는다.
날짜와 가격도 실제 거래소 휴장일·실제 CPI 일정으로 해석하면 안 된다.

## 2. 입력 계약 읽기

구현: `packages/event_study/shockgraph_analytics/contracts.py`.

| 입력 | 의미 | 핵심 제약 |
|---|---|---|
| `definition`, `threshold` | 모든 발표에 공통인 지표·단위·고정 임계값 | 모든 확률이 `actual_value > threshold`를 뜻해야 함 |
| `releases` | 발표·예측시각·수익률 측정시각·최초 발표치·당시 기대값 | 발표 ID 중복 금지, 기대값 공개시각 보존 |
| `snapshots` | 발표별 계약의 사전 확률 관측 | 한 발표당 선택 계약 하나, 관측·이용 가능 시각 모두 예측시각 이하 |
| `prices` | 자산·시각별 가격과 이용 가능 시각 | USD, 동일 가격 기준, 중복 빈티지는 사전 해결 |
| `assets`, `weights` | 순서가 맞는 자산과 비중 | 자산 누락·비중 자동 보정 금지, 합계 1 |
| `evaluation_at` | 사후 평가에서 정답을 확인하는 상한 시각 | 미래 정답을 평가하거나 학습하지 않음 |
| `raw_hash` | 정제 값의 원본 계보 식별자 | 64자리 SHA-256 형식 |

계약 ID는 발표 ID와 분리돼 있지만 이번 분석은 여러 임계값을 동시에 결합하지 않는다.
다른 임계값이나 전년비·전월비를 한 데이터셋에 섞지 않는다.
공급원 원본에서 계약 정의·발표 일정·단위·원본 해시를 확인하는 어댑터는 후속 범위다.
현재 검증기는 호출자가 적은 정의와 원본 해시의 진위를 공급원에 대조하지 않는다.

가격은 입력의 `return_start_at`, `return_end_at`에 정확하게 일치해야 한다.
최근 가격을 임의로 대체하거나 휴장일을 추정하지 않는다.
기업행동이 있는 기간의 수정주가가 예측시점에 존재했던 빈티지인지 공급 단계에서 확인해야 한다.
현금배당과 수정주가 정책이 다른 공급원들을 그대로 혼합하면 안 된다.

## 3. 시간 누수 직접 확인하기

구현: `evaluation.py`의 `prepare()`와 `evaluate()`.

발표 후 확률은 정산 전이라도 사용할 수 없다. 선택하는 확률의 관측·이용 가능 시각은
`prediction_at` 이하여야 하고, 기본 신선도 상한은 48시간이다.
사전 가격이나 기대값이 실제로 늦게 공개됐다면 해당 이벤트를 제외한다.
한 자산의 종료 가격이 없으면 포트폴리오 비중을 줄이지 않고 이벤트 전체를 제외한다.

학습에는 정답과 모든 자산의 종료 가격이 예측시점까지 이용 가능했던 발표만 포함한다.
과거 수익률 구간이 현재 구간과 겹치는 이벤트도 제외한다.
결과의 `train_event_ids`에서 각 예측이 어떤 사건을 보고 만들어졌는지 확인할 수 있다.

실습: 합성 입력의 확률 하나를 발표 이후 시각으로 바꾸고 별도 파일로 실행한다.
`coverage`에 제외 이유가 남는지, 그 이벤트가 학습에서 빠지는지 확인한다.

## 4. 확률 가중 경험적 분포 손계산

과거의 임계값 초과 사건과 비초과 사건을 각각 모은다.
이번 임계값 초과 확률이 `p`라면 초과 사건의 각 수익률에 `p / 초과 사건 수`,
비초과 사건에는 `(1-p) / 비초과 사건 수`를 부여한다.
기준 모델은 모든 과거 사건의 수익률에 `1 / 전체 사건 수`를 부여한다.

예를 들어 초과 시 수익률이 -2%, 비초과 시 +1%인 단순 예제에서
초과 확률이 70%라면 가중 기대수익률은 `0.7 × (-2%) + 0.3 × 1% = -1.1%`다.
이는 계산 설명이며 실제 자산 예측값이 아니다.

양쪽 시나리오에 최소 2개씩 표본이 없으면 예측을 생략한다.
실제 연구 실행의 기본 최소 학습 발표 수는 20개다. 이 숫자는 시작 설정이며 통계적 충분성을 보장하지 않는다.
이번 모델은 임계값 초과 여부에 따른 기준선이다. 실제값-기대값의 크기를 학습하는
surprise 회귀나 시장 국면·최근 변동성을 반영하는 모델은 아직 없다.

## 5. 무엇을 평가하는가

| 결과 | 의미 |
|---|---|
| `mean_return` | 가중 경험적 분포의 평균 수익률 |
| `predictive_std` | 그 분포의 표준편차; 일중 실현변동성 학습 성과가 아님 |
| `probability_up` | 수익률이 0보다 큰 표본의 확률 질량 |
| `q05`, `q95` | 미래 수익률 분포의 5·95% 분위수; 평균 추정의 신뢰구간이 아님 |
| CRPS | 예측한 전체 분포와 실현 수익률 사이의 손실; 작을수록 좋음 |
| 상승확률 Brier | 상승·하락 확률 예측 오차 |
| 하방 분위수 손실 | 5% 분위수의 예측 오차 |
| 구간 포함률·폭 | 90% 구간이 실제값을 포함하는지와 구간의 폭 |

비교표의 CRPS 차이는 `확률 가중 모델 - 과거 분포 모델`이다.
음수면 해당 시험 표본에서 확률 가중 모델의 손실이 더 작다.
발표별 대응 손실 차이를 1,000번 재표집하고 고정 난수 시드 42를 사용한다.
독립 시험 발표가 2개 미만이면 신뢰구간을 반환하지 않는다.
발표 간 시간 의존성이나 반복 탐색을 보정하는 기능은 후속이며, 이 구간으로 채택을 자동 결정하지 않는다.

포트폴리오는 같은 사건의 자산 수익률 벡터에 비중을 적용해 계산한다.
주식·채권의 반대 움직임이 상쇄되는지 테스트한다. 개별 자산 분위수를 더하지 않는다.
VaR·ES와 거래 비용을 포함하는 운영 위험 엔진은 이번 범위에 포함하지 않았다.

## 6. 지속 학습과의 연결

새 발표 자료를 검증된 입력에 추가하고 다시 실행하면 학습 후보가 늘어난다.
과거 예측은 당시 알 수 있었던 자료만 사용하도록 다시 계산된다.
현재 경험적 모델의 학습은 과거 표본으로 조건부 분포를 재구성하는 작업이다.
별도 최적화 파라미터를 학습하는 로지스틱·회귀 모델은 추후 같은 평가 경계에 붙인다.

예약 수집, 자동 재학습 트리거, 기존·후보 모델의 승인 게이트와 운영 배포는 아직 연결하지 않았다.
결과의 `promotion_status=not_evaluated`를 확인한다.
다음 실험은 전통적 기대·최근 변동성 기준 모델을 추가해 그 기준 대비 증분 가치를 평가하는 것이다.
