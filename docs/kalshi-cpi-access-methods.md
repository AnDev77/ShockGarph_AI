# Kalshi CPI 예측 데이터 접근과 방법론별 실행 조건

작성일: 2026-09-23

## 확인된 사실과 아직 모르는 것

| 증거 | 확인 범위 | 한계 |
|---|---|---|
| [2026-09-17 데이터 가용성 기록](data-feasibility.md) | 당시 공개 API에서 KXCPI 결과 확정 **63개 발표**, 확정 계약 508개, 2021-07-15~2026-09-11 정산 기간 및 과거 **일별** 캔들 응답 확인 | 당시 기록이며 이번 환경에서 재현되지 않았음. 발표 **직전 1분 양방향 호가**의 63건 커버리지는 미확인 |

| [BLS CPI 일정](https://www.bls.gov/schedule/news_release/cpi.htm) | 2026년 8월분은 2026-09-11 08:30 ET 발표(12:30 UTC) | 예정시각과 실제 데이터 공개·수집시각을 후속 검증해야 함 |
| 이번 작업환경 진단 | 일반 공개 GET `/exchange/status` 포함 기본 요청에서 시간 초과 또는 HTTP 403; 프록시 미사용 직접 연결은 ConnectError | Kalshi 자체 접근 정책, 네트워크 프록시, 시간적 장애 중 원인을 단정할 수 없음 |

Kalshi 공식 문서에 따르면 오래된 시장은 `/historical/markets`, 시장별 과거 캔들은
`/historical/markets/{ticker}/candlesticks`에서 조회하며 1·60·1440분 간격을
지원한다. 반면 이벤트·시리즈 메타데이터는 현재 경로에 남는다. 필요한 자료가
어느 계층에 있는지 `/historical/cutoff`로 판별한다. 공개 시장 정보는 인증 없이
읽는 경로로 설명되지만, 특정 환경의 실제 접근 가능성을 보장하지 않는다.

공식 자료: [공개 시장 데이터](https://docs.kalshi.com/getting_started/quick_start_market_data),
[과거 자료 경계](https://docs.kalshi.com/getting_started/historical_data),
[과거 시장 목록](https://docs.kalshi.com/api-reference/historical/get-historical-markets),
[과거 캔들](https://docs.kalshi.com/api-reference/historical/get-historical-market-candlesticks).

## 승인된 네트워크에서 바로 수행할 점검

```bash
python scripts/probe_cpi_coverage.py --max-pages 1
```

기본 표본은 `KXCPI-26AUG`, 발표시각 `2026-09-11T12:30:00Z`, 예측 기준
`12:25:00Z`다. 정산 결과가 있는 계약 하나를 선택해 발표 전 1시간 동안의
**1분 캔들**을 조회하고, 종료시각이 예측 기준 이하이며 거래량 양수,
YES 매수·매도 종가 0~1, 스프레드 0.10 이하인 캔들의 개수와 가장 최근 시각만
보고한다. 최근 15분 안에 이런 캔들이 있어야 `eligible`이다. 스프레드 상한과
15분은 연구용 시작 값이며 데이터 품질을 입증하는 기준으로 재검토해야 한다.
원본 가격·확률과 인증정보는 점검 출력이나 Git 저장소에 남기지 않는다.
표본 계약은 조회된 결과 확정 시장의 티커 사전순 첫 번째로 고정해 사후 거래량이나
결과에 따라 유리한 계약을 고르지 않는다. 사후 확정 여부는 점검의 대상 선정에만
쓰며 실제 예측 특징량으로 넣지 않는다.

```bash
python scripts/probe_cpi_coverage.py --max-pages 1 --event-ticker KXCPI-26AUG --release-at 2026-09-11T12:30:00Z
```

위 결과가 성공해도 **한 개 임계값 계약의 기술적 조회 성공**일 뿐이다.
계약 문구가 의미하는 CPI 전월비·반올림 규칙과 BLS 최초 발표치가 맞는지,
동일 이벤트의 임계값 범위가 완전한지, 나머지 월별 발표에 같은 품질이 있는지,
기업 데이터의 저장·시연 이용권은 별도로 확인한다. 과거 캔들 종가는 그 시각의
확정 호가장 전체를 복원하지 않으며, 개별 캔들의 `available_at`을 과거에
직접 기록했다는 뜻도 아니다. 결측·무체결을 임의 보간하지 않는다.

같은 시리즈의 이벤트별 **예측 분위수 이력** API도 문서에 있지만 인증 헤더가
필수로 명시돼 있어 이 공개 점검기에서 호출하지 않는다. 실제로 조회 가능한지,
과거 시점·표본 구성·시장 거래 가능 확률로 해석할 수 있는지를 별도 검사한다.
[예측 분위수 이력 API](https://docs.kalshi.com/api-reference/events/get-event-forecast-percentile-history).

## 결과별 실험 선택

| 확보한 자료 | 실행할 방법 | 가능한 주장과 제외할 주장 |
|---|---|---|
| 발표 직전 양방향 호가·거래량과 사전 발표시각이 충분한 월별 계약 | 고정 임계값 이진 확률의 발표 단위 시간순 Brier 검증 → 과거 전체 분포·부분 풀링 조건부 자산 분포의 동일 사건 CRPS 비교 | 시장확률의 **추가 설명력** 시험 가능. 다중 임계값은 정산 규칙·양끝 구간을 확인할 때만 별도 확장. 현재 정보집합을 완전히 학습했다고 주장하지 않음 |
| 과거 일별 캔들만 있고 가까운 발표 전 호가 확인이 어려움 | 종료시각이 발표 전임을 검증한 과거 일별 가격으로 탐색적 확률 보정, 누락 비율과 거래량 보고 | 고빈도 발표 반응, 장전 유동성, 시장 미시구조 효과의 검증은 불가. 종가가 발표 이후면 사용 금지 |
| 최근 소수 발표에만 1분 캔들·호가가 있음 | 예정 발표를 기준으로 앞으로 원본을 실시간 보존, 설명용 사례 연구와 순차 평가 | 사례를 학습 성능 또는 일반화 근거로 표시하지 않음 |
| 이 환경 또는 허용된 환경에서 Kalshi 원본을 못 읽음 | BLS 최초 발표치·검증된 발표 전 기대와 ETF 가격으로 CPI 서프라이즈 이벤트 연구; 자체 추정 확률은 별도 이름으로 검증 | Kalshi 시장확률의 증분 가치 주장은 중단. 수집 가능성과 라이선스를 새 데이터 공급원별로 검사 |

평가를 시작하는 **최소 연구 게이트**는 동일 정의의 발표 20건 이상을 과거 학습에
쓰고 이후 별도 발표 10건 이상을 시험에 남기는 것이다. 이것은 모델 성공이나
상용화에 충분하다는 뜻이 아니다. 하나의 발표에 여러 계약·캔들이 있어도
독립 사건 수는 1이다. ETF 세 종목의 가격은 Kalshi가 제공하지 않으므로
공통 발표시각의 합법적 가격 공급원, 장전 거래 품질, 당시 기대값을 추가로
확보해야 한다. 자료가 적으면 VaR·ES 수치를 표시하지 않는 기존 게이트를 유지한다.

현재 판단은 **시리즈·일별 과거 자료는 과거에 기술적으로 확인됐고, 지금 필요한
발표 직전 분봉·호가의 광범위한 재현성은 미확인**이다. 다음 작업은 접근 가능한
네트워크에서 위 표본을 재실행한 뒤, 매월 첫 발표자료·해당 시점 호가·ETF 가격의
교집합과 결측률을 계량하는 것이다.
