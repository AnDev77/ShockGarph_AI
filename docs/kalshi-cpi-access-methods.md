# Kalshi CPI 예측 데이터 접근과 검증 방법

작성일: 2026-09-26

## 결론

Kalshi CPI 데이터는 현재 작업 환경에서도 사용할 수 있다. 기본 운영 URL
`https://external-api.kalshi.com/trade-api/v2`는 HTTP 403 또는 시간 초과가
발생했지만, 공식 호환 운영 URL
`https://api.elections.kalshi.com/trade-api/v2`의 인증 없는 공개 GET은 성공했다.
첫 재연결 점검에서는 두 URL이 일시적으로 시간 초과됐으나, 최대 4회 재시도를 적용한
전체 감사는 이후 접근 오류 0건으로 끝났다. 따라서 API가 정책적으로 전면 차단됐다고
볼 근거는 없다. 호출 환경과 경로별 장애에 대비해 두 공식 URL의 상태를 구분해 기록해야 한다.

이번에 확인한 범위는 **기술적 읽기 가능성**이다. 데이터의 공개 재배포와 상용 제품
사용 권리는 별도 계약 검토가 필요하다.

## 실제 조회 결과

`make PYTHON=.venv/bin/python research-audit-cpi`로 현재·과거 KXCPI 시장을 모두
조회하고, 월별로 같은 의미를 유지하는 고정 임계값 계약 `T0.3`만 골랐다. 현재 시장은
`/series/KXCPI/markets/{ticker}/candlesticks`, 과거 시장은
`/historical/markets/{ticker}/candlesticks`에서 1분 캔들을 읽었다. 응답은 수집시각,
요청 인자와 해시를 포함한 불변 원본으로 로컬 `artifacts/raw`에 저장하며 Git에는 넣지 않는다.

| 점검 항목 | 결과 |
|---|---:|
| 과거 시장 레코드 | 483개 |
| 현재 시장 레코드 | 69개 |
| 결과가 확정된 `T0.3` 이벤트 | 55개 |
| 품질 기준 통과 | 29개 |
| 유효 호가는 있으나 15분보다 오래됨 | 6개 |
| 유효 캔들 없음 | 20개 |
| 캔들 접근 오류 | 0개 |

품질 통과 조건은 계약 종료시각 이전 1분 캔들, 양수 거래량, 0~1 범위의 정상적인
YES 매수·매도 가격, 스프레드 0.10 이하, 계약 종료 전 최근 15분 이내다. 확률은
가장 최근 유효 캔들의 YES 매수·매도 중간값을 사용한다. `close_time`은 Kalshi 계약의
거래 종료시각이며 BLS 발표시각과 같은 값이라고 가정하지 않는다. 예를 들어
`KXCPI-26AUG`의 거래 종료는 12:25 UTC, BLS 발표 예정은 12:30 UTC였다.

29개는 전체 55개의 52.7%다. 나머지 47.3%를 임의 보간하지 않았기 때문에 사용 가능한
표본이 줄었다. 이 결측이 시기나 시장 관심도와 연관돼 있으면 아래 성능 비교에도 선택
편향이 생길 수 있다.

## 시장확률의 첫 기준 평가

각 `T0.3` 계약의 결과를 이진 목표값으로 두고 Brier 점수를 계산했다. 과거 결과가 최소
10개 쌓인 시점부터는 **그 시점 이전 결과만** 사용한 누적 YES 비율을 기준 모델로 삼았다.
같은 24개 사건에서 원시 시장확률과 기준 모델을 짝지어 비교했다.

| 지표 | 결과 |
|---|---:|
| 품질 통과 29개 전체의 원시 시장확률 Brier | 0.0965 |
| 과거 10개 이상 확보 후 비교 가능한 사건 | 24개 |
| 비교 구간 원시 시장확률 Brier | 0.1005 |
| 비교 구간 누적 과거비율 Brier | 0.2339 |
| 사건별 Brier 차이 평균: 시장 − 기준 | -0.1334 |
| 사건 단위 paired bootstrap 95% 구간 | [-0.1888, -0.0847] |

낮은 Brier가 좋으므로 이 표본에서는 원시 시장확률이 단순 과거비율보다 나았다. 구간도
0 아래지만 이것을 상용 성능의 확정 증거로 해석하지 않는다. 비교 사건이 24개뿐이고,
유동성 필터를 통과한 사건만 남았으며, `T0.3` 한 임계값의 **정산 결과**를 맞히는 시험이다.
CPI 발표 후 SPY·TLT·GLD의 방향이나 수익률을 맞혔다는 결과가 아니다. 확률 보정,
계절·정책 국면, 계약 문구 변화와 다중 임계값의 논리 일관성도 아직 평가하지 않았다.

## 재현 명령

연결과 한 개 이벤트의 경로를 빠르게 확인한다.

```bash
python scripts/probe_cpi_coverage.py --max-pages 2
```

전체 `T0.3` 이력의 원본 보존, 품질 감사와 기준 점수 비교를 실행한다.

```bash
python scripts/audit_kalshi_cpi.py --request-interval 0.3
```

요청 제한이나 일시 장애가 있으면 수집기는 제한된 횟수만큼 지수 백오프로 재시도한다.
원본과 집계 보고서는 내용 해시 디렉터리에 저장된다. 확률 평가에는 결과 발표 뒤의
가격이나 이후 사건의 정산 결과를 넣지 않는다.

## 다음 분석 게이트

1. BLS 최초 발표치와 실제 발표시각을 각 Kalshi 이벤트에 연결하고 계약 정의가 매월
   같은지 검토한다.
2. 이용권이 확인된 공급원에서 SPY·TLT·GLD의 장전 호가 또는 분봉을 확보한다.
3. 발표 직후 5분·30분, 정규장 개장 후 구간을 분리하고 같은 사건에서 세 자산을 비교한다.
4. 시장확률을 제외한 CPI 기대·최근 변동성 기준 모델과 동일한 표본 외 사건에서 비교한다.
5. 확률 임계값과 품질 필터를 시험 결과를 본 뒤 바꾸지 않고, 사전에 고정한 민감도 분석만
   별도로 보고한다.

ETF 가격 키가 현재 환경에 없으므로 2~4단계는 아직 실행하지 않았다. 따라서 지금 확인된
가치는 “Kalshi CPI 확률이 단순 발생비율보다 정산 결과를 더 잘 구분했는가”까지이며,
“그 확률이 자산 변동성을 추가로 설명하는가”는 다음 실데이터 결합에서 검증해야 한다.
