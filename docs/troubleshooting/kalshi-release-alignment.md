# Kalshi 계약 종료시각과 CPI 발표시각 정합성

## 증상과 원인

Actions 실행 `36726662268`은 API 수집과 기존 집계 생성 이후, 신규 Kalshi 추가 효과
평가에서 `quote must be fresh and strictly before release` 오류로 중단됐다.
이는 API 키나 접근 권한 오류가 아닌 **시간 정합성 검증 실패**다.

기존 Kalshi 감사의 `eligible`은 계약 `close_time`을 기준으로 선정한다.
이 상태가 실제 BLS 발표 직전의 가용성과 신선도를 보장하지 않는다.
신규 비교는 BLS `release_at` 기준으로 엄격히 검사했으나, 정상적인 제외 사례를
입력 전체의 예외로 처리해 파이프라인을 중단시켰다.

## 조치와 해석

- 실제 발표시각에서 확률 관측시각을 뺀 값이 `0초 초과, 15분 이하`인 사건만 사용한다.
- `stale_before_release`: 발표보다 15분 넘게 오래된 확률이다.
- `at_or_after_release`: 발표와 동시에 끝나거나 이후에 관측된 확률이다.
  발표 시각에 끝나는 분봉도 발표 전 값임을 보장할 수 없어 제외한다.
- `selection_counts`에 확률 부재, 자산 구간 결측, 시간 탈락, 최종 채택 수를
  상호 배타적인 순서로 기록한다. 합계는 BLS 입력 사건 수와 일치해야 한다.
- `quote_time_exclusions`에는 사건 ID와 두 시각, 제외 사유만 기록한다.
  가격·수익률·키를 담지 않는다. 결과 오류 메시지에서도 모델 입력을 숨긴다.
- 시간 탈락은 제외 처리하되 결과 불일치, 스프레드·거래량 위반 등 다른 오류는
  계속 실패시킨다. 검사 실패를 무조건 무시하지 않는다.
- 후속 단계 실패 시에도 이미 생성된 안전한 집계 파일은 Actions 산출물로 보관한다.

기존 공통 사건 27건은 계약 기준의 교집합으로, 신규 발표 직전 비교의 최종 표본 수가
아니다. 최신 보고서의 `common_events`를 인용해야 한다. 표본 부족으로 지표가 비어
있다면 수집 실패나 Kalshi의 무효성을 의미하지 않는다.

## 검증과 다음 조치

통합 테스트에서 발표 16분 전·발표 정각·발표 1분 후를 제외하고, 15분 전은
포함하는지 확인한다. 표본 감소 후 API가 `insufficient_data`를 표시하는지도 확인한다.
실데이터의 시각 목록으로 계약 종료와 BLS 발표의 차이를 확인한 다음,
필요하면 BLS 발표 이전 구간을 대상으로 분봉을 재수집한다.
과거 발표 이후 확률로 빈 표본을 채워서는 안 된다.
