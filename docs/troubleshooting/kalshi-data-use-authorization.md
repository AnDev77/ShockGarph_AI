# Kalshi 기술적 접근과 데이터 이용 허가

## 확인한 문제

2026-10-06 공식 문서를 확인했다. API가 응답하는 것과 데이터를 연구·제품에 사용할
권리는 별개다. 이번 중단 원인은 키·IP·SIP 피드·HTTP 오류가 아니다.

- [개발자 약관 v1.1](https://kalshi-public-docs.s3.amazonaws.com/Kalshi-Developer-Agreement.pdf)
  3항과 3.1항은 API 이용 및 수집·저장을 본인의 거래 목적에 제한한다.
- [데이터 이용조건](https://kalshi-public-docs.s3.amazonaws.com/kalshi-data-terms-of-service.pdf)
  I·II절은 비상업적 소프트웨어 개발, 데이터 재배포와 포트폴리오·위험관리 서비스에
  서면 허가 조건을 두고, AI·ML 이용도 명시적으로 제한한다.

현재 저장소에 해당 프로젝트의 허가 근거가 확인되지 않았다. 프로젝트에 적용되는
별도 계약·허가가 있다면 그 범위를 확인해야 한다. 공개 엔드포인트나 새 API 키를
허가의 대체 근거로 보지 않는다.

## 적용한 조치

- 이번에는 실제 API를 호출하거나 기존 Kalshi 실자료로 새로운 분석을 실행하지 않았다.
- GitHub push는 비밀키 없이 정적 검사·테스트·합성 커버리지 감사만 실행한다.
- 기존 실제 수집 job은 `workflow_dispatch`와 저장소 변수
  `KALSHI_RESEARCH_USE_AUTHORIZED=true`가 모두 충족될 때만 실행된다.
  변수는 실제 제공자 허가를 확인한 기록이다. 변수 설정 자체가 허가를 만들지는 않는다.
- 새 오프라인 실제 입력 CLI는 `--authorization-record` 파일을 요구한다.
  결과에는 기록의 SHA-256만 넣는다. 내용·계약·인증정보는 커밋하지 않는다.
  파일의 진위와 이용 범위를 프로그램이 법적으로 판정하는 것은 아니다.
- 기존 수집 CLI는 보존했지만 허가 확인 전 연구 목적 실행을 안내하지 않는다.

## 재개에 필요한 범위

서면 확인에는 과거 CPI 계약·분봉 수집과 보관, 통계 분석, 모델 학습·검증,
논문·공모전의 집계 결과 공개, 향후 웹서비스의 파생 분석 제공을 각각 포함해야 한다.
연구용 허가를 상업 서비스 허가로 확대 해석하지 않는다.
허가 여부와 조건을 확인한 뒤, 허용 범위에 맞는 산출물 공개 정책을 결정한다.

허가 대기 중에는 합성 자료로 파이프라인을 검증하고 별도 이용권이 확보된
거시·자산 자료의 기준 모델을 개발할 수 있다. 이번에 다른 공급원의 접근·이용권을
새롭게 검증한 것은 아니다.
