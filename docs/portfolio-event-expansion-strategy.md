# CPI·FOMC·유가 기반 포트폴리오 영향 분석 실행 전략

작성일: 2026-10-07, 한국 시각. 이번 변경은 전략 문서이며 기능 구현이나 실제 성능 검증이 아니다.

## 1. 제품 목표와 우선 결정

**사용자가 자산과 비중을 입력하면, 다음 경제 이벤트에 대한 시장 기대와 과거 자산의
공동 반응으로 포트폴리오의 단기 변화 가능성을 한 화면에서 보여준다.**
제품의 중심은 포트폴리오 추정 결과다. 상회·부합·하회는 내부 계산과 설명에 사용하고,
사용자가 첫 화면에서 세 시나리오를 이해하거나 선택해야 하는 구조는 변경한다.
이번 전략은 기존 시나리오 탭 중심의 화면 계획을 대체한다. 실제 화면 코드는 아직 변경하지 않았다.

확장 순서는 **CPI 포트폴리오 계산 완성 → FOMC → EIA 원유재고 이벤트 → 유가 변동 분석**이다.
확장을 위해 CPI 예측 성능 개선을 끝없이 기다리지는 않는다. 공통 계산·조회·데이터 품질
구조를 완성한 뒤 이벤트별 자료와 모델을 붙인다. 각 이벤트의 검증 상태는 별도로 관리한다.

Kalshi는 교체 가능한 시장 기대 공급원이다. 제품 전체를 단일 공급원의 접근·이용권에 종속시키지 않는다.
이벤트 확률, 자산 반응, 포트폴리오 계산을 나누되 하나의 모듈형 저장소와 FastAPI를 유지한다.
DNN·곡률·LLM 에이전트·채팅방은 첫 실측 포트폴리오 결과와 배포를 마친 뒤 별도로 판단한다.

기존 시험에서 이미 본 사건은 개발 자료이며 새 최종 시험으로 다시 이름 붙이지 않는다.
상세 수치는 [유의미성 재평가](reviews/prediction-value-reassessment-review.md)를 따른다.

## 3. 첫 화면의 정보 순서

1. **내 구성:** SPY·TLT와 비중, 선택적으로 현재 평가액. 초기에는 USD·롱온리·비중 합 100%만 지원한다.
2. **다음 이벤트:** CPI·FOMC·원유재고 중 자료가 준비된 이벤트, 발표 시각과 분석 기준시각.
3. **내 포트폴리오:** 상승·하락·보합 추정확률, 평균 변화율, 분포의 P10–P90 범위.
4. **시장 기대:** CPI의 정의된 임계값 확률 또는 FOMC의 인하·동결·인상 내재확률.
5. **근거 펼치기:** 시나리오별 반응, 독립 사건 수, 기간, 가정, 자료·모델 검증 상태.

대표 추정치는 확정 예측처럼 표현하지 않고 분석 구간과 자료 상태를 함께 표시한다.
P10–P90은 모델이 산출한 분포의 중앙 80% 범위다. 미래 관측의 80%가 실제 포함된다는
주장은 별도 표본 밖 보장률 평가 후에만 가능하다. 평균의 신뢰구간과도 구분한다.
실측·합성·사용자 가정을 상시 표시하고, 실제 값이 없을 때 합성 결과로 대체하지 않는다.
검증 점수는 `/methodology`에 유지한다. 시장확률은 보정된 객관적 발생확률과 같다고 단정하지 않는다.

**‘CPI 상승확률’은 `P(CPI MoM > 0%)`로 정의한다.** 물가수준이 전월보다 오른다는 뜻이다.
전월 발표보다 상승률이 커질 확률, 컨센서스를 상회할 확률과 다르다.
해당 질문과 일치하는 계약·자료가 없으면 표시하지 않는다. 현재 합성 계약의 0.2%·0.3%
확률을 0% 초과 확률로 바꾸지 않는다. 몇 개의 임계값만으로 꼬리 가정 없이 정확한 CPI 평균을 만들지도 않는다.

## 4. 예측 방법과 포트폴리오 계산

첫 모델은 **시나리오별 경험적 공동수익률 분포를 현재의 시나리오 확률로 혼합하는 모델**이다.
기존 과거 조건부 분포 계산을 활용한다. 작은 집단의 축소 추정은 학습 구간에서만 설계·검증한다.
현재 조건과 과거 조건이 다르다는 한계가 있으며, 첫 버전에서 많은 거시 변수를 조건으로
붙이는 고차원 모델을 만들지 않는다. 이후 낮은 차원의 정규화 회귀를 강한 기준 모델 후보로 검토한다.

같은 과거 사건 i에서 관측한 모든 지원 자산의 수익률로 먼저 포트폴리오 수익률을 계산한다.

\[
R_{p,i}=\sum_a w_aR_{a,i},\qquad
\widehat F_{p,t}(r)=\sum_s p_{s,t}\frac{1}{n_s}\sum_{i\in s}\mathbf 1(R_{p,i}\le r).
\]

여기서 s는 한 이벤트 안의 배타적·포괄적 시나리오이고, p는 같은 발표 전 기준시각의 확률이다.
평균 변화율, 상승확률 `P(R_p > 0)`, 하락확률 `P(R_p < 0)`, 보합확률 `P(R_p = 0)`과
분위수를 이 공동 혼합분포에서 구한다. 금액 변화는 입력한 평가액에 수익률을 곱한다.

- 자산별 분위수를 비중 합산해 포트폴리오 분위수를 만들지 않는다.
- SPY·TLT를 독립적으로 뽑지 않는다. 같은 사건의 공동수익률을 유지한다.
- 비중이 양수인 자산의 결측, 확률이 양수인 시나리오의 표본 부족은 통합 추정 보류 사유다.
  해당 자산·시나리오를 몰래 버리고 재정규화하지 않는다.
- 여러 이벤트의 확률을 곱하거나 수익률을 단순 합산해 월간·연간 전망을 만들지 않는다.
  첫 버전은 **선택한 한 이벤트의 지정 구간 영향**을 계산한다.
- 극단 꼬리의 VaR·ES, 목표주가, 장기 수익률은 첫 버전의 표시 대상에 넣지 않는다.

| CPI | 이용 범위가 확인된 발표 전 계약 분포·컨센서스 | 최초 CPI MoM 발표값과 SPY·TLT 공동수익률 | 기존 발표 후 5분·30분 정의 유지·검증 |

### FOMC: 금리결정과 정책 경로를 구분한다

연준 정례 회의는 연 8회이며 공식 일정·성명·전망 자료가 있다.[^fedcalendar]
인하·동결·인상은 사용자용 요약이고 내부에는 결정 규모를 보존한다.
결정의 surprise는 실제 금리변화에서 발표 전 기대 금리변화를 뺀 값으로 정의한다.
발표 전 예측에서는 각 가능한 결정에서의 surprise만 계산하고 실제 결정은 입력하지 않는다.

성명·정책 경로가 자산 반응에 별도 정보를 준다는 기존 연구가 있다.[^fomcresearch]
금리 인하를 곧바로 주가 상승으로 연결하지 않는다. 발표 후 성명이나 기자회견의 내용을
발표 전 특징량으로 쓰지 않는다. 기자회견이 시작되는 경계와 겹치는 반응 구간은 분리한다.
당일 SEP 동시 공개 여부는 발표 전 알려진 일정 정보로 기록한다.
CME FedWatch는 선물 가격과 25bp 등 가정에 기반한 내재확률이다.[^fedwatch]
웹 화면이 보인다는 이유로 과거 스냅샷·재배포 권한까지 확보했다고 간주하지 않는다.

### 유가: EIA 이벤트와 연속적인 가격 움직임을 구분한다

유가 자체는 CPI처럼 한 번 발표되는 정답이 아니다. 첫 유가 확장은 EIA 주간 원유재고
발표라는 반복 가능한 사건으로 시작한다. 통상 수요일 미 동부시간 10:30에 발표하지만
휴일 예외가 있으므로 공식 일정을 사용한다.[^eiaschedule] API v2는 발급된 키가 필요하다.[^eiaapi]
이번 문서 작성에서는 실제 API 호출 성공·사용자 키 보유·과거 최초 빈티지 확보를 검증하지 않았다.

재고 surprise는 실제 재고변화에서 발표 전 컨센서스를 뺀 값이다. 컨센서스를 확보하지 못하면
과거 정보만 사용한 자체 기준 전망과 비교하고 ‘자체 모델 대비 차이’로 표시한다.
이를 시장 컨센서스나 시장 내재확률이라고 부르지 않는다. 최신 수정된 API 시계열을 최초 발표값으로
취급하지 않고 최초 보고서 또는 보존 스냅샷과 발표 시각을 확인한다.
재고 외 휘발유·정제제품·생산 등 동시 발표 항목도 기록하여 원유재고 하나의 인과 효과라고 주장하지 않는다.

WTI 일별 자료는 맥락 특징에 사용할 수 있지만 분봉 반응 검증을 대체하지 않는다.
유가 상승은 공급·수요 등 원인에 따라 의미가 달라진다.[^oilresearch]
초기 모델이 그 원인을 인과적으로 식별한다고 주장하지 않는다.
에너지 자산 수요가 확인되면 XLE를 첫 추가 후보로 검토한다. XLE는 에너지 기업 지수 ETF이고
원유 가격 자체를 복제하는 상품은 아니다.[^xle] 가격 자료와 공동 사건 표본을 확보한 뒤 활성화한다.

## 6. 데이터·운영 구조

이벤트별 수집 어댑터 → 불변 원본·해시 → UTC·발표 시점 정렬 → 사건별 공동수익률 →
모델·평가 작업 → 버전이 고정된 분석 스냅샷 → FastAPI → 포트폴리오 화면을 유지한다.
공통 기록은 `event_id`, `event_type`, `release_at`, `observed_at`, `available_at`,
`source`, `raw_hash`, `definition_version`, `rights_reference`로 시작한다.
지표 값의 대상 기간과 실제 공개 시각을 구분하고, 모든 특징량의 당시 가용성을 검사한다.

수집·학습은 예약 작업에서 실행하고 사용자 조회마다 실행하지 않는다.
사용자 비중 계산은 검증된 스냅샷에 대해 수행한다. Redis 미스에는 버전이 고정된 저장 결과를
정해진 시간 안에 읽고, 실패하면 이유가 있는 준비 중 상태를 반환한다. 외부 API 재수집이나
재학습을 조회 경로에서 실행하지 않는다. 마지막 정상 결과의 유효기간을 넘겨 현재 예측처럼 제공하지 않는다.

첫 배포는 기존 Vercel 웹·Render 컨테이너 계획을 우선 완성한다. Nginx는 별도 개발·운영
컨테이너 환경의 진입점에 사용하고 환경변수·호스트·저장소를 분리한다. 기존 로컬 HTTP
설정을 운영 TLS·무중단 배포 완료로 해석하지 않는다. 운영 규모가 확인되면 ECS·Cloud Run
같은 관리형 컨테이너로 옮길 수 있도록 이미지와 환경변수 경계를 유지한다.

Kalshi 공개 약관의 소프트웨어·연구·서비스 이용 제한과 프로젝트의 별도 계약 범위를 확인한다.[^kalshirights]
API 키는 이용권의 대체물이 아니다. 다른 공급원도 보관·모델 사용·화면 제공·재배포 범위를 따로 확인한다.
허가된 대안이 없는 이벤트는 조건부 과거 반응만 제공하거나 준비 중으로 둔다.
합성 데모 배포와 실측 분석 제공을 별도 완료 상태로 관리한다.

| 2 | 포트폴리오 중심 UI | 비중 입력 → 결과 한 장 → 근거 펼치기, 합성/실측 분리, 모바일 확인 |
| 3 | 배포와 실측 자료 연결 | 합성 데모 실제 URL·상태 점검. 실측은 원본·빈티지·이용권 충족 후 별도 활성화 |
| 4 | FOMC 어댑터 | 공식 일정·최초 결정·발표 전 기대·분봉 연결, 성명/기자회견 경계 시험 |
| 5 | EIA 어댑터 | 발표 휴일·단위·최초 빈티지·기대 자료 검증, 동일 사건 자산 패널 생성 |
| 6 | 유가 맥락·XLE | 자료 이용 범위·정렬·공동수익률 확보, 별도 모델의 표본 밖 평가 |

첫 세 작업은 데이터·계정이 준비되면 약 3개 개발일의 범위로 잡는다. 실측 이용권·가격·컨센서스
확보와 통계적 충분성은 그 일정에 자동 포함되지 않는다. 3일 안에 합성 데모 배포는 목표로 삼을 수
있지만 실제 예측 성능 입증을 약속하지 않는다. FOMC·EIA는 자료 감사 후 각각 작업량을 확정한다.
이번 요청에서는 계획만 작성하며 다음 구현은 1번부터 시작한다.

## 8. 출시 판단과 사업 가설

코드 테스트 통과, 실제 자료 연결, 예측 유효성, 고객 효용은 각각 별도의 판정이다.

- **계산 완료:** 공동분포·비중·시각·결측·출처를 올바르게 처리한다.
- **실측 제공 가능:** 해당 자산·이벤트·구간의 자료·이용권·신선도·표본 기준을 충족한다.
- **예측 근거:** 시간순 학습·사건 격리, 같은 시험 사건의 CRPS·상승확률 Brier·보정·구간 보장률을 확인한다.
  단순 과거 공동분포와 기존 시장정보 기준 모델을 비교하고, 시장 기대를 추가한 효과를 별도 보고한다.
- **제품 근거:** ETF 보유 사용자가 발표 전 결과를 이해하고 실제 재방문하는지 확인한다.
  다음 이벤트 재방문, 근거 조회, 준비 중 이탈, 지불 의사를 측정한다. 목표 수치는 초기 사용 자료 후 정한다.

시험은 이벤트별로 수행하며 CPI·FOMC·EIA 사건을 같은 분포로 무조건 합치지 않는다.
주 평가 대상·구간·필터·모델을 사전 고정하고, 미래 또는 미열람 사건으로 시험한다.
재표집은 사건 내 자산을 함께 유지하며 시간 의존성이 있으면 블록 단위 방법을 고려한다.
표본 10건은 화면 표시 문턱일 뿐 통계적 충분성이나 예측 정확도의 보증이 아니다.

개선이 입증되지 않은 결과도 계산 근거와 한계를 갖춘 추정치로 구분할 수 있지만,
‘검증된 예측’이나 수익 개선 효과로 홍보하지 않는다. 실측 자료 자체가 없으면 실측 예측 수치는 내놓지 않는다.
시장 기대의 추가 가치가 없으면 해당 공급원을 선택 기능으로 내리고, 반복적인 필터 탐색으로 출시를 미루지 않는다.

초기 고객은 SPY·TLT 등 지원 ETF를 보유하고 경제 발표 직전에 자신의 노출을 확인하려는 사용자다.
무료 체험에서 관심 구성·이벤트 결과·이해도를 검증하고, 알림·구성 비교·히스토리는 이후 유료 가설로 둔다.
차별화 후보는 ‘이벤트 뉴스의 내 포트폴리오 영향 번역’이며 데이터와 고객 검증 전 사업성이 입증된 것은 아니다.
