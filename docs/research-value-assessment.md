# 공모전·금융 리서치 관점의 분석 가치 재평가

검토일: 2026-09-22

## 1. 판단

주제는 금융 연구와 실무에 연결될 수 있다. 다만 현재 저장소는 수집·정규화·평가 기반을
구현한 단계다. 실제 자산 반응의 표본 외 예측력이나 포트폴리오 위험 개선을 입증한 단계는 아니다.
현재 상태를 증권사 운영 모델 수준이라고 설명해서는 안 된다.

권장 연구 질문은 다음과 같다.

> 기존 가격·변동성·거시 기대 정보를 알고 있을 때, 예측시장의 확률 분포를 추가하면
> 발표 전 포트폴리오의 손실 위험을 더 잘 설명하고 예측할 수 있는가?

아래 평가는 공개 연구와 저장소 구현을 근거로 한 프로젝트 판단이다.
특정 공모전의 심사표, 수상 가능성 또는 특정 증권사의 내부 채택 기준을 확인한 결과는 아니다.

| 사용 목적 | 현재 판단 | 설득력을 만드는 추가 증거 |
|---|---|---|
| 금융 서비스 기획·개발 공모전 | 문제 정의와 시제품의 소재로 적합 | 사용자 문제, 실데이터 사례, 재현 가능한 분석, 기존 서비스와의 차이 |
| 금융 논문·퀀트 분석 공모전 | 방법론 목록만으로는 부족 | 명확한 가설, 강한 기준 모델, 발표 단위 표본 외 검증, 실패 결과 |
| 증권사 매크로·멀티에셋 리서치 보조 | 검토할 가치가 있는 연구 도구 후보 | 컨센서스와의 차이, 충격 민감도, 국면별 안정성, 작성 시간 절감 |
| 위험관리·자산배분 지원 | 시나리오 분석 방향에 적합 | 공동 수익률 분포, 손실 구간 검증, 데이터·모델 변경 추적 |
| 실거래·운영 위험 모델 | 아직 근거 부족 | 독립 검증, 운영 이력, 비용·유동성 검증, 적용 대상별 승인 |

## 2. 공개 연구가 뒷받침하는 범위

- 연준 FEDS의 「Kalshi and the Rise of Macro Markets」는 Kalshi 예측을 설문·전통적
  시장 내재 전망과 비교하고, 거시 기대의 실시간 분포를 연구에 활용할 가능성을 제시한다.
  연준 홈페이지에 게시된 연구자의 논문이며 연준의 공식 투자 견해나 프로젝트의 성능 보증은 아니다. [1]
- Kuttner의 연구는 예상된 정책 변화와 예상하지 못한 정책 변화를 나눠 금리 반응을 추정한다.
  이 구분은 이벤트 결과를 곧바로 자산 방향으로 연결하면 안 되는 이유를 뒷받침한다. [2]
- MSCI의 공개 설명은 정량 시나리오를 포트폴리오의 관련 위험요인에 전파하는 스트레스 테스트
  절차를 제시한다. 이 프로젝트의 시나리오→자산→포트폴리오 구조와 업무상 접점이 있다. [3]
- Kalshi 거시 계약과 암호자산 변동성의 관계를 분석한 공개 사전논문도 존재한다.
  따라서 예측시장과 자산 반응을 연결했다는 사실만으로 신규성을 주장하기 어렵다.
  이 논문의 결과를 ETF·국내 자산에 일반화하거나 독립 재현 없이 확정 사실로 삼지 않는다. [4]

기여는 새로운 알고리즘 이름보다 **기존 정보 대비 추가 설명력, 시점이 맞는 데이터,
실제 사용자 포트폴리오의 위험 해석**에서 찾아야 한다.

## 3. 현재 구현과 주장 사이의 간격

| 항목 | 확인한 상태 | 후속 조치 |
|---|---|---|
| 원본 보존·정규화·시간 계약 | 코드와 고정 예제 테스트 존재 | 실제 역사 자료에서 누락·중복·시각 품질 측정 |
| 확률 기준 모델 | 원시 확률 반환과 Brier 점수 존재 | 실데이터 기준 성능표 생성 |
| 보정 모델 | 로지스틱·아이소토닉 학습 구현 없음 | 적은 표본에서는 원시 확률 유지도 후보로 비교 |
| Brier 신뢰구간 | 행별 손실의 정규근사 | 발표 단위 평균 손실과 대응 재표집으로 교체 검증 |
| 이벤트 식별 | 데이터셋이 `event_id`당 이진 정답 하나를 요구 | 공통 발표 ID와 계약별 정답 식별자 분리 |
| 시간순 분할 | 결과 확정시각으로 이벤트 그룹 분할 | 각 예측시점에 학습 정답이 실제 확정됐는지 추가 검사 |
| 이벤트 연구·전이·위험 엔진 | 패키지 역할 설명, 계산 구현 전 | 이벤트 하나·소수 자산으로 분석 한 건 완성 |
| 성능 근거 | 기존 테스트는 코드 계약 검증 | 42개 테스트 통과를 금융 예측력 증거로 사용하지 않음 |

현재 `configs/model.yaml`의 최소 이벤트 수 100·300은 개발상 후보 기준이다.
이 수를 넘었다고 일반화 성능이 보장되지 않으며, 도달하지 못한 표본을 복제해서 채우지 않는다.
고정 예제·데모 거래 자료는 실제 시장 성능 평가에 사용하지 않는다.

## 4. 반드시 바꿔야 할 분석 설계

### 발생 여부와 예상 밖 충격을 분리

분석용 충격을 `surprise = 최초 발표값 - 발표 직전 기대값`으로 정의한다.
가령 금리 인하가 이미 예상돼 있다면 실제 인하 자체만으로 상승을 예측할 근거가 되지 않는다.
동일한 25bp 인하도 예상이 동결이었는지 50bp 인하였는지에 따라 해석이 달라진다.

발표 전 예측에는 실제 surprise를 입력할 수 없다. 당시 정보로 가능한 결과별
`scenario_surprise = 시나리오 값 - 당시 기대값`을 만들고 시나리오 확률로 결합한다.
발표 후 실현 surprise는 별도의 사후 설명·평가에만 사용한다.
기대값을 Kalshi 분포에서 산출하는 경우 단일 이진 계약만으로 연속형 기대값을 복원하지 않는다.
꼬리 구간과 대표값 가정, 계약 간 확률 일관성을 기록한다.

### 정보 시점을 발표시각에 고정

`observed_at < resolved_at`만으로는 충분하지 않다. 공식 발표가 끝난 뒤 거래소 정산이
완료되기 전의 관측값도 이 조건을 통과할 수 있기 때문이다.
발표 전 예측은 `prediction_at < release_at`을 추가로 만족하고, 모든 입력의
`available_at <= prediction_at`을 검사한다. 발표시각, 정답 이용 가능 시각, 계약 정산시각은 구분한다.
경제지표는 최초 발표치와 수정치를 분리하고, 과거 예측에는 당시 빈티지만 사용한다. [6]

### 발표 단위 독립성을 유지

월별 발표 36회를 가정하면 분봉을 수만 개 모아도 독립 발표 수는 36회다.
같은 발표의 여러 계약·스냅샷·자산은 학습과 시험을 공유해서는 안 된다.
주 평가는 발표마다 고정된 사전 관측시점 하나로 시작하고, 추가 관측시점은 별도 보조 실험으로 둔다.
학습·검증에서는 당시 이미 이용 가능한 정답만 사용하며 겹치는 수익률 구간도 제거한다.
표준화, 보정, 특징 선택, 국면 경계는 학습 구간에서 정한다.

### 가격 반응의 측정 구간을 고정

기존 `[-5,+5]` 거래일 CAR은 다른 뉴스와 예상 반영이 섞이는 탐색 지표다.
예측 성능의 주 지표로 그대로 쓰지 않는다. 발표 직전부터 발표 후까지의 짧은 반응 구간은
장중 자료 확보가 가능한 경우에만 사용한다. 일봉만 있다면 전일 종가→발표일 종가처럼
재현 가능한 구간을 쓰고, 다른 뉴스 효과가 포함된다고 명시한다.
장전 발표에서 당일 시가부터 측정하면 개장 갭이 빠지는 것도 기록한다.
동시 발표를 구분할 수 없는 자료에서 CPI의 순수 인과효과라고 주장하지 않는다.

### 공동 분포로 포트폴리오 손실을 계산

자산별 VaR를 비중으로 더한 값은 포트폴리오 VaR가 아니다.
같은 발표·시나리오에 대응하는 자산 수익률 벡터를 함께 재표집하거나 잔차 공분산을 보존해
`R_portfolio = wᵀR_assets`, `L = -R_portfolio`를 계산한다.
손실 분포에서 VaR·ES를 산출하고, 추정치의 신뢰구간과 미래 손실의 예측구간을 구별한다.
예를 들어 독립 발표 40개에서는 95% 꼬리에 기대되는 관측이 약 2개뿐이다.
희소한 이벤트 표본의 꼬리 수치를 운영 수준 위험 한도로 표현하지 않는다.
이벤트 조건부 위험과 평상시를 포함한 전체 일별 위험도 구분한다.

## 5. 권장 최소 실험

첫 분석은 미국 CPI와 동일 통화의 ETF 3개 정도로 제한한다.
예시 후보는 SPY·TLT·GLD이며 투자 추천이 아니라 자산군 반응 비교용이다.
대상 확정은 라이선스·역사 자료의 공통 기간·발표 전 확률 스냅샷 확보 이후에 한다.
국내 자산·원화 환산·FOMC·개별주식 확장은 첫 실험의 데이터 품질과 성능을 확인한 뒤 진행한다.

| 실험 | 입력·방법 | 판별할 질문 |
|---|---|---|
| 기준 A | 과거 수익률 분포·최근 변동성 | 복잡한 정보 없이도 설명되는 위험은 얼마인가? |
| 기준 B | A + 당시 전통적 거시 기대·금리 등 | 기존 정보로 설명되는 부분은 얼마인가? |
| 후보 C | B + Kalshi 원시 확률 분포·변화량 | 예측시장 정보의 추가 가치가 있는가? |
| 후보 D | C의 확률을 보정 | 보정이 추가로 필요한가? |

모델 형태와 학습 기간을 가능한 한 맞춰 C-B와 D-C를 비교한다.
컨센서스 역사 자료를 확보하지 못하면 대체 가능한 단순 기대 기준을 사용하고,
전문 컨센서스보다 우수하다는 주장은 보류한다.
처음에는 규제 선형 회귀·로지스틱 모델과 경험적 분포로 충분하다.
많은 특징량이나 복잡한 모델은 검증 표본과 비교 성과가 확보될 때 추가한다.

주 평가 지표는 사전에 선택한다. 권장 시작점은 미래 수익률 분포의 CRPS다.
상승확률 Brier, 하방 분위수 손실, 예측구간 포함률·폭을 보조 지표로 둔다.
이벤트 확률의 Brier 개선과 자산 손실 예측의 개선은 별도로 보고한다.
롤링 학습·평가에서 발표별 손실 차이를 대응 재표집하고,
시간 의존성이 남으면 발표 블록 재표집을 사용한다. 효과 크기와 신뢰구간을 함께 공개한다.
여러 자산·시차·특징을 탐색하면 다중검정과 선택 편향을 관리하고 최종 시험 구간을 보존한다.
통계적 유의성 하나로 실용적 가치를 판정하지 않는다.

## 6. 자료 확보가 먼저인 이유

Kalshi는 현재·최근 자료와 역사 자료를 분리하며 cutoff와 페이지 순회를 제공한다. [5]
API 경로가 있다는 사실은 필요한 전체 기간·시각·호가 품질을 확보했다는 뜻이 아니다.
첫 산출물은 다음 항목을 담은 데이터 커버리지 표여야 한다.

- 계약 계열·경제지표 정의·임계값·정답 기준
- 최초·최종 관측시각, 발표별 유효 관측 수, 제외 사유
- 매수·매도 호가 차이, 거래량, 마지막 갱신 후 경과시간, 결측 비율
- 시장가격·거시 기대·발표치와의 공통 기간, 수정 이력·이용권

얇은 호가와 오래된 마지막 체결값을 정확한 발생확률로 간주하지 않는다.
기간 확보에 실패하면 실데이터 전향 수집과 과거 사례 설명 도구까지로 결과 범위를 낮춘다.

## 7. 공모전·실무 제출물과 중단 기준

우선 만들 제출물은 데이터 커버리지 표, 재현 스크립트, 기준 모델 비교표,
성공·실패 사례를 함께 담은 발표 전 포트폴리오 위험 리포트다.
사례는 결과를 본 뒤 좋은 사건만 고르지 않고 선정 규칙을 미리 정한다.
리포트에는 현재 기대, 상방·하방 시나리오, 자산별 노출, 손실 구간, 표본 수와 불확실성을 표시한다.

추가 가치가 없으면 그 결과를 공개하고 시나리오 설명·보고서 작성 보조 기능의 가치를 평가한다.
이 경우 검증된 초과 예측력이나 수익 개선을 제품의 핵심 주장으로 쓰지 않는다.
보고서 작성 시간·오류 감소도 동일한 과제를 수동 수행한 경우와 비교해야 주장할 수 있다.
지금 우선순위는 인프라 확대보다 실데이터 분석 한 건을 끝까지 검증하는 것이다.

## 8. 학습 순서와 확인 질문

1. 기대와 surprise: 같은 발표 결과가 왜 서로 다른 가격 반응을 만들 수 있는가?
2. 이벤트 연구: CAR과 앞으로의 투자 수익률 예측은 무엇이 다른가?
3. 검증 설계: 분봉 수와 독립 발표 수는 왜 다른가? 과거 정답이 언제 학습 가능했는가?
4. 확률 평가: Brier·CRPS·분위수 손실은 각각 무엇을 평가하는가?
5. 위험 계산: 자산 간 동행성을 빼면 포트폴리오 꼬리손실이 왜 달라지는가?
6. 금융 데이터: 수정치·시차·거래시간·스프레드가 성과를 어떻게 부풀릴 수 있는가?

## 이번 검토의 변경·검증 기록

이번 요청은 개발 일차를 추가 진행한 것이 아니라 문서 푸시와 분석 타당성 재검토다.
분석 가치 재평가 문서를 추가하고 방법론·최상위 명세에 검증 계약을 연결했다.
위에서 확인한 런타임 한계는 후속 수정 항목으로 기록했으며 계산 코드를 변경하지 않았다.

- `make PYTHON=.venv/bin/python quality`: Ruff 통과, Pyright 오류·경고 0개
- `make PYTHON=.venv/bin/python test`: 기존 테스트 42개 통과
- 저장소 Markdown 30개: 상대 링크·코드 블록 검증 통과
- `git diff --check`: 통과
- 실데이터 학습·백테스트·부하 테스트: 이번 검토에서 실행하지 않음
