# 현재 제품 방향: 관심 종목 RAG 브리핑

기준일: 2026-11-17 KST. [웹 현재 방향](https://github.com/AnDev77/shockgraph-web/blob/main/docs/current-product-direction.md), [이번 주 계획](https://github.com/AnDev77/shockgraph-web/blob/main/docs/daily-work-plan.md), 사용자의 11/17 Kafka 우선 적용 결정을 따른다. 계획과 현재 구현을 구분한다.

## 출시 범위와 책임

- 홈 대표·기본 관심 종목은 CAMT·SPCX·AVGO다. Python은 CAMT SEC 공시 수집·문단 검색·요약 초안·검토된 내부 조회를 먼저 연결한다. SPCX·AVGO는 각각 자료·종목 식별·수집 검증 후 브리핑을 확장한다.
- Java doChallenge는 회원·관심 목록·채팅·외부 API, React shockgraph-web은 화면·차트를 담당한다. Python에 회원 관심 목록이나 별도 공개 홈을 중복 구현하지 않는다.
- 기본은 최근 7일의 새 근거다. 없으면 자료 부족, 수집 실패면 조회 실패다. 단일 기업 공시는 사실과 회사 전망을 분리해 요약하고 독립 출처가 부족하면 종합 판단을 보류한다. 이전 자료는 날짜와 함께 구분한다.
- QQQ/SPY 차트·기존 종목방은 유지한다. 예측 모델·가격 연구·리밸런싱·자유형 상담·추가 종목방은 이번 출시 필수 조건이 아니다.

## Kafka와 후속 구현

- Kafka 첫 적용은 RAG·LLM 요약 초안 작업 전달이다. 예측 워커나 채팅으로 범위를 자동 확대하지 않는다.
- 현재 #18은 공시 해시별 로컬 스냅샷·파일 기반 작업 의도와 참조 이벤트를 사용한다. 원문·비밀값·요약 본문은 Kafka에 넣지 않고 사람 검토 후 공개 경계를 유지한다.
- 현재 검증은 합성 공시와 가짜 생산자·소비자까지다. 운영용 공유 원본 저장소·DB 트랜잭션 아웃박스·실브로커 재처리·권한·관측은 별도 완료 조건이다. 파일 의도를 운영용 아웃박스라고 부르지 않는다.
- 임베딩·LangGraph·MySQL 영속화·독립 출처 확장은 별도 구현·검증 작업이다. 과거 Kafka 전면 수집 설계나 RabbitMQ 계획으로 되돌리지 않는다.
