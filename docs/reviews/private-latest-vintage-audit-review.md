# 최신 비공개 빈티지 읽기 감사 리뷰

## 바뀐 동작

`--latest`는 별도 index key 없이 R2의 지정 prefix를 페이지 순서대로 읽어 정상 형식의 기록 index를 찾는다. 가장 최근 저장 시각의 index를 기존 `audit_capture`로 감사하고 결과에는 index 경로·가격 원본을 출력하지 않는다. 비어 있거나 중단된 목록과 이상한 시각을 성공으로 처리하지 않는다. 기존 `--index-key` 방식은 유지한다.

## 검증과 한계

합성 버킷에서 원본 바이트 변조, 빈 버킷, 잘못된 다음 페이지 토큰을 검사했다. 대상 통합 시험 9개가 통과했다. 버킷 전체 목록을 읽으므로 객체가 늘어나면 목록 호출 비용이 증가할 수 있고, 가장 최신 index가 손상되면 이전 항목으로 자동 후퇴하지 않고 실패한다. 이 동작은 기록의 무결성을 확인하는 것이며 수익률이나 예측 정확도를 평가하지 않는다. 실제 R2에 대한 새 명령의 연결 시험과 전체 게이트 결과는 별도로 확인한다.

## 객관적 판단

로그에서 객체 키를 복사하지 않아도 최신 기록을 재검사할 수 있어 운영 재현성이 개선됐다. 서로 다른 거래일의 빈티지가 아직 충분히 누적되지 않았고 5·20일 정답도 성숙하지 않았으므로 리서치 성능은 `HOLD`다. 자료 이용권과 사용자 재방문 증거도 변화가 없다.

## 로컬 완료 검증

wheel을 빌드하고 필수 Python 소스 7개를 확인했다. Ruff 오류 0건과 Pyright 오류·경고 0건을 확인했다. 기존 175개에서 2개 늘어난 전체 177개 시험이 통과했다. 새 시험은 최신 기록을 다시 읽을 때 원본 변조가 실패로 처리되는지와 원격 목록의 누락·중단이 감사 성공으로 둔갑하지 않는지를 확인한다. 실제 R2의 이 명령 실행은 아직 이 결과에 포함되지 않는다.

## 원격 재현

[초안 PR 게이트](https://github.com/AnDev77/ShockGarph_AI/actions/runs/40255188632)에서 빌드 소스 7개, Ruff 0건, Pyright 오류·경고 0건, 전체 177개 시험 통과를 확인했다. 이 게이트에는 R2 비밀값을 주입하지 않으므로 실제 버킷의 최신 항목이 존재하는지까지 확인한 결과는 아니다.

## 원격 버킷 연결 점검

보관 직후 독립 CLI `--latest`가 R2 객체 목록에서 최신 index를 찾아 다시 감사하도록 워크플로 단계를 추가했다. 기존 보관 명령 안의 즉시 검증과 별개의 프로세스에서 수행된다. 변경 자체는 새로운 예측 알고리즘이 아니며 동일 거래일 반복 실행의 예측 기록을 새 독립 표본으로 만들지 않는다. 실제 실행이 완료되기 전까지 연결 성공이라고 기록하지 않는다.
