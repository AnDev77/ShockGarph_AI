# 사전 예측 저장 병목 복구

기준일: 2026-11-20 KST. 기존 연구 PR #20 안에서 보완한다. 새 PR을 쌓거나 Java·React를 수정하지 않는다.

## 시작 근거와 진단

- main `6288f6c44368c3492b3e9566fd0adbfcb270a8da`, #20 `34b18c3d5f8b57e4de1a41204adef37b9787f9a9`를 확인했다. 열린 초안은 독립적인 #19와 #20 두 개였다. 작업 트리의 기존 build/dist 외 추적 파일 변경은 없었다.
- 최근 예약 실행 [44609104414](https://github.com/AnDev77/ShockGarph_AI/actions/runs/44609104414)은 11/19 20:28:54 UTC에 생성·시작됐다. 뉴욕 15:28:54이며 기존 예약 07:10보다 8시간 18분 54초 늦다. GitHub 내부에서 왜 그만큼 지연됐는지는 공개 실행 메타데이터만으로 확정할 수 없다.
- 원본 요청은 11/18까지였다. 다음 거래일인 11/19 뉴욕 08:30까지 저장해야 했지만 생성 시각부터 지났다. 설치는 20:29:10 UTC 이전에 끝났고 수집·보관 단계는 20:29:16부터 20:29:34 사이였다. 계산이 몇 시간씩 걸려서 생긴 문제가 아니다.
- 실제 로그 상태는 `snapshot_only_preopen_gate_failed`다. 원격 읽기 감사·재고 감사·공식 채점 명령은 성공했으나 그 성공이 당일의 새 예측을 뜻하지 않았다. 원본·점수·객체 경로는 이 문서에 옮기지 않는다.
- 수집기가 `end >= 미국 수신일`을 일괄 거부하여 전날 저녁에 미리 예측할 수 없었다. 워크플로도 항상 전날 날짜를 요구했다. 이 두 조건과 아침 단일 예약, 예측 저장을 요구하지 않는 성공 조건을 함께 고친다.

## 실행 흐름과 구체적인 예

1. 11/19 뉴욕 20:23에 실행되면 그날 정규장은 16:00에 끝났고 한 시간도 지났다. 수집 대상은 11/19다. 겨울 한국 시각으로는 11/20 10:23이다.
2. 공급원에 보내는 종료 시각은 `min(대상 날짜 23:59:59 UTC, 실제 요청 시각 - 15분)`이다. 요청 종료를 미래로 보내 무료/지연 SIP 범위를 벗어나지 않는다. 모든 반환 거래일이 요청 달력과 일치해야 하고 raw/all의 빠진 거래일은 실패한다.
3. 원본을 R2에 보관한 실제 완료 시각으로 예측을 만든다. 11/20 뉴욕 08:30까지 보관을 끝내야 한다. 원본 보관과 예측 인덱스의 실제 저장 시각은 기존 감사로 다시 확인한다.
4. 자정·오전 6시 23분 재시도에서 같은 거래일 예측이 이미 있으면 수집을 생략하고 다시 감사한다. 중복 실행은 새 독립 거래일로 세지 않는다. 금요일 저녁에 성공한 기록은 월요일 아침에도 재사용한다.
5. 원본만 저장됐거나 예전 거래일 예측만 남아 있으면 마지막 필수 검사가 종료 코드 1로 실패한다. 객체 변조·연결·설정 오류는 코드 2다. 실패 전에도 가능한 원본 감사·기존 채점은 수행한다. 가격·비밀값·성과 점수는 새 검사 출력에 없다.

이 일정은 지연에 대한 여유와 재시도를 늘린다. GitHub 예약 실행의 정시 도착을 보증하지 않는다. 모든 시도가 마감을 놓치면 실패로 남기며 과거 시각으로 소급 저장하지 않는다.

## 중간 검증과 오류

- 먼저 필수 거래일 게이트 시험을 추가했다. 구현 전에는 새 옵션·거래일 출력 부재로 5건 실패를 재현했다. 수집 시간 모듈 시험도 구현 전 import 오류를 확인한 뒤 구현했다.
- 날짜 선택·같은 날 폐장 후 수집·최근 SIP 범위·원본 수신 시각·잘못된 성공 판정을 검증했다. 정상 예측 재시도는 원격 메모리 저장소를 추가로 쓰지 않는다. 실제 R2 연결 시험이라고 부르지 않는다.
- Ruff의 import 정렬, 중첩 with, 100자 줄 길이 위반을 수정했다. 모델 수치나 거래일 정답 정의는 조정하지 않았다.
- YAML 파서로 두 예약과 마지막 필수 검사의 구성을 읽었다. 정적 YAML 구문 확인은 실제 예약 실행 성공을 대신하지 않는다.
