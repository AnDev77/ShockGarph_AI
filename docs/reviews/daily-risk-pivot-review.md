# 일별 위험 분석과 주주 인증 커뮤니티 전환 리뷰

작성일: 2026-10-19. 기존 21일 일정의 개발 일차를 완료한 것으로 계산하지 않는 제품 범위 변경이다.

## 결정과 실제 변경

제품 첫 분석 단위를 월별 CPI 계약에서 매 거래일 ETF 위험으로 바꿨다. 첫 대상은 TLT의 향후 5·20거래일 변동성이다. 브렌트유·금리·물가 기대·VIX는 당시 이용 가능했던 시계열로 결합하고, SPY·XLE와 포트폴리오 분석은 검증 후 확장한다. CPI/FOMC/Kalshi 코드는 삭제하지 않고 기존 연구 결과로 남겼다. 주주 인증 종목방은 제품 사용성·데이터 권리·권한 검사를 충족해야 하는 후속 기능으로 정의했다.

| 변경 경로 | 목적 |
|---|---|
| `shockgraph-ai-project-spec.md`, `README.md`, `AGENTS.md` | 새 제품 목표·현재 구현 범위·개발 규칙 정렬 |
| `docs/daily-risk-methodology.md` | 일별 입력/정답, 누수 방지, 기준선, 표본 외 성능 계약 |
| `docs/shareholder-community-roadmap.md` | 허가된 보유 확인과 종목 채팅 권한·doChallenge 재사용 기준 |
| `docs/product-ui-direction.md` | 이벤트 중심 홈을 매일의 자산 위험 화면으로 변경 |
| `docs/architecture.md`, `docs/methodology.md`, `docs/deployment-and-serving-strategy.md` | 현재 주 경로를 표시하고 과거 이벤트 연구 설계와 구분 |
| `configs/model.yaml`, `configs/assets.yaml` | 일별 위험의 목표·기간·기준선·우선 자산 선언 |

이번 변경은 **문서와 설정만 수정**했다. 일별 수집기·특징량·모델·실자료 백테스트·API·UI, 보유 인증·채팅은 구현하지 않았다. Kalshi `T0.3` 확률의 과거 Brier 차이는 일별 위험 모델의 성과가 아니다.

## 확인

- `make quality`: Ruff 통과, Pyright 오류·경고 0개.
- `make test`: 기존 테스트 79개 통과.
- 이 테스트는 기존 이벤트 코드의 회귀만 확인한다. 신규 일별 위험 성능을 검증하지 않는다.
- doChallenge 코드는 읽기 전용으로 검토했다. WebSocket의 요청 `memberId` 신뢰, 무제한 `/topic` 구독, CONNECT 인증 부재를 확인했으며 신규 종목방에 직접 이식하지 않는다는 조건을 적었다.

## 다음 수직 개발 순서

1. TLT 수정가격과 EIA 브렌트·FRED 금리/VIX의 공급원 권리 및 공개 지연 확인.
2. `available_at`과 미래 정답 종료일을 보존하는 일별 패널 구성.
3. 5일·20일 변동성 기준선과 시간순 평가 구현, 국면별 실패 검토.
4. 브렌트·금리·VIX 추가 모델이 같은 시험일에서 기준선을 개선하는지 확인.
5. 성능 확인 후 FastAPI 스냅샷·Next.js 결과 카드, 이후 포트폴리오 공동 위험.
6. 후속 종목방은 보유 확인 사업자·허용 범위와 인증된 채팅 세션·구독 권한부터 검증.
