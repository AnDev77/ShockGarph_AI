# 30~31일차 Kalshi 확률 추가 효과의 예비 평가와 배포 연결

## 작업 범위

주 분석 SPY·TLT와 5분·30분 공통 사건에서 과거 발생비율 모델과 Kalshi 확률 모델을
같은 시점에 평가한다. 전통 거시정보 자료가 미확보 상태이므로 완전한 B·C 비교라고
부르지 않는다. 곡률·DNN·FOMC는 배포 이후 별도 연구로 남긴다.

## 코드 구조

- `packages/event_study/shockgraph_analytics/kalshi_ablation.py`: 동일 조건부 경험분포와
  축소 강도 4에서 확률만 바꾸는 비교, 결과 가용시각 검사, CRPS 대응 차이와 재표집 구간
- `scripts/evaluate_cpi_kalshi_ablation.py`: BLS·Kalshi·Alpaca 결합과 공통 네 조합 완전성,
  신선도·스프레드·거래량 검증, 해시를 포함한 불변 집계 보고서 내보내기
- GitHub Actions: 원시 CSV를 러너에서만 사용하고 집계 `kalshi_ablation.json`만 보관
- API: 보고서를 검증한 후 전용 연구 조회와 자산 분석 응답에 전달
- 웹: SPY·TLT 선택과 진단 CRPS·불확실성·연구 표본 부족 상태 표시
- 패키지 설치 설정: API와 분석 패키지를 실제 설치 산출물에 포함

## 평가 계약

초기 학습 20건의 연구 평가와 5건의 진단 평가를 함께 생성한다. 각 평가는 시험 10건
미만이면 지표를 비운다. 양 시나리오 학습 사건이 각각 2건 미만인 시험도 함께 제외한다.
현재 사건의 결과는 점수 계산에만 사용한다. 데이터가 누적되면 같은 과거 사건이 이후
학습에 들어가는 시간순 확장 평가다. 모델마다 다른 시험 사건을 사용하지 않는다.

보고서에는 개별 가격·수익률·예측이나 비밀키를 담지 않는다. 신뢰구간은 월별 독립을
가정한 탐색 구간이며 순차 학습 의존성·다중비교 보정을 포함하지 않는다. 실제 우위의
유무와 관계없이 결과를 기록하고, 표본과 입력 범위를 넘는 결론을 내리지 않는다.

## 검증

- 로컬 Ruff·Pyright 통과, 테스트 118개 통과(기존 Starlette 경고 1개)
- TypeScript 검사 및 Next.js 프로덕션 빌드 성공
- 휠 빌드·설치 후 별도 경로 조작 없이 API 모듈 가져오기 성공
- 합성 입력에서 미래 결과 변경 불변성, 입력 확률이 같을 때 점수 일치,
  GLD 결측 무관성, 한 시나리오 부족·보고서 변조 거부·불변 보고서 검증
- 실데이터 결과는 변경 푸시 후 Actions에서 확인

## 사용자가 볼 사항

1. `common_events`와 두 평가의 `test_events`, 제외 사유부터 확인한다.
2. `mean_crps_difference`는 음수가 Kalshi에 유리하며 네 조합을 모두 읽는다.
3. 초기 5건 진단 수치를 초기 20건 연구 평가 결과로 인용하지 않는다.
4. API 환경변수 `SHOCKGRAPH_ABLATION_REPORT`로 내려받은 집계 파일을 지정한다.
5. 이번 작업은 배포 연결 코드이며 외부 서비스에 실제 배포한 상태는 아니다.

검증하려면 역사적 CPI 기대·금리·최근 변동성의 시점별 자료를 먼저 확보한다.
