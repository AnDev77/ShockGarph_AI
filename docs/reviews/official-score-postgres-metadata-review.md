# 공식 위험 점수의 PostgreSQL 메타데이터 리뷰

## 직전 상태와 변경 구조

R2는 공식 5·20일 사후 점수를 원본 index 해시와 함께 불변 객체로 보존하지만 SQL에서 시작일·종목별로 조회하거나 같은 사건의 중복 점수를 거부하는 스키마는 없었다. 새 `0003_official_forward_scores.sql`은 한 시작일·종목·기간·모형에 한 행을 허용하고, 예측·정답 index와 R2 점수 객체의 SHA-256 및 비공개 URI, UTC 시각, 실현 변동성과 오차를 보관한다. 모형은 최근 변동성·EWMA·GARCH·GJR 네 기준선으로 제한하고 `price_baselines_v1`이라는 산출 버전을 명시한다. 실제 원본 점수의 불변 사본은 계속 R2에 둔다.

`save_official_score_rows`는 두 종목과 시각·해시·유한한 값을 전부 검사한 뒤 8행을 파라미터 SQL로 쓴다. 같은 식별자와 같은 값의 재시도는 신규 0행이고, 기존 값이 다르면 실패한다. 충돌 중 일부 새 행이 이미 쓰였다면 **호출자가 그 트랜잭션 전체를 롤백**해야 한다. 입력은 앞서 감사한 공식 선택 계획과 점수 아티팩트의 실제 해시를 사용해야 한다. 현재 저장 함수는 수집 워크플로에 연결하지 않았고 PostgreSQL 접속 정보도 확인되지 않았다.

## 시험과 한계

합성 커서에서는 두 종목 × 네 모형의 8행이 한 번 생성되고 같은 요청을 반복하면 0행, 정답 index 해시가 달라지면 충돌 오류가 발생하는지를 검사한다. 불완전한 자산 조합·잘못된 객체 SHA·두 번째 자산의 NaN 입력은 SQL 쓰기 전에 거부한다. 이 시험은 함수의 파라미터, 재시도, 값 검사 계약을 확인하지만 PostgreSQL 서버의 CHECK 제약·트랜잭션 격리·마이그레이션 적용 성공을 증명하지 않는다. 실제 연결 후 별도 통합 검증이 필요하다.

로컬 전체 185개 시험이 통과했으며 직전 183개에서 대상 시험 2개가 늘었다. Ruff 위반 0건, Pyright 오류·경고 0건이었고 wheel 빌드와 필수 소스 7개 검사를 완료했다. 원격 게이트도 다음 기록처럼 확인했다.

[PR #8의 원격 품질 게이트](https://github.com/AnDev77/ShockGarph_AI/actions/runs/40278753666)는 배포 패키지 빌드·내용 검사·정적 검사·전체 시험 단계가 모두 성공했다. 이는 실제 PostgreSQL 서버에 마이그레이션을 실행하거나 R2 점수와 연결했다는 뜻은 아니다.

## 증권사 리서치 관점

공식 표본의 유일 키와 첫 빈티지 출처 해시를 DB에 고정하는 방향은 재현성과 사후 선택 위험을 낮춘다. 그러나 이 표가 채워지지 않았고 첫 미래 정답도 아직 성숙하지 않았으므로 독립 표본·A/B 개선·사용자 효용에 대한 증거는 추가되지 않았다. 모델 기준선 버전을 바꾸더라도 이미 선택된 시작일을 다시 공식 성과로 승격시키지 않도록 평가 정책을 별도 검토해야 한다. 실제 DB·R2 연동 및 개인정보·데이터 표시 권리 검토 전에는 API에 점수 값을 공개하지 않는다.

## 사용자 점검표

1. 로컬 및 PR 게이트의 패키지 빌드·정적 검사·전체 시험을 확인한다.
2. PostgreSQL 환경이 준비되면 마이그레이션 적용, 거래 단위 롤백과 동일 입력 멱등성의 실제 서버 시험을 실시한다.
3. 실제 5일 정답 뒤 R2 공식 점수 선택과 DB 행의 해시·시각을 대조한다. 비공개 수치는 공개 로그에 기록하지 않는다.
