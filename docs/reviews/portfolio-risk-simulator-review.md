# 포트폴리오 시나리오 리스크 시뮬레이터 구현

작성일: 2026-10-08, 한국 시각. 기능 브랜치: `feat/portfolio-risk`.

## 사용자에게 달라진 점

메인 화면을 시나리오 선택에서 포트폴리오 결과 중심으로 변경했다.
SPY 비중을 0–100% 정수로 입력하면 TLT는 나머지 비중으로 계산한다. 선택적 USD 평가액,
발표 후 5분·30분, 합성 데모·실제 자료 모드를 지원한다. 평균 변화율·금액, 상승·하락·보합
추정확률, P10–P90과 P25–P75·중앙값, 자산별 평균 기여를 표시한다.
상회·부합·하회 확률과 표본은 접힌 근거 영역에 두고 연구 점수는 `/methodology`에 유지한다.
FOMC·원유재고는 준비 중 표시이며 수집·모델·실측 결과를 구현한 것은 아니다.

## 계산과 코드 구조

- `packages/event_study/shockgraph_analytics/portfolio.py`: 비음수·합계 1의 두 자산 비중을
  검증한다. 비중이나 누락된 시나리오를 자동 재정규화하지 않는다.
- 같은 사건의 SPY·TLT 수익률을 먼저 비중 합산하고, 시나리오 안에서는 사건별 동일 비중,
  시나리오 간에는 계약 확률을 적용한 경험적 혼합분포를 만든다. 조건부·통합 분위수 모두
  포트폴리오 공동수익률에서 계산한다. 자산별 분위수 합산이나 독립 표본 추출을 하지 않는다.
- 정확히 상쇄되는 단순 수익률은 Decimal 합산으로 부호의 부동소수점 오차를 방지한다.
  상승은 수익률 `>0`, 하락은 `<0`, 보합은 `=0`으로 정의한다.
- 양의 확률이 있는 시나리오의 사건 수가 표시 문턱 10건 미만이면 전체 결과를 보류한다.
  확률 0인 시나리오는 전체 혼합을 막지 않는다. 문턱 10건은 통계적 충분성의 보증이 아니다.
- `GET /v1/portfolios/cpi`: `spy_weight`, `tlt_weight`, `horizon`, `source`, 선택적
  `portfolio_value`를 받는다. 비중 합은 정확히 1이며 USD 평가액은 0–1조 범위다.
  기본 자료 모드는 실제이고, 없으면 `pending`·`result=null`이다.
- `apps/web/components/portfolio-contract.ts`: 출처·요청 비중·구간·확률 합·표본·분위수
  순서·금액·자산 기여 일치를 검사한다. 모순된 응답을 표시하지 않는다.
- `dashboard.tsx`: 입력 변경 때 이전 비중의 결과를 숨기고 요청을 취소한다.
  짧은 입력 지연 처리, 제한 시간, 오류·재시도·표본 부족·실제 자료 대기를 제공한다.
- Next.js 동일 출처 GET 프록시의 허용 목록에 포트폴리오 경로를 추가했다.
- CI에 기능 브랜치, 웹 응답 계약 검사, 컨테이너의 포트폴리오 경로 검사를 추가했다.
  실제 수집 작업의 별도 허가 조건은 변경하지 않았다.

## 데이터와 해석

기존 독립 합성 사건 36건과 합성 계약 확률을 사용한다. 새로운 실제 Kalshi·ETF 자료를
수집하거나 실측 포트폴리오 예측 성능을 평가하지 않았다. 사건별 실제 입력의 연결 대기
상태는 유지한다. 이 결과는 시장 기대와 과거 공동 반응에 기반한 모형 추정이며 검증된
투자 성과·매수/매도 권유·손실 한도가 아니다. P10–P90의 실제 미래 보장률은 미검증이다.
현재 조건과 과거 경제 국면의 차이를 통제한 고차원 모델도 아니다.

실제 모드의 공개 허가 필드·참조는 기록을 검증하는 형식이며 공급자 허가의 진위를 증명하지 않는다.
합성 데모의 완성을 실측 서비스 출시 완료로 해석하지 않는다.

## 실행과 화면 확인

```bash
make PYTHON=.venv/bin/python api-demo
npm --prefix apps/web run dev
```

두 명령은 별도 터미널에서 실행한다. 비중·평가액 직접 입력은 실행 앱에서 지원한다.
[오프라인 미리보기](../ui/portfolio-risk-dashboard.html)는 같은 React 컴포넌트를 API 계산
결과로 렌더링하며 6가지 예시 비중·2가지 구간·합성/실제 대기 상태를 전환한다.
오프라인 입력 필드는 비활성이고 실시간 수집이나 임의 비중 계산을 하지 않는다.

## 검증 결과

- `make PYTHON=.venv/bin/python quality`: Ruff 통과, Pyright 오류·경고 0개.
- `make PYTHON=.venv/bin/python test`: 177개 통과. 신규 13개는 공동 상쇄, 손계산 혼합,
  비중·금액·기여, 부분 표본 부족·확률 0 시나리오, 잘못된 입력과 데모/실제 분리를 확인했다.
  기존 Starlette 사용 중단 예정 경고 1개.
- 웹 TypeScript 검사와 프로덕션 빌드 통과.
- 웹 응답 계약 30개 상태 확인: 정상 24개와 출처·비중·분위수·확률·기여·금액 변조 6개 거절.
- API·웹 프로덕션 서버를 함께 실행한 HTTP 확인: 비중 0–100%와 두 구간의 202가지
  동일 출처 요청이 정상. 메인·연구 노트 200, 실제 자료 대기, 잘못된 비중 422,
  프록시 미지원 경로 404 확인. 확인 뒤 두 프로세스를 종료했다.
- 오프라인 미리보기 생성 완료. 실제 브라우저의 픽셀·클릭 검사는 수행하지 않았다.
- 기존 Ruff 실행 파일의 잘린 바이너리를 같은 잠금 버전 0.16.9로 재설치했고,
  Next.js 손상된 빌드 캐시를 삭제한 뒤 빌드가 통과했다. 의존성 버전 변경은 없다.
- 실제 수집·학습·실측 성능 시험·클라우드 배포·원격 CI 실행 결과 확인은 수행하지 않았다.

합성 기본 예시(SPY 60%·TLT 40%, 30분, $10,000)의 결과는 평균 -0.1412%,
상승 45%·하락 55%, P10–P90 [-1.3196%, +0.9388%]다. 코드와 화면의 계산 예시이며
실제 시장 예측이나 투자 성과가 아니다.

## 사용자 점검표

1. 예시 비중 또는 직접 입력을 바꾸면 비중·결과가 함께 변경되는지 확인한다.
2. 같은 자산 구성에서 5분·30분의 정의가 명확한지 확인한다.
3. 평가액을 지우면 변화율만 남고, 입력하면 USD 금액으로 환산되는지 확인한다.
4. 실제 모드에서는 데모 결과 없이 연결 대기가 표시되는지 확인한다.
5. 시나리오 용어를 먼저 이해하지 않아도 내 자산의 변화 추정치를 읽을 수 있는지 확인한다.
6. 화면의 확률·범위가 실측 예측 성과라는 인상을 주지 않는지 확인한다.
