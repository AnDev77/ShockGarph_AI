# PostgreSQL 실연결과 회원 관심 종목 인증 경계 리뷰

작성일: 2026-10-27. 초안 PR #11의 기존 API가 실제 DB에서도 동작하는지를 검증한다. 회원 가입·로그인 자체는 doChallenge에 있으며, 이번 코드는 그 서비스의 JWT 형식을 가진 요청이 ShockGraph API에서 회원별로 처리되는지 확인한다.

## 변경과 작업량

- `.github/workflows/quality-gate.yml`에 격리된 PostgreSQL 16 시험 서비스를 추가했다. 테스트 전용 DB와 연결 문자열은 품질 게이트 내부에서만 사용하고, 운영 비밀값이나 가격 자료는 사용하지 않는다.
- `tests/integration/test_postgres_auth_boundary.py`에 실제 migration 0003 재적용, 사건 자료의 관계 저장, 관심 종목 중복 추가, 다른 회원의 삭제 거절 효과, 미래 발표 원문 숨김을 묶은 실DB 시험을 추가했다. doChallenge `JwtTokenProvider`가 만드는 HS256 JWT의 헤더와 페이로드 바이트 배열을 Python 표준 라이브러리로 독립 구성해 API에 보낸다.
- 실DB 시험은 이름이 `_test`로 끝나는 DB에서만 마이그레이션·정리를 수행한다. PostgreSQL이 없는 로컬에서는 해당 시험을 명시적으로 건너뛰고, 원격 게이트에서는 반드시 실행되도록 환경을 설정했다.

## 시작·중간·완료 근거

시작 시점에 기존 API·SQL 시험은 합성 토큰과 가짜 연결에서만 193개 통과했다. 작업 중 이 실행 환경의 가상환경 `python` 링크가 끊겨 있어 로컬 실행이 처음 실패했고, 현재 Python 실행 파일의 링크를 복구했다. 이어 Ruff의 줄 길이 4건, Pyright의 타입 오류 7건을 수정했다. 이 문제는 새 시험 코드 작성 과정의 문제였으며 실제 DB 결과와 구분한다.

로컬 전체 194개 시험은 통과하고 실DB 1개는 서버가 없어 건너뛰었다. 이후 원격 게이트의 실제 연결, wheel 소스, Ruff·Pyright, 전체 시험을 확인한 뒤 완료 근거를 추가한다.

## 객관적 한계와 사용자 점검

이 시험은 격리된 CI DB와 Java 발급 형식을 재현한 토큰의 상호 운용 계약이다. 실제 doChallenge 로그인 서버가 발급한 토큰을 두 서비스에 전달해 인증한 배포 시험, 실제 운영 DB, 회원 탈퇴 동기화는 아직 아니다. 기존 토큰에 issuer·audience 구분이 없고 공유 서명 비밀값 운영도 설계해야 한다. 공식 발표 및 자산 가격을 수집하거나 표시한 시험이 아니며 예측 성능·제품 수요는 HOLD다. 사용자 점검에서는 두 회원으로 로그인해 한 회원의 관심 종목 추가·삭제가 다른 회원 목록에 영향을 주지 않는지 확인한다.
