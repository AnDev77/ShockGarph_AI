# CPI 원본의 서비스 스냅샷 변환과 연결 진단 리뷰

작성일: 2026-10-11, 한국 시각. 브랜치: `feat/data-serving`.

## 완료한 작업과 실제 결과

기존 포트폴리오 계산을 바꾸지 않고, 최초 CPI 발표·발표 전 컨센서스·같은 사건의 SPY/TLT
분봉·대상 사건 다중 임계값 호가를 결합하는 오프라인 변환 경로를 구현했다.
실제 자료가 없을 때 어느 입력이 필요한지 API와 화면에서 확인할 수 있다.
외부 API 재수집·새 모델 훈련·실제 예측 성능 실험은 이번에 하지 않았다.

합성 역사적 사건 36건을 원본 형식으로 만들고 서비스 스냅샷으로 변환했다.
실제 연결 감사는 `blocked`다. 설정 파일, 최초 발표 원본, 가격 원본, 당시 컨센서스,
대상 전체 호가, 이용 범위 기록이 필요하다. 실제 포트폴리오 결과는 여전히 `pending`이다.
실제 자료가 없을 때 합성 수치로 자동 대체하지 않는다.

현재 작업구와 첨부 ZIP 12개 목록에는 실제 입력 파일이 없었다. 기존 Actions artifact는
집계 JSON 6개뿐이어서 사건별 수익률을 복원할 수 없다. 과거 SIP/BLS 수집 성공 기록과
현재 서비스에 원본이 연결돼 있다는 주장은 구분해야 한다. 집의 로컬 원본은 이번 검사 범위가 아니다.

## 정확성 및 해석 범위

역사적 컨센서스가 발표 후 자료이거나 수익률이 대상 기준시각 이후에 가용해졌다면 사용하지 않는다.
대상·미래 사건을 제외하고, 중복 행은 임의로 선택하지 않는다. 누락 가격은 보간하지 않는다.
공동수익률의 비교 집합을 맞추기 위해 네 자산/구간 조합 모두 있는 사건만 유지한다.
이 기준의 표본 손실은 계보 커버리지에 남긴다. 고정 `0.3%` 이진 outcome은 이 필터에 쓰지 않는다.

최초 발표값과 기존 candle의 가용 시각은 각각 공식 발표 시각·candle end 대리값이다.
가용성의 시간 검사를 구현했지만 실제 수신 지연 측정이나 모든 정보 누수 제거를 증명한 것은 아니다.
BLS URL·파일 해시·스키마 검증도 원본 진실성이나 예측 정확도를 증명하지 않는다.

이용 기록은 확인된 증빙과 범위를 기록하는 형식이다. 형식을 채워서 공급자 권리를 얻는 것이 아니다.
정식 변환은 그 기록이 없거나 범위가 부족하거나 만료됐으면 금융 파일 내용을 읽기 전에 멈춘다.
기존 실제 연구 Actions의 이용 범위 게이트는 유지했고 실제 원본 업로드를 추가하지 않았다.

보고서만 `snapshot_built`라고 적혀 있어도 실제 스냅샷이 적재되지 않으면 계산하지 않는다.
감사 보고서를 설정한 경우 파일 해시가 일치해야 하며, 합성 자료를 actual로 적재할 수 없다.
최소 표본 미달은 연결 오류와 구분한다. 현재 API는 역사적 스냅샷이며 최신 대상 자동 갱신은 미구현이다.

FastAPI TestClient의 기존 httpx 사용 중단 예고 경고 1건이 남아 있다.
이 환경의 이전 `.next` 캐시 손상으로 첫 빌드가 실패했으며 생성 캐시를 비운 후 통과했다.
HTTP 첫 실행은 환경의 네트워크 인터페이스 조회 제한으로 실패했으며,
웹을 `--hostname 127.0.0.1`로 명시해 재실행하고 통과했다.
테스트는 데이터 처리 소프트웨어를 검증했다. 신규 금융 실측 수집, 예측 성능 개선,
공급자 이용권 확보, 브라우저 시각 검사, 실제 클라우드 배포 성공을 뜻하지 않는다.
원격 CI 결과는 GitHub Actions에서 별도로 확인한다.

## 사용자가 우선 볼 항목

- [데이터 연결 안내](../cpi-serving-data-guide.md)의 입력 표와 현재 자료 상태를 확인한다.
- 집에서 보관한 `release_vintage.csv`, `asset_minute_bars.csv`, 전체 호가 보고서가 있다면
  API 키 없이 원본 보관 위치부터 확인한다. 과거 컨센서스가 없으면 actual로 대신 채우지 않는다.
- `serving-audit`의 종료 코드보다 `status`와 `blocker_codes`를 확인한다.
- 실제 자료 준비 후 build 결과의 두 경로를 API 환경변수로 설정하고 재시작한다.
  `/v1/data-readiness/cpi`가 `ready`인지와 분석 기준시각·대상 발표가 맞는지 확인한다.
- 비중을 바꿔 평균·범위가 변하는지 확인한다. 표본 부족일 때 숫자가 보류되는지도 확인한다.
- [화면 미리보기](../ui/portfolio-risk-dashboard.html)는 합성 설명용이다. 실제 성과로 소개하지 않는다.

다음 실제 입력 작업은 원본 복구와 발표 전 컨센서스·호가·이용 범위 확인이다.
그 후 실제 스냅샷 변환·적재를 진행한다. 모델 연구를 다시 늘리기보다 배포 가능한 데모와
실제 자료의 연결 상태를 구분해서 마무리한다.
