# 공식 위험 평가의 독립 구간 감사 리뷰

## 직전 상태와 변경 구조

PR #8은 사후 점수의 R2 원본 대조와 PostgreSQL 메타데이터 저장 경로를 만들었지만, 객체 수·모형 행 수와 실제로 평가 가능한 독립 시작일 수를 구별하는 감사 보고서는 없었다. 새 `scripts/audit_official_evaluation.py`는 비공개 R2 index를 전부 읽어 해시와 원본을 재감사하고, 같은 거래일의 첫 예측만 선택한다. 기존 `official_score_plan`이 선택한 기간별 첫 성숙 정답을 기준으로 5일·20일의 성숙 시작일 수와 대기 시작일 수를 각각 센다. 평가 창은 양 끝 거래일을 포함하는 구간으로 보고 종료일이 가장 빠른 창부터 선택하여 서로 겹치지 않는 최대 개수를 계산한다. TLT와 SPY, 네 모형의 행을 독립 예측 사례로 곱하지 않는다.

보고서는 원본 index 수, 고유 시작일 수, 중복 index 수, 기간별 성숙·대기·비중첩 개수만 포함한다. 내부 객체 경로, 가격, 오차, 신뢰구간은 출력하지 않는다. 대상 버킷에서 index가 250개를 넘으면 기존 전체 감사 비용 한도에 맞춰 실패한다. 실제 R2 호출은 하지 않았으며 PostgreSQL 접속도 필요하지 않다.

## 작업량과 시험 결과

새 시험은 코드가 없을 때 import 오류로 먼저 실패했다. 합성 R2로 5일 정답만 성숙한 경우, 같은 거래일의 중복 보관, index 바이트 변조를 확인하고 비중첩 구간의 종료일 우선 선택을 검증했다. 처음 전체 품질 검사에서 `Iterable` import 위치를 Ruff가 지적하여 수정했다. 별도 worktree에 가상환경이 없어 Pyright가 55개 패키지 import 오류를 냈으며, 검증에 사용하던 기존 환경을 연결한 뒤 정적 검사를 다시 실행했다. 이 오류는 소스의 금융 계산 실패와 구별한다.

최종 로컬 전체 시험은 187개가 통과했고, 새 대상 시험 4개가 포함됐다. Ruff 위반 0건, Pyright 오류·경고 0건, wheel 빌드와 필수 소스 7개 검사에 성공했다. PR 자동 게이트는 별도로 확인한다. 합성 시험의 개수는 실측 가격의 예측 성과나 데이터 공급권 검증을 뜻하지 않는다.

## 증권사 리서치 관점의 판정

서로 겹치는 20일 창과 종목·모형 반복을 단순 행 수로 세지 않는 것은 성능 주장의 최소 통제다. 이 보고서의 비중첩 개수는 특정 선택 규칙으로 얻는 기술적 상한이며, 통계적으로 충분한 독립 표본이나 모델의 우위를 증명하지 않는다. 표본의 시간순 홀드아웃, 동일 날짜의 A/B 비교, 불확실성 추정, 실제 PostgreSQL 저장과 외부 사용자 효용은 아직 미검증이다. 첫 실제 사전 예측의 5일·20일 정답이 없다면 연구 및 제품 판정은 `HOLD`로 유지한다.

## 사용자 점검표

1. PR 게이트에서 wheel 내용·Ruff·Pyright·전체 시험 결과를 확인한다.
2. 별도 비공개 운영 환경에서 읽기 전용 감사 명령을 실행해 시작일 수와 기간별 성숙 수를 비교한다.
3. 실제 미래 정답을 모은 뒤 비중첩 개수와 표본 불확실성에 따라 성능 공개 가능 여부를 다시 판단한다.
