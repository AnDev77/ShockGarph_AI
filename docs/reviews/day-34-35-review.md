# 34~35일차 CPI 다중 임계값 분포와 컨센서스 시나리오

## 이번 작업의 결론

기존 `CPI MoM > 0.3%` 이진 모델은 성능 비교용 기준선으로 유지한다. 주 연구 후보는
한 CPI 사건에 열린 Kalshi의 여러 `Above c%` 계약을 함께 수집해 CPI 확률분포를 만들고,
당시 전문가 컨센서스를 기준으로 하회·부합·상회 확률을 계산하는 방식으로 확장했다.
이번 단위에서는 분포 변환과 실제 API 감사 경로까지 구현했다. 역사적 컨센서스 원천과
ETF 수익률 모델의 결합은 아직 하지 않았으며 값을 임의로 만들지 않았다.

## 왜 이 구조인가

`P(CPI>0.2)`와 `P(CPI>0.3)`은 서로 겹치므로 그대로 합치면 확률이 중복된다.
대신 임계값을 오름차순으로 놓고 누적 초과확률의 차이를 구하면 배타적인 구간이 된다.

예를 들어 `q(0.2)=0.80`, `q(0.3)=0.55`, `q(0.4)=0.20`이면 다음과 같다.

| CPI 구간 | 계산 | 확률 |
|---|---:|---:|
| `X≤0.2` | `1-q(0.2)` | 0.20 |
| `0.2<X≤0.3` | `q(0.2)-q(0.3)` | 0.25 |
| `0.3<X≤0.4` | `q(0.3)-q(0.4)` | 0.35 |
| `X>0.4` | `q(0.4)` | 0.20 |

합은 정확히 1이다. 이 변환은 독립 시나리오 가격을 합으로 나누는 정규화가 아니라,
중첩된 누적사건을 차분해 배타적 구간으로 바꾸는 연산이다.

실제 호가에서는 높은 임계값의 확률이 잠시 더 높아지는 순서 역전이 생길 수 있다.
작은 역전은 비가중 L2 등위회귀로 가장 가까운 단조감소 곡선에 투영한다. 원본과
조정량을 모두 남기고, 한 점이라도 0.05보다 크게 바뀌면 품질 부족으로 계산을
중단한다. 0.05는 실증적으로 확정된 값이 아니라 초기 연구 기준이므로 후속 민감도
분석에서 0, 0.02, 0.05 등을 비교해야 한다.

## 컨센서스 변환

Kalshi KXCPI 계약은 공식 페이지의 규칙상 한 자리 소수로 공표된 CPI 전월비가
임계값보다 큰지를 정산한다. 컨센서스가 `c`, 보고 간격이 `d=0.1%p`일 때 정확한
`c-d`, `c` 계약이 모두 있어야 다음을 계산한다.

- 하회: `1-q(c-d)`
- 부합: `q(c-d)-q(c)`
- 상회: `q(c)`

경계 계약이 없으면 선형 보간하지 않는다. 컨센서스도 확률 기준시각까지 공개된
빈티지만 허용한다. 이 제약은 과거 사건에 현재 컨센서스를 붙이는 미래 정보 누수를
막는다.

근거로 확인한 공식 자료는 [Kalshi KXCPI 사건 페이지](https://kalshi.com/markets/kxcpi/cpi/kxcpi-26aug)와
[Kalshi 시장 API 문서](https://docs.kalshi.com/api-reference/market/get-market)다. 실제 연구
실행에서는 각 원본 응답과 계약 규칙의 해시를 별도로 보존한다.

  - 발표 전 한 시간의 1분 캔들에서 기존 호가·스프레드·거래량 게이트 재사용
  - 원본 불변 저장과 내용 해시 기반 보고서 생성

  - 원시 확률과 해시를 노출하지 않는 CI 집계 생성
- GitHub Actions
  - `KXCPI-26AUG`, `2026-09-11T12:25:00Z`를 고정 실데이터 점검 대상으로 추가
  - 임계값 수, 포함 상태, 단조 여부와 최대 조정량만 14일 산출물로 보존

## 검증한 실패 조건

- 다른 CPI 사건의 계약 혼합
- 같은 임계값 또는 시장 티커 중복
- 기준시각 이후에 관측·이용 가능해진 호가
- 발표 전 15분보다 오래된 호가
- 티커 임계값과 API `floor_strike` 불일치
- 지원하지 않는 방향 관계
- 0.05를 넘는 단조 투영 조정
- 컨센서스와 분포의 사건 불일치
- 기준시각 이후 공개된 컨센서스
- 컨센서스의 정확한 인접 경계 누락
- 발표시각과 같거나 늦은 확률 기준시각

## 사용자가 우선 확인할 항목

1. `status`가 `eligible`인지 본다. `abstained`면 `curve_error`부터 확인한다.
2. `candidate_threshold_markets`와 `quote_status_counts` 합계를 비교한다. 계약 수가 많아도
   발표 직전 유효 호가가 두 개 미만이면 분포를 만들 수 없다.
3. `raw_monotone`이 거짓이면 `max_isotonic_adjustment`를 본다. 허용됐다는 사실이
   경제적으로 정확하다는 뜻은 아니다.
4. `thresholds`가 컨센서스 `c-0.1`, `c`를 실제로 포함하는지 확인한다. 둘 중 하나가
   없으면 하회·부합·상회 계산을 생략하는 것이 정상이다.
5. `as_of`가 실제 BLS 발표보다 엄격히 이른지 확인한다. 현재 예제는 거래 종료시각인
   발표 5분 전을 쓴다.
6. 이번 결과는 CPI 분포 품질 검사다. ETF 수익률 예측 성능, Kalshi의 증분 가치,
   상용 모델의 정확도를 입증한 결과로 읽지 않는다.

## 아직 부족한 것과 다음 작업

가장 큰 결손은 사건별 역사적 전문가 컨센서스 빈티지다. 공급원과 이용조건을 확정한
뒤 `consensus_vintage.csv`를 수집해야 한다. 그다음 모든 과거 CPI 사건에 같은 곡선
감사를 배치 실행하고, 정확한 경계가 있는 사건만 SPY·TLT 5분·30분 수익률과 결합한다.
시간순 학습에서 과거 수익률을 하회·부합·상회 세 집단으로 나누고 현재 확률로 혼합해,
다음 네 모델을 같은 시험 사건에서 비교한다.

1. 무조건부 과거 수익률 분포
2. 고정 `T0.3` 이진 Kalshi 기준선
3. 컨센서스만 사용한 전통 거시 기준선
4. 컨센서스와 Kalshi 다중 임계값을 함께 사용한 후보

후보 4가 후보 3보다 CRPS·하방 분위수 손실에서 반복적으로 나아야 Kalshi의 독립적
부가가치를 주장할 수 있다. 독립 시험 사건이 부족하면 DNN으로 넘어가지 않고
계속 수집하며 탐색 결과로만 표시한다.
