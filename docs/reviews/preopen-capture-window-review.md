# 사전 예측 보관 시각 여유 확보 리뷰

## 확인한 운영 사실과 변경 이유

2026-10-26 첫 `main` 예약 실행은 뉴욕 07:10 목표보다 6시간 8분 50초 늦은 13:18:50에 시작했다. 실행 자체는 성공했고 기존 2026-10-23 거래일이 이미 보관되어 새 가격 수집은 생략됐다. 비공개 원본 감사와 공식 채점 단계는 성공했으며 공식 성숙 점수는 0건이었다. 이는 예정 시각에 실행됐다는 뜻도, 새로운 예측 표본이 늘었다는 뜻도 아니다. [실제 실행](https://github.com/AnDev77/ShockGarph_AI/actions/runs/40367432971)의 단계 상태와 점수 건수만 확인했고 가격·오차·객체 키·비밀값은 기록하지 않았다.

기존 평일 07:10 예약은 다음 정규장 09:30 개장과 2시간 20분 간격이다. 보관 함수가 요구하는 개장 1시간 전 완료 조건을 고려하면 예약 지연과 작업 시간에 쓸 수 있는 여유가 1시간 20분뿐이다. 어제와 같은 지연이 신규 거래일 수집 때 반복되면 원본은 저장되더라도 공식 사전 예측은 생성되지 않는다. 예약 시각을 뉴욕 현지 평일 00:10으로 앞당겨 다음 장까지 9시간 20분의 시간을 둔다. 동일 거래일 중복 방지와 R2 불변 보관, 개장 전 영수증 검사는 그대로 적용한다.

## 검사와 한계

로컬에서 `make quality`의 Ruff·Pyright 오류와 경고 0건, `make test`의 전체 184개 통과를 확인했다. wheel을 빌드하고 필수 소스 7개 포함 검사를 통과했다. [초안 PR #10의 원격 품질 게이트](https://github.com/AnDev77/ShockGarph_AI/actions/runs/40424616823)에서도 빌드·wheel 내용·정적 검사·전체 시험 단계가 모두 성공했다.

새 계약 시험은 2026-10-26 월요일, 다음 거래일 화요일, 미국 서머타임 종료 후인 2026-11-03 화요일에서 마지막 완료 거래일 종가 이후 예약되는지 확인한다. 관측된 6시간 8분 50초 지연을 6시간 9분으로 올림해 적용해도 개장 1시간 전 보관 조건을 만족하는지 검사한다. 이 시험은 시간대 변환과 예약 간격의 계약을 확인한다. GitHub 예약 실행이 반드시 그 시간에 시작하거나 실제 Alpaca/R2 저장이 성공한다는 보장은 아니다.

실제 GitHub Actions 예약은 지연 또는 누락될 수 있다. 이번 변경은 관측된 지연에 대한 여유를 키우지만 무기한 지연을 해결하지 못한다. 2026-10-23 최초 사전 예측의 5일·20일 정답은 여전히 성숙하지 않았고 공식 미래 성과는 `HOLD`다. PR은 초안으로 두고 다음 예약 실행에서 실제 시작 시각, 중복 방지 판정, 원본 감사, 신규 예측 생성 여부를 다시 확인한다.

## 증권사 리서치 관점

사전 예측의 이용 가능 시각을 보장하지 못하면 나중 가격을 보며 계산한 값을 사전 성과로 오인할 위험이 있다. 개장 전 영수증 검사를 유지하면서 수집 시각 여유를 늘리는 결정은 자료 계보의 신뢰성을 높인다. 다만 예측 시작일의 실제 증가, 동일 기간 A/B 오차 비교, 독립 구간의 불확실성, 사용자 효용 증거는 이번 시각 변경만으로 추가되지 않는다.

## 사용자 점검표

1. 로컬 시험·정적 검사·wheel 내용과 PR 원격 품질 게이트를 확인한다.
2. 변경이 `main`에 반영된 후 다음 예약 실행의 현지 시작 시각과 단계 상태를 확인한다.
3. 신규 사전 예측 건수와 향후 성숙 점수 건수를 구분하여 확인한다.
