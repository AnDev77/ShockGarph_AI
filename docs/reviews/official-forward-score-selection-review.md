# 공식 사후 평가 빈티지 선택 리뷰

## 직전 상태와 변경 구조

기존 비공개 점수 아티팩트는 예측·정답 index 키를 직접 주면 두 원본을 검증해 저장했다. 같은 2026-10-23 거래일에서 이미 두 예측 index가 생겼고, 후속 정답본을 여러 번 수집하면 둘 모두를 독립 사례처럼 집계할 위험이 있었다. `official_score_plan`은 보관된 index 전체의 원본·저장 시각을 재감사하고 같은 시작일에서 가장 먼저 저장된 예측을 고정한다. 5일과 20일의 각 정규장 종료 뒤 처음 수신한 완전한 양 종목 가격본을 기간별 공식 정답으로 고정한다. 손상된 원본은 다른 가격본으로 조용히 대체하지 않고 실패한다.

`run_official_scores`는 그 조합만 기간별 별도 불변 R2 객체에 저장한다. 같은 조합을 다시 실행하면 새 객체는 없다. 수집 워크플로가 가격 감사 다음에 이 명령을 호출하며, 로그에는 시작일·점수·신규 객체 수만 출력한다. 비공개 점수 수치와 객체 경로는 출력하지 않는다. 기존 수동 점수 저장 함수의 조합별 객체는 연구·진단 용도로 계속 남지만 공식 집계에는 선택 계획의 결과만 사용해야 한다.

## 검증 대상과 결과

합성 원격 저장소에서 첫 시작일의 중복 예측 2건, 5일 후 가격본, 20일 후 가격본을 구성했다. 첫 시작일의 5일 정답은 첫 5일 가격본으로 고정되고, 첫 시작일의 20일 정답은 첫 20일 가격본으로 결정되었다. 그 사이 생성된 두 번째 시작일에도 5일 점수가 성숙했기 때문에 최종 시작일 2개, 기간별 객체 3개, 종목별 점수 6개가 계산되었다. 재실행에서 신규 객체는 0개였고, 후속 원본을 변조한 경우 공식 점수 저장 전에 실패했다. 대상 통합 시험 15개, 전체 183개, Ruff 위반 0건, Pyright 오류·경고 0건, wheel 필수 소스 7개를 확인했다.

## 증권사 리서치 관점의 판정

같은 시작일을 두 번 세지 않고 사후 수정가격에서 유리한 빈티지를 골라 다시 점수를 내지 않도록 기간별 정답 선택을 고정한 것은 필요한 운영 통제다. 다만 5일 정답과 20일 정답은 서로 겹치고 연속 시작일도 겹치므로 객체 3개나 점수 6개가 독립 표본 3개 또는 6개를 뜻하지 않는다. 정답본의 당시 가격과 이후 개정 차이, 원격 새 실행, 기본 브랜치 예약 수집, PostgreSQL 평가 메타데이터, 데이터 표시 권리가 미검증이다. 2026-10-26 현재 실제 성숙 정답 0건, 검증된 예측 우위 0건, 제품 판정 `HOLD`다.

## 사용자 점검표

1. 초안 PR의 품질 게이트에서 wheel·정적 검사·전체 시험이 다시 재현되는지 확인한다.
2. 기본 브랜치에 워크플로가 반영되고 5일 미래 정답이 성숙한 뒤, 비공개 실행의 건수와 원본 감사만 확인한다. PR 단계의 예약 실행은 활성화됐다고 간주하지 않는다.
3. 표본이 쌓인 뒤 TLT 5일과 20일을 나누어 사전 등록한 A·B 기준선을 동일 날짜에 비교하고 독립성·불확실성을 판단한다. 점수 수치와 가격은 권리·판정 전 공개하지 않는다.
