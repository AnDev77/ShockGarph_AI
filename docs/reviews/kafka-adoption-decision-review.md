# Kafka 수집 사건 전달 도입 결정 리뷰

작성일: 2026-10-27. 사용자 요청으로 Kafka 일괄 금지 조항을 철회하고 포트폴리오에서 실제 증명할 기능을 정의했다.

## 변경 전 문제

`AGENTS.md`, 최상위 명세와 여러 활성 문서가 Kafka를 금지하고 RabbitMQ만 다음 브로커로 적었다. `ingestion_outbox` 스키마는 있지만 원본 저장 뒤 한 DB 트랜잭션의 메타/아웃박스 기록, 발행기, Kafka 소비자는 아직 없다. 단순 브로커 설치를 제품 성과처럼 제시할 근거도 없다.

## 선택과 작업량

Kafka는 **검증된 수집 사건을 후속 정규화/분석 작업에 전달**하는 데 먼저 쓴다. `AGENTS.md`·명세·아키텍처·의존성·5일 목표·제품 장애 설계를 정정하고, [도입 계약](../kafka-event-pipeline-decision.md)에 단일 토픽, 파티션 키, 아웃박스 발행, 멱등 소비, 장애 주입, 관측 기준을 기록했다. 채팅의 원장, 가격 원본 저장소, 검증 없는 모델 성능의 근거로 쓰지 않는다. RabbitMQ 동시 운영은 선택하지 않는다.

## 검증과 남은 조건

이번 변경은 설계·개발 제약 변경이다. Kafka 실행 코드/컨테이너/처리량 측정은 아직 없고 사용자가 Kafka를 이용해 볼 수 있는 기능도 없다. 기존 `make quality`·`make test`·wheel과 원격 PR 게이트는 문서 변경이 기존 코드를 깨지 않았는지 확인하는 범위다. 아웃박스의 원자 기록과 발행 중단·중복 소비·재시작을 실제 CI 브로커에서 시험하는 기능 PR이 뒤따라야 한다. 실제 위험 예측 성능과 사용자 수요는 HOLD다.
