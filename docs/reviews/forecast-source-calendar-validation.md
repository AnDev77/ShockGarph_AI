## 발견한 결함과 수정 이유

기존 감사는 원격 객체 해시와 저장 시각을 확인했지만 예측의 기준 거래일과 원본 CSV의 마지막 거래일을 대조하지 않았다. 정답 기간도 5·20이라는 이름만 확인하여 실제 시작일·종료일·종료 시각 또는 중복 기간 오류를 놓칠 수 있었다. 해시가 맞다는 것은 바이트가 일치한다는 뜻이며, 날짜의 의미가 맞다는 뜻은 아니다. 이번 결함은 합성 객체로 재현했으며 실제 운영 데이터가 잘못됐다고 판단한 것은 아니다.

## 구조·추가 기능·코드 경로

- `scripts/archive_forward_capture.py`: 이미 해시를 검사하며 읽은 TLT/SPY CSV 바이트에서 거래일을 파싱한다. 거래일 배열이 검토된 달력과 같은 순서·누락 없는 목록인지 확인하고 마지막 거래일을 기준일로 삼는다. 별도 원격 다운로드는 추가하지 않는다.
- 같은 파일의 `audit_capture`: 예측 origin이 원본 마지막 거래일과 같은지, 정답 5·20기간이 정확히 두 개인지, 각 시작일·종료일·종료 시각이 검토된 거래소 달력과 일치하는지 검사한다. 인덱스가 개장 전에 저장됐는지도 실제 달력에서 얻은 첫 거래일로 검사한다.
- `tests/integration/test_private_forward_archive.py`: 기준 거래일, 20일 시작일, 종료일, 종료 시각, 중복 기간의 다섯 오류를 각각 주입한다. 객체 해시도 다시 계산하여 해시 검사만으로 통과하던 결함을 재현한다.
- 기존 latest·inventory·공식 채점이 공통 `audit_capture`를 사용하므로 같은 검사를 받는다. 원본·기존 R2 객체를 수정하지 않으며 이상 기록은 오류로 차단한다. 모델 계산·정답 정의·예약 일정은 이번 보완에서 변경하지 않았다.
