# 사건 중심 구조와 장애 대응 계획 리뷰

작성일: 2026-10-27. 사용자 제공 토스 Learner's High 적용 제안을 `AGENTS.md`, main과 초안 PR #8~#11, doChallenge 초안 PR #6에 비춰 검토했다.

## 문제와 변경 전 상태

기존 문서의 SPY·TLT 종목별 관측·채팅 계획과 최근 합의한 QQQ·SPY 관심 종목/공식 사건/사건 대화방 동선이 서로 다르다. 실DB 회원 API는 초안 PR #11의 CI에서 검증됐지만 공개 분석 화면·금융 채팅·실제 로그인 연동은 없다. 제안 문서에 Redis, 장애 복구, 모니터링이 제시돼도 병목과 부분 실패가 확인되지 않은 상태에서 도입 결과를 말할 수 없다.

## 선택과 결과

`docs/event-product-architecture-and-incident-response.md`에 현재와 목표 구성을 나눴다. 첫 제품 동선은 QQQ·SPY 사건 중심으로, TLT 예측은 별도 연구로 기록했다. R2/DB의 부분 실패와 가격 빈티지, 금융 공급자 429·timeout·스키마 오류, PostgreSQL/캐시 장애, 인증·채팅 저장·중복 전송의 사용자 응답과 장애 주입 기준을 작성했다. Kafka·Kubernetes·새 MSA는 현시점 도입하지 않으며 Redis·RabbitMQ에는 각각 실측 병목과 아웃박스/멱등 조건을 붙였다.

## 검증과 한계

문서 자체는 구조적 대응 계약이며 장애 복구·채팅 영속성의 구현 시험이 아니다. 로컬 기존 코드 회귀 194개 통과, PostgreSQL 서버가 없는 환경의 실DB 시험 1개 skip, wheel 필수 소스 11개, Ruff/Pyright 오류·경고 0건이었다. 앞선 PR #11 격리 PostgreSQL 게이트는 실DB를 포함한 195개 시험을 통과했다. 이 문서 PR 게이트 결과는 실행 후 별도 기록한다. 공식 QQQ·SPY 관측값의 공개 권리, 실제 doChallenge 발급 토큰의 배포 연동, 금융 대화방 권한·신고·차단, R2/DB 복구, 실제 p95는 미확인이다. TLT 미래 모델 성능과 제품 수요는 HOLD다.

## 사용자 점검

- 첫 화면 종목·방 범위가 QQQ/SPY 사건 중심인지, TLT 연구 수치가 사용자용 관측값과 섞이지 않는지 확인한다.
- 부분 실패에서 재시도 전후 원본 해시와 공식 시작일 수가 바뀌지 않는지 기능 구현 시 주입 시험을 요구한다.
- 회원/채팅 저장 장애에서 빈 데이터나 전송 성공을 꾸며내지 않고 오류·기준 시각을 보여주는지 확인한다.
