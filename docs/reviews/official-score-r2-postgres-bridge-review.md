# 공식 점수의 R2·PostgreSQL 연결 리뷰

## 변경된 구조와 직전 대비

직전 PR #8은 공식 점수용 SQL 스키마와 트랜잭션 안에서 8행을 저장하는 함수까지 만들었다. 이번 작업은 `persist_official_metadata`가 공식 선택 계획을 다시 계산하고 R2에 비공개 점수 객체를 불변 저장한 후, 예측·정답 index와 점수 객체의 원격 바이트를 재조회하여 점수 계산 결과와 대조하도록 연결한다. 검증된 5일 또는 20일의 TLT·SPY 점수 두 개를 네 기준선별 8행으로 저장한다. 작업 기록에는 점수나 내부 객체 경로를 출력하지 않는다.

각 기간의 SQL 쓰기는 별도의 트랜잭션에서 수행한다. 기존 값과 같은 재시도는 신규 0행이고, 같은 시작일·자산·기간·모형에서 출처 또는 수치가 다르면 예외로 해당 기간을 롤백한다. 이미 성공한 다른 기간은 보존되고, 실패 후 다시 실행하면 멱등 방식으로 이어갈 수 있다. 연결에는 `0003_official_forward_scores.sql` 마이그레이션, PostgreSQL 서버, `SHOCKGRAPH_POSTGRES_DSN` 비밀값과 `database` 선택 의존성이 필요하다. 현재 운영 수집 워크플로는 DB 접속값이 없어 이를 호출하지 않는다.

## 확인한 시험과 아직 없는 증거

코드가 없을 때 신규 시험은 import 오류로 실패했다. 합성 R2·SQL 연결의 세 통합 시험에서 처음 8행 생성, 같은 원본을 다시 실행했을 때 신규 0행, 원격 점수 객체의 바이트 변조가 DB 쓰기 전에 실패, 기존 행의 상충이 트랜잭션 오류가 되는지를 확인했다. 전체 시험은 185개에서 188개로 늘었고 모두 통과했다. Ruff 위반 0건, Pyright 오류·경고 0건, wheel 필수 소스 7개 검사에 성공했다.

실제 PostgreSQL 서버의 마이그레이션, 트랜잭션, R2→DB 연결은 시험하지 않았다. 첫 2026-10-23 사전 예측의 5일·20일 미래 정답도 아직 성숙하지 않았고, 실제 MAE나 모델 A/B 개선의 확인 건수는 0이다. 합성 통합 시험은 예측 성과가 아니다.

## 독립 리서치 판정과 운영 점검

공식 첫 빈티지만 DB에 고정하고 저장 객체를 재계산값과 대조하는 절차는 사후 선택과 원본 변조로부터 평가를 보호한다. 다만 DB 행 8개는 종목 2개와 모형 4개의 동일 시작일 관측이며 독립 표본 8개가 아니다. 5일과 20일 표본도 서로 겹친다. 실제 5일 성숙 이후에도 충분한 독립 시작일, 동일 기간의 A/B 비교, 오차의 불확실성, 데이터 공개 권한을 확인하기 전에는 예측 우위와 사용자 효용을 주장할 수 없다. 제품 및 연구 판정은 `HOLD`다.

운영자는 먼저 실제 서버에 마이그레이션을 적용하고 비공개 시험 DB에서 동일 입력 재시도와 상충 입력의 롤백을 확인해야 한다. 그 뒤 실제 성숙 정답이 생겼을 때만 별도 비밀값으로 명령을 실행하고 원격 R2/DB 해시, 고유 시작일 수, 기간별 성숙 건수를 비공개로 대조한다. 공개 화면에는 통과 전 성능 수치를 노출하지 않는다.
