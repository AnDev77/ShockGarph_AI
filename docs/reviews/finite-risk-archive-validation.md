## 발견한 결함·구조·선택 이유

- `scripts/archive_forward_capture.py`의 `audit_capture`는 해시·날짜를 검사했지만 저장된 변동성 값의 숫자 형식과 범위를 검사하지 않았다. 합성 원격 객체에 NaN·무한대·음수·불리언·문자열·null을 넣고 해시를 다시 계산했더니 기존 감사가 통과했다.
- 각 5·20일 기간의 `trailing_volatility`, `ewma_volatility`, `garch_volatility`, `gjr_volatility`에 유한한 음이 아닌 숫자를 요구한다. Python에서 bool이 int의 하위 타입이므로 별도로 거부한다. 변동성 0은 정상 가능한 값으로 허용한다. 임의의 최대 변동성 상한을 추가하지 않는다.
- 기존 latest/inventory/채점 경로가 공유하는 감사 함수에 넣어 한 경로만 수정되는 일을 피한다. 모델 계산이나 저장 스키마는 바꾸지 않으며, 잘못된 값을 자동 보정하거나 삭제하지 않는다. 원격 I/O도 추가하지 않는다.
- 예외에는 실제 값·종목별 성과를 넣지 않는다. CLI의 기존 일반 오류 출력이 유지된다. 실제 운영 데이터에 이러한 오류가 있었다는 주장이 아니라, 오류를 차단하지 못하는 검증 결함의 재현이다.
