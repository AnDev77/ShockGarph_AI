# 기능별 개발 리뷰

사용자가 범위를 명시적으로 바꾸지 않는 한, 프로젝트 개발 요청 한 번은
21일 계획의 연속된 이틀을 진행한다.

작업 시작 전에 목적·범위·검증 방법을 브리핑한다.
새 리뷰는 `kalshi-cpi-history-coverage-review.md`처럼 핵심 기능으로 이름을 짓는다.
기존 `day-*` 파일과 링크는 보존한다. 리뷰에는 다음 내용을 작성한다.

1. 완료한 범위와 의도적으로 미룬 작업
2. 변경된 코드 구조
3. 정확한 테스트·품질 검사 결과
4. 데이터·모델·제품 관련 결정
5. 다음 작업 전에 사용자가 확인하거나 결정할 항목
6. 다음 작업의 계획

일차가 필요하면 본문에서만 기록한다. 커밋 메시지는 실제 주요 변경 내용을 한글로 작성한다.
