# Alpaca SIP 가격 원본과 종목별 스냅샷 연결 리뷰

작성일: 2026-10-22. 이전에는 현재 내려받은 TLT 수정종가 파일 한 벌과
키 없이 실제 수신한 재무부 금리 원본이 있었다. 사용자가 Alpaca를 첫 가격
공급원으로 선택해 실제 API가 제공할 TLT·SPY 가격의 보관·분석 경로를 만들었다.

## 변경된 동작

`AlpacaDailyCollector`는 인증 헤더를 실행 중 메모리에서만 사용하고, TLT·SPY의
`feed=sip`, `1Day`, `adjustment=raw`와 `adjustment=all`을 별개로 요청한다.
각 페이지의 원본 JSON 바이트와 해시·UTC 수신 시각을 불변 저장하고,
페이지 반복·중복 거래일·누락 거래일·비정상 가격을 거부한다. 미국 현지
수신일보다 오래된 마지막 거래일만 요청해 무료 과거 SIP 조회의 최신 자료
제약을 보수적으로 다룬다. Alpaca의 `t`는 일봉이 속한 거래일이지 실제
게시 시각이 아니므로 검토된 거래일 달력의 마감 시각을 관측 기간 끝으로
사용하고, 가격 전체 버전의 이용 가능 시각은 **마지막 페이지의 실제 수신
시각**보다 앞당기지 않는다.

`collect_alpaca_prices.py`는 각각의 응답을 붙인 TLT·SPY 6열 전체 가격 CSV와
원본 응답 해시를 연결한 비공개 manifest를 만든다. 기존
`import_daily_prices`는 두 종목과 `US_SIP` 거래 범위를 허용해 동일한 시점별
가격 스냅샷 검사 경로를 사용한다. 출력은 기존 `PriceSnapshot` 입력 형식의
CSV이지만 한 번 수신한 오늘의 전체 이력을 과거 날짜의 캡처로 둔갑시키지
않는다. 기존 A/B 평가에는 향후 여러 시점의 실제 보관본과 정답 기간이 필요하다.

## 검증 결과와 실제 자료 상태

`make quality PYTHON=.venv/bin/python`에서 Ruff 위반 0건, Pyright 오류·경고
각 0건이었다. `make test PYTHON=.venv/bin/python`의 전체 **157개 시험이 통과**했다.
새 통합 시험은 인증 헤더가 실제 요청에는 들어가고 보관 원본에는 남지 않는지,
두 페이지·두 조정 방식의 TLT 값이 정상적으로 CSV와 스냅샷으로 합쳐지는지
검사한다. SPY·TLT를 함께 수집하는 명령의 비공개 파일·원본 해시 manifest도
합성 SIP 응답으로 검사했고, 누락 거래일과 반복 커서를 거부하는 것도 확인했다.
수신 이전 예측이 나중에 받은 가격 스냅샷을 사용하지 않는 시험 역시 통과했다.

현재 실행 셸에는 `APCA_API_KEY_ID`, `APCA_API_SECRET_KEY`가
없다. 키 값을 조회하거나 인쇄하지 않고 변수의 존재 여부만 확인했다.
`scripts/collect_alpaca_prices.py --end 2026-10-20`은 실제 HTTP 요청 전에
`missing_credentials`를 반환했다. 이 로컬 명령으로는 실제 가격이 없었다.
표에 기록한 테스트의 가격은 합성이고, Actions 실수집 결과는 아래에 기록했다.
개인 API 접근과 공개 웹의 가격·파생 점수 표시 권리도 별도 확인 대상이다.

## GitHub Actions 비밀 변수 연결

사용자는 GitHub Actions에 API 키가 이미 등록되어 있다고 확인했다. 현재 작업
셸에서는 그 값을 읽을 수 없으며 GitHub 연결은 비밀 변수의 **이름과 값**을
조회할 수 없다. `.github/workflows/alpaca-price-collection.yml`은 같은 저장소의
기능 브랜치에 워크플로 파일이 추가될 때 한 번 실행한다. `APCA_API_KEY_ID` 또는
`ALPACA_API_KEY_ID`, `APCA_API_SECRET_KEY` 또는 `ALPACA_API_SECRET_KEY`를
서로 짝지어 환경 변수에 전달한다. 서로 다른 공급원의 키는 Alpaca 인증에
사용할 수 없으며 이름이 다르거나 환경에만 속한 비밀 변수는 이 작업에서
자동으로 연결되지 않는다.

가격 원본과 CSV는 공개 저장소의 커밋·Actions 아티팩트에 업로드하지 않는다.
일회성 러너에서 수집을 검증한 뒤 작업 공간과 함께 삭제된다. 이 첫 실행은
인증·응답 품질·거래일 커버리지 확인용으로, 지속 보관과 과거 예측 성능
입증은 별도의 비공개 저장 경로와 다수의 시점별 캡처가 준비되어야 한다.
수동 실행 버튼은 이 파일이 기본 브랜치에 들어간 뒤 활성화된다.
Alpaca는 `end`를 포함하는 경계로 해석하며 미국 일봉 시각은 현지 자정에
해당하는 UTC 04:00/05:00이다. 첫 구현에서는 마지막 거래일 **다음 날짜**를
상한으로 지정했으나 무료 SIP에서 최근 날짜 요청이 403으로 거절됐다. 이후
요청의 상한을 마지막 거래일의 `23:59:59Z`로 명시해 그날 일봉만 포함하고
응답의 거래일은 원래 요청한 마지막 거래일까지 검사하도록 수정했다.

첫 기능 브랜치 push의 [Actions 실행](https://github.com/AnDev77/ShockGarph_AI/actions/runs/39740895747)은
설치와 비밀 변수 존재 검사를 통과했지만, 가격 수집 요청에서 HTTP 403을
받았다. 키가 두 변수에 연결됐다는 사실과 가격 조회 권한은 다르다.
원인을 구분하도록 워크플로에 2024년 SPY 하루의 IEX·SIP 요청 상태 코드만
출력하는 보수적인 진단을 추가했다. 상태 코드는 실제 가격이나 비밀키가 아니다.
두 번째 [진단 실행](https://github.com/AnDev77/ShockGarph_AI/actions/runs/39741629738)에서
오래된 하루의 IEX와 SIP, 오래된 넓은 SIP 범위는 모두 HTTP 200이었고, 현지
전일에서 **오늘 날짜**까지의 SIP 조회만 403이었다. 키는 Alpaca 과거 SIP에
접근할 수 있으며 최근 요청 상한이 원인일 가능성이 높다. 명시적인 UTC
시각으로 바꾼 전체 수집 결과를 별도로 확인해야 한다.

세 번째 [실수집 실행](https://github.com/AnDev77/ShockGarph_AI/actions/runs/39742059555)은
**성공**했다. `2024-01-02`부터 미국 현지 수집일 전일까지 TLT와 SPY를
각각 **704거래일** 수집했다. 두 종목의 `raw`·`all` 조정본을 합치고,
요청 페이지 원본·해시와 실제 UTC 수신 시각을 일회성 작업 환경에 기록한 뒤
거래일 누락 검사를 통과했다. 이는 실제 API 연결과 자료의 구조·공통
거래일 커버리지를 검증한 결과다. 가격 CSV·원본은 외부에 업로드하지 않아
작업 종료 후 재사용할 수 없다. 당시 시장에서 이용할 수 있던 과거 가격
버전, 공급원의 재배포 권리, 5·20일 A/B 실성능은 여전히 **미검증**이다.
