# 수정가격 전체 스냅샷의 시점별 선택 리뷰

작성일: 2026-10-19. 기능 단위: 과거 수정종가가 뒤늦게 바뀌어도 이전 예측의
입력과 미래 정답의 공개 시점을 혼동하지 않는 계약. 실제 TLT 가격이나 과거
공급원 파일을 받지 않아 수치는 모두 합성 시험 결과다.

## 변경된 코드 구조

| 경로 | 핵심 기능 |
|---|---|
| `packages/risk_engine/shockgraph_risk/daily.py` | 한 시점의 전체 가격 이력인 `PriceSnapshot`, 예측 시각 이전에 캡처된 최신 완전 스냅샷 선택, 같은 조정 기준에서 EWMA·최근 변동성 재계산, 입력 지문·평가 정답 원본 해시 |
| `packages/data_pipeline/shockgraph_data_pipeline/daily_price_import.py` | 기존 단일 시계열 검사를 유지하고 `full_snapshot` 모드에서 과거 날짜의 뒤늦은 가격 수정을 별도 품질 항목으로 기록, 원본 캡처 시각 반환 |
| `scripts/import_daily_prices.py` | `--full-snapshot` 로컬 검사 옵션 |
| `tests/unit/test_price_snapshots.py`, `tests/unit/test_daily_price_import.py` | 뒤늦은 수정의 과거 예측 불변성, 미완전·지연·중복 스냅샷 차단, 정답 캡처 이후 학습, 로컬 스냅샷 검사 |
| `docs/daily-risk-methodology.md`, `docs/data-source-gate-b.md` | 과거 버전 보관·조정 범위·실자료 게이트 |
| `AGENTS.md`, `docs/reviews/README.md` | 새 리뷰의 제목과 파일명을 일차 대신 핵심 기능으로 기록 |

## 시점 규칙

예측 `t`에서 `captured_at <= prediction_at[t]`인 원본 전체 이력 중 **가장 최근에
받은 파일 한 개**를 사용한다. 이 파일이 첫 거래일부터 `t`까지의 연속 거래
세션을 포함하지 않으면 계산을 거부한다. 각 과거 날짜마다 서로 다른 수정 버전을
개별 선택하면 배당 조정 기준이 뒤섞일 수 있다. 입력 지문에는 전체 파일의 원본
해시와 실제 수정종가·게시 시각·캡처 시각을 반영한다.

정답은 평가 시각 전에 받은 전체 이력에서 미래 가격을 읽는다. 그 파일을 실제
받은 시각을 `label_available_at`의 하한으로 설정한다. 분할 이전에 정답이
확정되지 않았으면 `purged_training_rows`에서 제외한다. 파일이 과거 값을
소급 제공하더라도 실제 캡처 시각 이전의 예측 근거로 쓰지 않는다.

## 검증 결과

- `make quality`: Ruff 통과, Pyright 오류·경고 0개.
- `make test`: 전체 100개 통과. 신규 스냅샷 계산 시험 3개와 로컬 입력 시험 1개 추가.
- 합성 수정가격 CSV에 `--full-snapshot` 실행: 6개 세션, 과거 수정 지연 1개를
  보고하면서 구조 검사 통과. 사용 권리·과거 버전 증거 미확인 상태를 유지했다.
- 모든 신규 가격·수정 사례는 합성 자료다. 실제 TLT의 MAE·QLIKE, 경제적
  유의성이나 제품 공개 가능성을 입증하지 않는다.

## 제한과 다음 연결

- 현재 한 CSV는 한 시점의 완전한 TLT/USD/XNAS 가격 이력이다. 역사적 날짜의
  원본을 새로 다운로드해 과거 캡처인 것처럼 취급하지 않는다. `--full-snapshot`
  검사 통과만으로 공급원 권리와 수정종가 빈티지의 진위를 확인할 수 없다.
- 공식 2026년 Nasdaq 일정은 예정 세션이며 임시 휴장 확인과 공급원별 배당·분할
  조정 정의가 여전히 필요하다.
- 실제 과거 캡처 파일을 얻을 수 없다면 무조정 종가와 당시 알려진 배당·분할
  자료로 총수익률을 재구성하는 대안을 공급원 권리와 함께 평가한다.
- 다음 구현은 이용 가능한 자료 범위가 확인된 뒤 스냅샷 목록·파일 해시를
  고정한 비공개 시간순 5일 홀드아웃 보고서다. 20일 목표는 충분한 비중첩
  표본과 함께 판단한다.
