# 발표 전 거시 확률의 TLT 변동성 예측 목표 정정 리뷰

검토일: 2026-10-20

## 최근 목표 문서의 실제 내용

- [연구 가치 재평가](../research-value-assessment.md)는 **기존 가격·변동성·거시
  기대를 알고도 예측시장 확률이 포트폴리오 위험 예측을 개선하는가**를 질문했다.
- 2026-10-19 [프로젝트 명세](../../shockgraph-ai-project-spec.md)의 첫 정답은
  **TLT의 미래 5·20거래일 변동성**이었다. 그러나 발표 전 CPI/Kalshi 확률은
  제품 주 경로에서 후순위 별도 연구로 밀렸다.
- 2026-10-20에 쓴 [TLT 모델 설계](../tlt-volatility-model-design.md)는 과거
  가격만 사용하는 GARCH를 다음 후보로 선정했다. 확률이 기존 정보보다
  추가로 위험을 예측하는가라는 원래 가설과 실험 우선순위가 달랐다.
- 직전 수정에서 첫 정답을 **거시 발표 뒤 TLT의 부호 있는 수익률**로 잘못
  바꿨다. 이는 사용자가 정한 변동성 정답과 다른 문제여서 해당 설계·리뷰와
  최상위 문서의 잘못된 문구를 되돌렸다.

## 이번에 고정한 실험과 제품 순서

| 비교 | 같은 평가 날짜의 입력 | 분리해서 판단할 가치 |
|---|---|---|
| A | 과거 TLT 가격으로 계산한 최근 변동성·EWMA | 단순 기준선 |
| B | 가격과 발표 전에 공개된 금리·VIX·거시 일정/기대 | 전통 정보의 추가 가치 |
| C | B와 같은 규제 모형에 **발표 전 확률 스냅샷**만 추가 | 거시 확률 정보의 추가 가치 `C−B` |
| D | C와 같은 입력·날짜의 작은 머신러닝 모델 | 비선형 모형의 추가 가치 `D−C` |

첫 정답은 `sqrt(sum(r²[t+1:t+h]) / h)`, `h ∈ {5, 20}`이며 **TLT 수익률의
방향이 아니다**. 각 확률 입력은 실제로 예측 전에 이용 가능해야 하고
`available_at <= prediction_at < release_at`을 충족해야 한다. 결측 확률은
0%로 보간하지 않는다. 뒤늦게 나온 CPI 실제치·시장 정산값과 이미 열어 본
2024년 이후의 TLT 탐색 성과를 독립 시험에 소급해서 사용하지 않는다. 발표별
공통 표본과 겹치는 5·20일 정답을 고려한 불확실성을 먼저 계산한다.

가격만 이용한 Ridge 탐색에서는 MAE가 5일 0.003156 대 EWMA 0.002740,
20일 0.003243 대 EWMA 0.001604였다. 이 비교는 **가격 전용 모델의 실패**이고
확률 추가 모형을 평가한 결과가 아니다. 현재 1,253개 가격 행이 있어도
발표 전 확률과 결합 가능한 날짜·독립 발표 수는 아직 확인되지 않았다. 원본
시점·데이터 권리와 신규 독립 평가 기간을 확보하기 전에는 제품 성능 승인이 없다.

다음 구현은 계약 정의와 권리를 확인한 확률 스냅샷을 당시 TLT 가격·금리와
결합해 공통 날짜·발표 수·결측률을 보고하는 일이다. 그다음 A/B/C, 충분한
표본이면 D를 시간순으로 평가한다. 확률 C가 기준선을 반복적으로 개선하고
시점·권리 조건을 만족할 때에만 공개 웹에 예측 변동성, 기준선 대비 오차,
불확실성·실패 국면을 함께 보여준다. 검증과 제품 사용성을 확인한 후 포트폴리오와
주주 인증 채팅을 검토한다.

## 확인 결과와 한계

`make quality PYTHON=.venv/bin/python`에서 Ruff의 저장소 정적 규칙 검사가 모두
통과했고 Pyright는 오류와 경고를 각각 0개 보고했다. `make test
PYTHON=.venv/bin/python`은 가격 스냅샷의 예측시각 선택과 누수 방지,
일별 위험 계산, 기존 CPI 파이프라인을 포함한 계약·단위·통합 테스트
113개를 통과했다. 이번 변경은 목표·흐름·모델 비교 설계 문서를 바로잡은
것으로, 기존 코드의 실행 경로에 회귀가 없다는 수준의 확인이다. 발표 전
확률을 실제 TLT 데이터에 결합하거나 A/B/C/D를 학습한 검증은 이번 테스트에
포함되지 않았으므로 금융 예측 성능을 입증했다고 말할 수 없다.

## 코드 구조와 사용자 점검

이번 정정은 코드·데이터베이스 스키마·API 실행 경로를 수정하지 않았다.
`packages/risk_engine`의 가격 전용 기준선과 `apps/collector`의 Kalshi 연구
수집 경로는 아직 연결되지 않았으며, 실제 연결은 공통 패널을 먼저 만든 뒤 진행한다.

- [ ] 첫 정답이 5·20일 TLT 변동성으로 표시되고 수익률 방향과 혼동되지 않는가?
- [ ] B와 C가 같은 평가 날짜·모형에서 오직 발표 전 확률 입력으로 구분되는가?
- [ ] D와 C가 같은 입력·날짜에서 비교돼 모델 복잡도의 효과를 분리하는가?
- [ ] 아직 결합 실증이 없다는 상태가 README·모델 설명·제품 화면 설계에 드러나는가?
- [ ] 공개 화면은 실증 승인이 없으면 예상 수치 대신 결측·미지원 이유를 보여주는가?
