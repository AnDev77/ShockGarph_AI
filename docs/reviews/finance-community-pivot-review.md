# 금융 위험 화면과 종목 커뮤니티 전환 리뷰

## 결정 배경

2026-10-27 사용자는 금융 예측 결과를 보여주고 종목별 의견을 나누는 서비스를 5일 일정으로 구현하도록 범위를 바꿨다. 기존 제품 목표 문서에서 채팅을 자동 대안으로 출시하지 않던 결정은 이 명시적인 변경 요청으로 갱신한다. 현재 실제 사전 예측은 가격 기반 방법에 한정되며 B 모델의 거시정보 효과와 독립 미래 성능은 검증되지 않았다. 채팅으로 이용자를 모았다는 사실은 모델 성능의 증거가 아니다.

## 저장소 확인과 설계

- ShockGraph의 `apps/api`와 `apps/web`은 아직 운영 코드가 없는 자리표시자다. 따라서 조회 API와 화면을 새로 연결해야 한다.
- doChallenge는 Spring Boot의 HTTP 메시지 저장·조회, WebSocket 전송, 읽음 상태, JWT 로그인 코드를 갖는다. 현재 WebSocket 요청은 사용자가 보낸 `memberId`를 신뢰하고, STOMP 구독 권한 검사도 확인되지 않는다. 이 상태로 공개 금융 채팅에 재사용할 수 없다.
- 첫 버전은 TLT·SPY 가격 기반 사전 위험 결과의 읽기 전용 조회, 로그인된 공개 종목 대화방, 최소 신고·삭제로 한정한다. 보유 인증과 개별 투자 권유는 제외한다.
- 예측값은 원본 감사에 성공한 보관 결과에서만 제공하고, 결과 확인 전·자료 없음·오래됨을 화면에 구분한다. 비공개 가격 원본과 과거 오차 수치는 공개하지 않는다.
- 배포는 GitHub Actions, Docker, Nginx Blue-Green을 대상으로 하며 Jenkins는 운영 가치가 확인된 이후 검토한다. 공유 DB와 장기 WebSocket 연결의 전환 한계를 시험한다.

## 현재 작업량과 한계

이 리뷰 시점에는 두 저장소의 구현 현황과 재사용 경계를 확인하고 5일 계획을 작성했다. 새로운 앱·API·채팅 인증 코드를 완료했다고 주장하지 않는다. 실제 PostgreSQL 운영 연결, 웹 접근성, Nginx 전환, 클라우드 호스트 접근 정보도 확인되지 않았다. 차후 구현 단위별 시험 결과를 별도 기능 리뷰에 기록하고, 미래 정답이 없는 모델 성능은 판단 보류한다.

## 확인 기준

1. WebSocket CONNECT·SEND·SUBSCRIBE에서 인증된 서버 측 신원과 권한을 검사한다.
2. 예측 API가 공개 허용 필드만 반환하고 자료 부재 시 숫자를 만들지 않는다.
3. 두 사용자 채팅과 재접속 누락 메시지 조회가 동작한다.
4. 새 버전 상태 검사 실패 후 Nginx가 기존 정상 버전으로 계속 응답한다.
5. 실제 사용·예측 성능과 합성 시험을 서로 다른 증거로 보고한다.
