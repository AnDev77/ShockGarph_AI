# 지표 API 수집 시각을 반영한 입력 게이트 리뷰

작성일: 2026-10-22. 직전에는 지표의 `available_at`을 예측 시각과 비교했으나,
해당 값이 공급원의 게시 시각이라면 우리 서버의 실제 수신 이전에도 지표가
사용될 수 있었다.

## 이번 변경

`evaluate_traditional_holdout.py`의 기본 입력에 UTC `captured_at` 열을 추가했다.
공급원에서 사용할 수 있게 된 `available_at`보다 수집 시각이 빠르면 거부하고,
실제 특징량의 이용 가능 시각은 더 늦은 `captured_at`으로 취급한다. 기본 CLI는
수집 시각이 없는 이전 5열 CSV를 거부한다. 기존 합성·탐색 연구 재현에만
`--allow-unverified-indicators`를 명시할 수 있다. 결과는 스키마 버전 4에
`indicator_capture_times_supplied`와 `indicator_capture_times_verified=false`를 기록한다.

예를 들어 지표가 20:16 UTC에 게시되고 파일을 20:21 UTC에 수신했다면 20:20
UTC 예측은 그 지표를 사용할 수 없다. 이 시간과 값은 게이트를 검사하는
**시험 시나리오**이며, 실제 공급원 원본 수신 로그의 증거로 제시하지 않는다.

## 실분석의 시작 조건

TLT 현재 수정종가 한 벌에 대한 **실가격 탐색 계산은 이미 수행**했다.
2021~2026년 단일 버전 가격에서 가격만 사용한 EWMA·Ridge·GARCH를 비교한
결과는 [TLT 탐색 리뷰](tlt-exploratory-garch-visual-review.md)에 있다.
그러나 그 파일은 과거 예측 당시 보관한 가격 버전이 아니다.

| 단계 | 시작 시점과 필요한 자료 | 가능한 결과 |
|---|---|---|
| 실가격 기술·탐색 | 현재도 가능. 비공개 TLT 가격 단일 이력은 로컬에 있음 | 과거 가격 변화·사후적 탐색. 시점별 예측 성능이라고 말하지 않음 |
| 새 관측의 A/B 계산 | 적법한 가격·지표 API를 연결해 두 원본의 실제 UTC 수신 로그와 버전을 매일 저장한 시점부터. 과거 빈티지 제공 계약이 있으면 소급 검증 범위를 늘릴 수 있음 | 5·20거래일 후 각 예측의 최초 정답. 초기에 표본 부족으로 점수 보류 가능 |
| 신뢰 가능한 독립 시험 | 시장 국면을 포함하는 충분한 독립 기간, 공급원 이용·표시 권리, 과거 수정가격 빈티지와 실제 공통 날짜를 확보한 뒤 | 사전 고정된 기준선 A 대비 B의 오차·불확실성 평가. 확보 전에는 완료 날짜를 확정할 수 없음 |

수집을 오늘 시작하더라도 **첫 5거래일 정답은 그 이후**, 첫 20거래일 정답은
**20거래일 이후**에만 나온다. 이는 결과 한 건의 최초 확인 가능 시점이지
모델의 통계적 유의성이나 사업용 공개 가능 시점이 아니다. 여러 해의 과거
빈티지를 얻지 못하면 20일 비중첩 표본이 쌓이는 데 더 오래 걸린다.
SPY 실가격 이력과 두 종목 각각의 B 실분석도 아직 없다.

## 검증 결과

`make test PYTHON=.venv/bin/python`의 전체 시험 145개가 통과했다. 신규 단위
시나리오는 API 반영 시각 20:16 UTC, 수집 시각 20:21 UTC인 값을 20:20 UTC
예측에서 제외하고 다음 거래일 예측에서만 쓰는지 검사했다. 통합 시험은 기본
CLI가 수집 시각이 없는 5열 CSV를 거부하고, 6열 CSV를 받아도 보고서에서
`indicator_capture_times_verified=false`와 공개 불가 상태를 유지하는지 확인했다.
`make quality PYTHON=.venv/bin/python`의 Ruff 및 Pyright는 각각 위반 0건,
오류 0건·경고 0건이었다. 시험 데이터의 시각과 가격은 합성이며, 실제 발표·
수신 시각의 진위나 TLT/SPY 모델 성능을 증명하지 않는다.
