# 재무부 금리 공식 응답 실수집과 TLT 날짜 커버리지 리뷰

작성일: 2026-10-22. 앞선 수집 실패를 환경의 네트워크 전체 차단으로 단정했으나,
실제 원인은 Python의 SOCKS 프록시 지원 패키지 누락이었다. 직접 DNS 조회는
실패했지만 `curl`로 공식 월별 URL에 접속해 HTTP 200과 XML 응답을 확인했다.
`uv pip install --python .venv/bin/python socksio`로 현 환경의 수집 경로를
복구했고, 새로 설치하는 환경에서도 재현되도록 `httpx[socks]`를 프로젝트
의존성으로 지정했다. `socksio`는 운영 프록시 경로에서 `httpx`가 응답을 받을
수 있도록 필요한 의존성이다.

## 실제 수집 내역

2026-10 월별 공식 재무부 XML을 두 번 받았다. 첫 수신은 실제 응답을 `curl`로
받아 동일 수집기의 응답·원본 저장 경로에 전달했으며 2026-10-22 02:48:08 UTC에
찍혔다. 두 번째 수신은 기존 `scripts/collect_treasury_rates.py --month 202610`
명령으로 02:48:51 UTC에 이뤄졌다. 두 응답 바이트의 SHA-256은 모두
`57125022700225b6371f68887ac7beceb7cb483bb3b2a4378070c8beb5b95702`였다.
각 응답에는 2026-10-01부터 2026-10-21까지 10년물 금리가 있는 관측일 14개가
들었다. 같은 월의 같은 응답이라도 수신 시각이 다른 두 보관본으로 유지했다.
두 실제 원본 파일은 비공개 `data/raw/`에만 있고 Git에 포함하지 않는다.

`make treasury-coverage PRICE_HISTORY=artifacts/tlt-adjusted-history-private.csv \
TREASURY_RAW_ROOT=data/raw PYTHON=.venv/bin/python`으로 현재 로컬 TLT 이력의
1,253개 세션과 비교했다. TLT 파일은 2026-10-16에서 끝난다. 재무부의 서로
다른 관측 날짜는 14개이고, 수신본을 포함한 관측값은 28개다. TLT와 같은
관측 날짜는 11개지만 실제 첫 수신일 이후의 가격 세션은 **0개**다. 즉 11개를
과거 예측에 사용 가능한 공통 표본으로 읽을 수 없다. 재무부가 10월 초에 이미
그 값을 공개했는지와 별개로, 우리 시스템이 당시 수신해 보관했다는 증거가 없다.
실제 금리와 TLT로 평가한 A/B 오차·불확실성은 여전히 **없다**.

## 검증 결과와 남은 조건

공식 URL의 HEAD와 GET은 HTTP 200이었고 응답 Content-Type은 `text/xml`이었다.
원본 XML이 기존 파서와 불변 저장소를 통과해 금리 14개로 읽혔다. 기존 Python
수집 명령을 SOCKS 지원 설치 뒤 재실행해 동일 SHA-256의 응답을 다시 수신했다.
커버리지 명령은 날짜 겹침 11개와 첫 수신 이후 가격 세션 0개를 분리해 출력했다.
`make quality PYTHON=.venv/bin/python`의 Ruff 위반 0건, Pyright 오류·경고
각 0건이었다. `make test PYTHON=.venv/bin/python`의 전체 153개 시험도 통과했다.
기존 수집기의 합성 XML·변조 검출·수신 시각 시험과 달리 이번 HTTP 200·14개
관측값은 실제 공식 응답에 대한 실행 결과다. 두 검증은 역할이 다르며 실제
모델 성능을 뜻하지 않는다.
