# CPI 시나리오 리스크 분석 제품 전환

검토일: 2026-10-06. 기능 브랜치: `feat/scenario-risk`.

## 이번 작업의 결과

주 화면을 미래 자산 가격 예측에서 시장 내재확률과 과거 시나리오별 ETF 반응의
기술통계로 전환했다. 상회·부합·하회 탭, SPY·TLT 분위수 카드, 자료 모드·표본 수·자료
기간을 구현하고 Brier·CRPS 검증 화면은 `/methodology`로 옮겼다.

합성 데모는 API에서 실제 계산한다. 실제 자료의 분위수를 확보했다고 주장하지 않는다.
기존 CRPS·Brier 집계로는 사건별 수익률 분위수를 복원할 수 없으며,
현재 실제 시나리오 화면은 연결 대기다. 실제 값이 없을 때 데모로 대체하지 않는다.
추가 모델 연구, 실제 Kalshi 수집, 실제 금융 예측 성능 시험은 실행하지 않았다.

## 구현한 코드 구조

- `packages/event_study/shockgraph_analytics/scenarios.py`: 당시 컨센서스·최초 발표값에
  따른 사건 분류와 경험적 역누적분포 분위수. UTC, 시점 가용성, 중복 사건, CPI 격자,
  유한 수익률, 실제 입력의 공개 허가 기록을 검증한다. 기존 다중 임계값·등위회귀 계층을
  재사용한다. 합성 자료는 외부 API나 실측 자료를 사용하지 않는다.
- `apps/api/shockgraph_api/app.py`: `/v1/scenarios/cpi`, `source=demo|actual`, 두 ETF와
  두 반응 구간. 응답은 집계만 포함하며 사건별 수익률·인증 정보를 노출하지 않는다.
- `apps/web/components/dashboard.tsx`: 시나리오 확률 탭, 두 ETF의 P10–P90 범위,
  P25–P75 상자와 P50 세로선, 표본 수·기간. 모두 같은 수익률 축으로 비교한다.
  API 응답의 출처·확률 합·분위수 순서·표본·스냅샷 일치를 검증한다.
- `apps/web/components/research-dashboard.tsx`, `/methodology`: 기존 연구 기록 조회를
  별도 페이지로 분리했다. 기존 엄격한 조건의 연구 집계이며 F3를 선택한 새 모델이 아니다.
- `apps/web/app/api/[...path]/route.ts`: 동일 출처 GET 프록시와 허용 경로 목록,
  응답 캐시 방지, 서버 측 타임아웃. API 주소를 서버 환경변수로 분리한다.
- `apps/web/scripts/export-preview.cjs`: 같은 React 컴포넌트를 API 계산 결과로
  렌더링한 독립 미리보기. 시나리오·구간·데모/실제 상태를 로컬에서 전환한다.
- API·웹 Dockerfile, `compose.demo.yml`, Nginx 로컬 설정, `render.yaml`, 기존 CI의
  컨테이너 검사 작업을 추가했다. Python 런타임은 기존 `uv.lock`의 버전·해시를 사용한다.
- README의 제품 설명·아키텍처·통계 결론과 포트폴리오 설명을 갱신했다.

## 해석 기준과 수학적 범위

상회·부합·하회는 CPI MoM 실제 최초 발표값을 해당 사건의 발표 전 컨센서스와 비교한
구분이다. CPI가 단순히 0.3%보다 높은지와 다르다. 한 자리 소수 CPI와 같은 격자에 있는
컨센서스, 정확한 인접 임계값 계약이 있을 때만 세 확률을 구성한다.

분위수는 시나리오에 속하는 과거 사건 수익률의 경험적 역누적분포에서 계산한다.
P10–P90은 과거 분포의 범위이지 미래 예측구간, 신뢰구간, 손실 한도나 ES가 아니다.
현재의 금리·경기·다른 뉴스까지 일치하는 유사 사건 검색도 아니다.
동일 시나리오라는 공통 조건만으로 묶는다. 인과관계를 주장하지 않는다.

시나리오당 10건은 화면 표시 문턱이며 통계적 충분성이나 꼬리 안정성의 기준이 아니다.
12개 사건의 합성 표본으로 꼬리 위험의 정밀도를 입증하지 않는다.
표본이 작거나 구조가 다른 실제 사건에 대해서는 분포의 불안정성을 별도로 검토해야 한다.

## 확인한 검증 결과

- `make PYTHON=.venv/bin/python quality`: Ruff 통과, Pyright 오류·경고 0개.
- `make PYTHON=.venv/bin/python test`: 164개 통과. 신규 11개는 사건 분류·확률 합,
  경험적 분위수 정의, 소표본 수치 보류, 미래 정보·중복·비유한 값 거절,
  실제 입력 허가·경계 검증, 데모/실제 분리·CORS를 확인했다.
- 기존 Starlette 사용 중단 예정 경고 1개. 신규 코드의 테스트 실패는 아니다.
- 웹 `typecheck`, 프로덕션 `build`, 합성 화면 내보내기 통과.
- 같은 실행 환경에서 FastAPI와 Next.js standalone 서버를 함께 시작해 `/`,
  `/methodology` HTTP 200, 동일 출처 프록시의 SPY·TLT × 5분·30분 응답,
  실제 `pending`·빈 배열, 연결한 기존 CPI 집계 조회를 확인했다.
- Render·Compose·Actions 파일의 YAML 파싱 확인. 공급자 스키마나 실제 배포를
  검증한 것과는 다르다.
- `git diff --check` 통과.

이 검사들은 계산과 데이터 경계·서비스 실행을 확인한다. 합성 시나리오 테스트 11개나
전체 테스트 164개가 실제 자산 예측 성과를 뜻하지 않는다.

## 확인하지 못한 항목

현재 실행 환경에 Docker·Nginx 실행 파일이 없어 컨테이너 빌드·Nginx 런타임 검사는
수행하지 못했다. 컨테이너 CI는 설정했으며 원격 실행 결과는 별도로 확인해야 한다.
클라우드 프로젝트 연결·공개 URL·SSL·실제 DB 연결·운영 배포는 수행하지 않았다.

브라우저 실행 파일이 없고 설치 다운로드가 정상 파일을 반환하지 않아 실브라우저의
클릭·키보드 동작·모바일 픽셀 검사는 수행하지 못했다. React 출력으로 만든 미리보기와
타입·빌드·HTTP 검증을 제공하지만 실브라우저 검증을 대신했다고 주장하지 않는다.

## 사용자 점검표

1. 미리보기에서 상회·부합·하회와 5분·30분을 바꾸고 ETF 범위·기간·표본 수가
   선택한 시나리오에 맞게 바뀌는지 확인한다.
2. 합성 출처가 화면 상단·각 자산 카드에 표시되는지 확인한다.
3. 실제 데이터로 전환했을 때 데모 숫자가 남지 않고 연결 대기가 표시되는지 확인한다.
4. 실제 사건별 원본·당시 컨센서스·이용권 없이는 실측 분위수 서비스가 완성된 것으로
   소개하지 않는다. `publication_authorized` 값 자체가 이용권을 만들지는 않는다.
5. 이력서의 정합성 100%·완전 차단·자산 예측 유의성 입증 표현을 사용하지 않는다.
6. 공개 배포는 [배포 안내](../scenario-demo-deployment.md)의 계정 연결·URL 점검을
   끝낸 뒤 완료로 기록한다. 처음에는 합성 데모를 공개한다.
