# Kalshi 계약 기대 맥락 분리 리뷰

개정일: 2026-10-20. 제품 목표의 순서를 정정한 문서 변경이다. 실제 Kalshi
서비스 화면, A/B 실자료 학습기 또는 승인된 예측 결과를 구현했다는 뜻은 아니다.

## 결정과 경계

첫 제품의 TLT 5·20거래일 변동성은 가격 기준선 A와 전통 시장 정보 모델 B를
실제 이용 가능 시점과 같은 날짜에서 검증한다. Kalshi는 **그 시각에 특정 계약의
참가자가 계약 가격에 반영한 기대**를 설명하는 별도 사건 자료다. 가격 하나를
전체 시장의 합의, CPI 결과의 전체 분포, TLT 변동성의 예측 원인이나 매매
신호로 해석하지 않는다. 위험 결과가 검증되지 않아도 권리와 사건 리포트의
사용자 효용이 확인되면 당시 기대를 사후 발표치·ETF 관측과 구분해 보여줄 수 있다.

첫 제품의 모델 입력에는 Kalshi 계약 확률이 없다. 이미 구현된
`packages/risk_engine/shockgraph_risk/macro_panel.py`의 합성 확률 결합 경로와
기존 CPI 계약 적중률 감사는 연구 이력으로 보존한다. 현재 C 모형의 실자료
학습·평가는 없으며, 이번 정정으로 이를 구현하거나 출시 일정에 넣지 않는다.
후일 별도 연구를 시작하면 새 독립 표본과 사전 고정한 C/B 비교가 필요하다.

## 사건 화면과 자료 계약

| 항목 | 표시·검증 규칙 |
|---|---|
| 계약 범위 | 계약 식별자, 질문 원문, 결과 임계값·단위·만기와 버전을 함께 보여준다. 단일 `T0.3`을 CPI 전체 분포라고 쓰지 않는다. |
| 당시 기대 | 계약의 가격 또는 해당 가격으로 해석한 확률을 **그 계약에 대한 당시 값**으로 표시한다. 가격과 추정 확률의 차이, 수수료·호가 측면 등 계산 정의를 명시한다. |
| 시간 | `observed_at`, `available_at`, `captured_at`, 발표 `release_at`을 보존한다. 기대 화면은 발표 전 이용 가능한 스냅샷만 사용하고 이후 정산값을 당시 값으로 바꾸지 않는다. |
| 호가 품질 | 최근 거래·거래량·매수/매도 호가 폭·지연과 결측을 확인한다. 품질이 부족하면 수치를 보류하거나 제한을 붙인다. |
| 출처·권리 | 원본 해시와 출처를 보존하고 공개 재표시·파생 설명의 허용 범위를 확인한다. 권리가 확인되지 않은 원문·호가를 화면에 싣지 않는다. |
| 위험 전망과의 관계 | 사건 설명은 `GET /v1/risk/events`의 후보 계약으로 분리한다. A/B 전망의 입력 근거·성과로 표시하지 않는다. API는 아직 미구현이다. |

## 바뀐 구조

- `AGENTS.md`, 제품 명세, README와 일별 위험·모델 방법론에서 A/B의 실자료
  독립 평가를 다음 우선순위로 고정했다.
- 프로젝트 흐름도와 프로그램 아키텍처에서 Kalshi 계약 설명을 사건·리포트
  경로에 연결하고, 확률 결합 C를 점선의 별도 연구로 표시했다.
- 제품 결정표와 화면 설계에서 A/B 성과에 따라 위험 수치를 승인하고, 계약
  정의·시각·권리가 맞는 사건 맥락은 별도로 판단한다.
- 기존 연구 코드, 검증 결과, 일차별 리뷰는 이력대로 보존했다. 문서만 바뀌므로
  실자료 A/B 성능이나 사건 리포트 효용을 새로 증명하지 않는다.

## 검증 결과

`make quality PYTHON=.venv/bin/python`으로 Ruff 검사와 Pyright 검사를 실행했고,
각각 모든 규칙 통과 및 오류 0건·경고 0건으로 끝났다. `make test
PYTHON=.venv/bin/python`은 수집·계약·시점 검증·위험 기준선 관련 기존 시험을
포함해 120개를 모두 통과했다. 변경된 11개 문서의 상대경로 링크 66개를 검사한
결과 누락은 0개였고, `git diff --check`도 공백 오류 0건이었다. 이 검사는
문서 정정이 기존 Python 동작을 깨지 않았는지 확인한 결과이며, 아직 없는 공개
화면이나 A/B의 실자료 예측 성능을 증명하지 않는다. Kalshi의 외부 데이터
재표시 권리와 실제 호가 품질은 별도 공급원 검토가 필요하므로 이 리뷰로
승인하지 않는다.
