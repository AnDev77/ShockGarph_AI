# ShockGraph AI 제품·화면 설계 방향

상태: 2026-10-19 일별 위험 제품 설계. 실제 웹·앱과 실자료 위험 모델은 미구현.

## 핵심 질문과 첫 화면

“오늘 유가·금리·변동성의 변화가 내가 보는 ETF 위험에 어떤 영향을 줄까?”

로그인 없이 첫 화면에서 검증된 최신 위험 스냅샷을 읽는다. 첫 지원 후보는 TLT이고, SPY·XLE는 데이터와 모델 검증 후 선택지에 추가한다. `configs/assets.yaml`의 후보 목록이 제품 지원 목록은 아니다. 홈은 날짜별 CPI 발표 일정 대신 **자산 위험 상태, 기준시각, 관련 시장 지표**를 중심에 둔다.

| 사용 흐름 | 목표 화면과 상태 |
|---|---|
| 1. 관심 ETF 선택 | 지원 중인 종목·기간만 활성화하고 미지원 사유 표시 |
| 2. 5·20거래일 선택 | 예상 변동성, 과거 기준선과의 차이, 하방 범위가 검증됐을 때만 표시 |
| 3. 근거 확인 | 브렌트·금리·VIX의 당시 값과 모델 기여, 국면별 실패 사례 확인 |
| 4. 내 구성 | 자산·비중을 입력하면 같은 시점의 공동 위험 스냅샷으로 계산. 결측 종목은 숨기지 않음 |
| 5. 발표일 살펴보기 | CPI/FOMC가 있는 날에만 보조 이벤트 해석을 노출. Kalshi 정산 적중률과 ETF 위험 성능을 구별 |

## 결과 카드 계약

- 제목: “TLT, 향후 5거래일 위험”처럼 자산·기간·측정 대상을 먼저 적는다.
- 주 숫자: 검증된 미래 실현 변동성 추정치. 상승확률이나 목표주가처럼 표현하지 않는다.
- 하방 손실 구간: 별도 꼬리 검증을 통과한 뒤에만 표시하고 추정의 불확실성과 미래 손실 범위를 구분한다.
- 근거: `as_of`, 입력 자료의 마지막 이용 가능 시각, 모델 버전, 학습·시험 기간, 기준선 대비 성능, 결측·지연 상태.
- 상태: `ready`, `experimental`, `insufficient_data`, `stale`, `unsupported`, `pending`, `error`. 합성 자료만 있으면 `DEMO`를 추가한다.
- 포트폴리오: 자산별 위험의 가중합으로 공동 위험을 대신하지 않는다. 통화, 비중 합계, 동시 관측 기간이 맞지 않으면 계산을 중단한다.

첫 화면은 큰 수치 하나와 “무엇이 변했나”를 설명하는 짧은 문장으로 시작한다. 기여도·백테스트·자료 출처는 펼치기에서 보여준다. 시계열 변동을 인과관계로 표기하지 않는다.

## 공개 분석과 후속 커뮤니티

공개 분석은 가입 없이 볼 수 있게 한다. 사용자가 로그인하면 관심 종목을 저장할 수 있다. 종목 토론방은 제품 사용성·데이터 권리를 확인한 뒤 추가하며, **해당 종목 보유 인증이 유효한 경우에만** 방의 기록·실시간 구독·글쓰기를 허용한다. 화면에는 마지막 보유 확인 시각과 만료 여부를 함께 표시한다. 캡처 제출이나 수동 입력으로 `인증 주주` 표시를 하지 않는다. 상세 흐름은 [주주 인증 채팅 설계](shareholder-community-roadmap.md)를 따른다.

토론방 내용과 모델의 검증된 숫자는 시각적으로 분리한다. 모델 결과에서 방으로 이동한 뒤에도 타인의 주장이나 메시지를 공식 분석 근거처럼 보이게 하지 않는다. 신고·차단·운영자 조치, 보유 검증 취소와 재확인 UI를 출시 전에 마련한다.

## API와 화면 책임

향후 API 계약 후보:

- `GET /v1/risk/assets`: 분석 가능 종목·기간·지원 상태.
- `GET /v1/risk/assets/{instrument_id}?horizon=5`: 기준시각·모델·성과·상태가 포함된 검증 스냅샷.
- `POST /v1/risk/portfolios/evaluate`: 입력 비중의 공동 위험 계산. 로그인 없는 첫 버전은 저장하지 않는다.
- `GET /v1/risk/events`: 검증된 경우에만 보조 이벤트 설명.
- 후속 커뮤니티의 인증·방·메시지 API는 별도 권한 계약 후 설계한다.

FastAPI는 스냅샷에서 검증된 숫자만 반환한다. Next.js는 계산을 새로 하지 않고 상태와 근거를 표시한다. 같은 화면의 카드들이 서로 다른 날짜·모델 버전이면 함께 비교하지 않는다. 요청 변경 시 이전 응답이 뒤늦게 새 결과를 덮지 않도록 한다.

## 디자인·점검

Next.js + Chakra UI v3 모바일 우선 카드형 화면을 목표로 한다. 밝은 배경 `#F6F7FB`, 흰 표면 `#FFFFFF`, 본문 `#182033`, 브랜드 강조 `#5848D5`를 출발점으로 삼는다. 어두운 테마와 360px 폭, 키보드/터치, 낮은 대비, 로딩 및 데이터 부재 상태를 검증한다. 상승·하락 색상만으로 위험 상태를 전달하지 않는다.

- [ ] 로그인 없이 검증된 분석 또는 정확한 미지원 상태를 볼 수 있다.
- [ ] 기간과 기준시각, 데이터의 실제 최신 시각이 표시된다.
- [ ] 기준선 대비 성능이 없는 실험 모델을 `ready`로 노출하지 않는다.
- [ ] 실자료와 합성 데모를 명확히 구분한다.
- [ ] 포트폴리오 결측·만료·통화 차이를 숨기지 않는다.
- [ ] 종목방의 구독·글쓰기·이전 메시지 조회 모두 보유 권한을 확인한다.
