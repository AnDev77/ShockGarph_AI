# ShockGraph AI 제품·화면 설계 방향

상태: 2026-10-21 SPY·TLT 개별 카드와 TLT A/B 연구의 분리 설계. 실제 웹·앱과 SPY 실자료는 미구현.

## 핵심 질문과 첫 화면

“SPY와 TLT 각각 최근에 얼마나 움직였고 위험 상태는 어떤가?”

로그인 없이 첫 화면에서 출처와 기준시각이 있는 **종목별 카드**를 본다.
SPY와 TLT 각각 최근 5·20·60일 가격 변화율, 최근 관측 변동성이 자기
과거 이력에서 차지하는 위치, 기간 내 최대 하락 폭과 관련 사건을 표시한다.
종목마다 데이터 최신 시각·배당 조정 기준·결측을 독립적으로 표시한다.
사용자가 비중을 입력할 때만 동일 시작·종료일의 **기간 총변동률**을
`w × SPY 기간 변화율 + (1−w) × TLT 기간 변화율`로 계산한다. 최초
비중으로 보유하고 중간 재조정·현금 유입이 없었다는 가정이다. 자산별
변동성의 가중합을 포트폴리오 위험으로 제시하지 않는다.
SPY의 실제 가격과 외부 표시 권리는 아직 확보되지 않았으므로 이 화면은
현재 설계이지 구현 완료가 아니다. QQQ·XLE는 별도 확장이다.
모형별 성능이 승인되면 **TLT 변동성 전망·선택된 A/B 모형과 검증 결과**를
보여준다. TLT 예측 연구가 승인되지 않아도 SPY·TLT 개별 관측의
사용자 효용은 따로 시험한다. Kalshi의 기대 정보는 해당 계약의 정의·임계값·확률·시각·출처를
별도 사건 카드에 표시한다. 한 계약을 CPI 전체 결과 분포나 전체 시장의 합의로
표현하지 않는다. 수치 검증 전에는
예측 수치 대신 **SPY·TLT 각각의 출처 있는 과거 관측**과, 별도 검증된 경우
**발표 전 기대·최초 발표 결과·SPY/TLT·금리 관측의 자동 연결**을 보여준다. 데이터가
없다면 자료 부족 이유를 명시한다. 기록 입력 상자나 일정만 있는 화면은
제품 가치가 입증된 것으로 간주하지 않는다.

| 사용 흐름 | 목표 화면과 상태 |
|---|---|
| 1. 종목 선택 | SPY 또는 TLT의 최근 가격 변화·관측 위험과 개별 자료 최신 시각, 결측 표시 |
| 2. 근거 확인 | 선택한 종목의 5·20·60일 변화, 변동성의 과거 위치·하락 폭·사건과 표본 수 |
| 3. 선택적 합산 | 같은 기간 두 종목의 총변동률을 최초 입력 비중으로 합산. 재조정이나 미래 예측으로 표현하지 않음 |
| 4. 연구 결과 | 5·20일 전망이 승인된 자산에만 예상 변동성·오차·모델 버전 표시. 현재 TLT 승인 없음 |
| 5. 발표일 살펴보기 | 권리가 확인된 사건의 당시 기대·최초 발표·SPY/TLT 사후 관측을 시각과 출처로 연결 |

첫 화면의 재방문 가설은 ‘관심 종목 하나의 최근 변화와 관측 위험을
1분 안에 이해한다’이다. 같은 정보가 이미 있는 ETF 시세·히트맵
화면과 비교해 과제 완료 시간, 해석 오류, 일주일 뒤 재방문을 측정한다.
기존 도구보다 효용이 없다면 차별 기능을 다시 정의한다.

## 예측 결과가 약할 때의 화면

종목별 관측 화면의 사용성을 먼저 시험한다. 사건 리포트는 한 사건을
시범 생성한다. 왼쪽에는 `발표 전에 실제 이용할
수 있던 기대·확률·시각`, 가운데에는 `최초 발표값`, 오른쪽에는 관측 시작·
종료 시각을 적은 `SPY·TLT·금리 움직임`을 보여준다. 과거 유사 사건을 같은 정의로
비교할 수 있으면 표본 수·분포·제외 사유를 표시한다. 이는 단일 사건의
인과효과나 미래 수익률의 증거가 아니다. 위험 전망에는 Kalshi 확률을 모델
입력처럼 붙이지 않는다. B가 독립 시험에서 A를 개선했다면 B 전망을, B가
개선하지 못했지만 A의 오차·안정성·
시점·권리를 확인했다면 A 기준 정보를 **해당 근거와 한계**를 붙여 시험한다.
어느 수치도 신뢰할 수 없으면 전망 카드를 숨기고 출처 있는 과거 관측만 표시한다.

이 리포트가 FRED/CME/Koyfin과 Notion을 오가며 수동으로 조사하는 작업보다
빠르고 오류가 적은지 사용자 과제로 비교한다. 그 결과가 확인되기 전에는
투자 기록 편집기를 제품의 필수 화면으로 넣지 않는다. 종목별 공개 채팅은
별도 작은 MVP로 병행하며 분석 성과로 취급하지 않는다.
허가되지 않은 시세·호가 원문도 공개하지 않는다. [성과별 제품 결정](product-goal-and-fallback.md)을 따른다.

## 결과 카드 계약

- 제목: “TLT, 향후 5거래일 위험”처럼 자산·기간·측정 대상을 먼저 적는다.
- 주 숫자: 검증된 미래 실현 변동성 추정치. 상승확률이나 목표주가처럼 표현하지 않는다.
- 하방 손실 구간: 별도 꼬리 검증을 통과한 뒤에만 표시하고 추정의 불확실성과 미래 손실 범위를 구분한다.
- 근거: `as_of`, 선택된 모형 A/B와 해당 입력의 관측·수신 시각, 모델 버전, 공통 학습·시험 기간과 비중첩 구간 수, A/B의 같은 날짜 비교 또는 A의 절대 오차·불확실성, 결측·지연 상태. 발표 일정은 해당 시각에 알려진 경우에만 입력으로 표시한다.
- 상태: `ready`, `experimental`, `insufficient_data`, `stale`, `unsupported`, `pending`, `error`. 합성 자료만 있으면 `DEMO`를 추가한다.
- 선택적 총변동률: 기간·통화·조정 기준이 맞는 두 종목의 **기간 변화율**만 초기 비중으로 합산한다. 공동 위험·미래 손실 범위로 표시하지 않는다.

첫 화면은 검증된 경우 선택된 모형의 추정치와 “어떤 정보로 계산했나”를 설명하는 짧은 문장으로 시작한다. A는 가격 기반 기준 정보, B는 전통 정보 기반으로 표시한다. 기여도·백테스트·자료 출처는 펼치기에서 보여준다. 별도 사건 카드에는 “Kalshi의 CPI 0.3% 초과 계약: 당시 계약에 반영된 확률 61%(예시), 관측 시각 …”처럼 **실제 계약 문구와 시각을 기준으로** 표시한다. 예시의 61%를 실제 관측값으로 쓰지 않는다. 지연·얕은 거래량·넓은 스프레드는 표시하거나 해당 값을 보류한다. 확률과 TLT 위험의 인과관계나 검증된 예측 기여를 암시하지 않는다.

## 공개 분석과 초기 채팅

공개 가능한 사건 분석 리포트·검증된 위험 정보는 가입 없이 볼 수 있게 한다.
SPY·TLT 각 종목 카드에 연결된 공개 채팅방은 작은 MVP로 병행한다.
첫 범위는 공개 읽기, 로그인 쓰기, 영속 메시지·커서 페이징, WebSocket 전송,
신고·차단·삭제와 기본 전송 제한이다. 방은 `SPY`, `TLT` 또는 특정 분석
카드에 연결하고 공식 데이터와 이용자 의견을 분리한다. 이 방은 **주주 인증
종목방이 아니며** 인증 주주로 표시되지 않는다. 향후 종목방은
제품 사용성·데이터 권리를 확인한 뒤 추가하며, **해당 종목 보유 인증이 유효한
경우에만** 방의 기록·실시간 구독·글쓰기를 허용한다. 화면에는 마지막 보유
확인 시각과 만료 여부를 함께 표시한다. 캡처 제출이나 수동 입력으로 `인증 주주`
표시를 하지 않는다. 상세 흐름은 [주주 인증 채팅 설계](shareholder-community-roadmap.md)를 따른다.

토론방 내용과 모델의 검증된 숫자는 시각적으로 분리한다. 모델 결과에서 방으로 이동한 뒤에도 타인의 주장이나 메시지를 공식 분석 근거처럼 보이게 하지 않는다. 공개 채팅의 신고·차단·운영자 조치를 처음부터 넣고, 후속 보유 인증 방에는 취소와 재확인 UI를 별도로 마련한다.

## API와 화면 책임

향후 API 계약 후보:

- `GET /v1/market/assets/{symbol}?window=60`: 각 종목의 변화율·관측 변동성·과거 위치·출처·결측 상태. 현재 미구현.
- `POST /v1/market/total-change`: 같은 기간의 개별 총변동률과 초기 비중을 합산. 재조정·공동 위험과 구별하며 현재 미구현.
- `GET /v1/risk/assets`: 분석 가능 종목·기간·지원 상태.
- `GET /v1/risk/assets/{instrument_id}?horizon=5`: 기준시각·모델·성과·상태가 포함된 검증 스냅샷.
- `POST /v1/risk/portfolios/evaluate`: 입력 비중의 공동 위험 계산. 로그인 없는 첫 버전은 저장하지 않는다.
- `GET /v1/risk/events`: 발표 일정과 권리가 확인된 계약별 당시 확률·질문·임계값·관측/이용 가능 시각·거래량/스프레드·상태를 사건 맥락으로 반환. 계약 정산 결과와 구분하고 위험 전망의 입력 근거라고 표시하지 않음.
- 사건·자산 리포트 읽기 API: 허가된 자료의 관측·공개 시각, 최초 발표값, 고정 관측 구간과 과거 비교 결과. 평가 프로토타입 이후 설계.
- `GET /v1/chat/rooms/{room_id}/messages?before=...`: 공개 방의 메시지 커서 조회. 현재 미구현.
- `WS /v1/chat/rooms/{room_id}`: 로그인 신원 확인과 방 권한 검사 뒤 실시간 전송. 현재 미구현.
- `POST /v1/chat/reports`: 메시지 신고 및 운영 처리 경로. 현재 미구현.
- 후속 커뮤니티의 인증·방·메시지 API는 별도 권한 계약 후 설계한다.

FastAPI는 스냅샷에서 검증된 숫자만 반환한다. Next.js는 계산을 새로 하지 않고 상태와 근거를 표시한다. 같은 화면의 카드들이 서로 다른 날짜·모델 버전이면 함께 비교하지 않는다. 요청 변경 시 이전 응답이 뒤늦게 새 결과를 덮지 않도록 한다.

## 디자인·점검

Next.js + Chakra UI v3 모바일 우선 카드형 화면을 목표로 한다. 밝은 배경 `#F6F7FB`, 흰 표면 `#FFFFFF`, 본문 `#182033`, 브랜드 강조 `#5848D5`를 출발점으로 삼는다. 어두운 테마와 360px 폭, 키보드/터치, 낮은 대비, 로딩 및 데이터 부재 상태를 검증한다. 상승·하락 색상만으로 위험 상태를 전달하지 않는다.

- [ ] 로그인 없이 검증된 분석 또는 정확한 미지원 상태를 볼 수 있다.
- [ ] 기간과 기준시각, 데이터의 실제 최신 시각이 표시된다.
- [ ] 기준선 대비 성능이 없는 실험 모델을 `ready`로 노출하지 않는다.
- [ ] 실자료와 합성 데모를 명확히 구분한다.
- [ ] 포트폴리오 결측·만료·통화 차이를 숨기지 않는다.
- [ ] 종목방의 구독·글쓰기·이전 메시지 조회 모두 보유 권한을 확인한다.
