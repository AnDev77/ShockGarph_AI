# ShockGraph AI 제품·화면 설계 방향

상태: 2026-10-20 발표 전 거시 확률을 포함한 TLT 변동성 검증과 성과별 제품 경로 설계. 실제 웹·앱과 실자료 확률 결합 모델은 미구현.

## 핵심 질문과 첫 화면

“다가올 거시 발표에 대해 시장이 생각하는 확률까지 보면 내 ETF의 향후 변동성 위험을 더 잘 알 수 있을까?”

로그인 없이 첫 화면에서 출처와 기준시각이 있는 **자동 사건·자산 분석 리포트**를 읽는다.
첫 지원 후보는 TLT이고, SPY·XLE는 데이터와 모델·사용성을 검증한 뒤
선택지에 추가한다. `configs/assets.yaml`의 후보 목록이 제품 지원 목록은 아니다.
예측 성능이 승인되면 **TLT 변동성 전망·당시 거시 확률·기준선 대비 검증 결과**를
같이 보여준다. 승인 전에는 예측 수치 대신 **발표 전 기대·최초 발표 결과·
TLT/금리 관측의 자동 연결·과거 비교**가 가능한 경우에만 보여준다. 데이터가
없다면 자료 부족 이유를 명시한다. 기록 입력 상자나 일정만 있는 화면은
제품 가치가 입증된 것으로 간주하지 않는다.

| 사용 흐름 | 목표 화면과 상태 |
|---|---|
| 1. 관심 ETF 선택 | 지원 중인 종목·기간만 활성화하고 미지원 사유 표시 |
| 2. 5·20거래일 선택 | 예상 변동성, 과거 기준선과의 차이, 하방 범위가 검증됐을 때만 표시 |
| 3. 근거 확인 | 발표 전 거시 결과 확률·금리·VIX의 당시 값, 자료 시점·확률 추가 전후의 오차·실패 사례 확인 |
| 4. 내 구성 | 자산·비중을 입력하면 같은 시점의 공동 위험 스냅샷으로 계산. 결측 종목은 숨기지 않음 |
| 5. 발표일 살펴보기 | 해당 발표의 결과별 당시 확률·호가 시점과 이후 실제 발표를 구별. Kalshi 계약 적중률과 TLT 위험 예측 성능을 구별 |

## 예측 결과가 약할 때의 화면

먼저 한 사건의 과거 리포트를 시범 생성한다. 왼쪽에는 `발표 전에 실제 이용할
수 있던 기대·확률·시각`, 가운데에는 `최초 발표값`, 오른쪽에는 관측 시작·
종료 시각을 적은 `TLT·금리 움직임`을 보여준다. 과거 유사 사건을 같은 정의로
비교할 수 있으면 표본 수·분포·제외 사유를 표시한다. 이는 단일 사건의
인과효과나 미래 수익률의 증거가 아니다. C의 증분 성능이 없거나 불확실하면
수치 예측 카드와 ‘확률로 더 잘 맞혔다’는 문구를 내보내지 않는다.

이 리포트가 FRED/CME/Koyfin과 Notion을 오가며 수동으로 조사하는 작업보다
빠르고 오류가 적은지 사용자 과제로 비교한다. 그 결과가 확인되기 전에는
로그인·판단 기록 편집기·댓글·실시간 채팅을 제품의 필수 화면으로 넣지 않는다.
허가되지 않은 시세·호가 원문도 공개하지 않는다. [성과별 제품 결정](product-goal-and-fallback.md)을 따른다.

## 결과 카드 계약

- 제목: “TLT, 향후 5거래일 위험”처럼 자산·기간·측정 대상을 먼저 적는다.
- 주 숫자: 검증된 미래 실현 변동성 추정치. 상승확률이나 목표주가처럼 표현하지 않는다.
- 하방 손실 구간: 별도 꼬리 검증을 통과한 뒤에만 표시하고 추정의 불확실성과 미래 손실 범위를 구분한다.
- 근거: `as_of`, 확률 관측·수신 시각과 발표 시각, 모델 버전, 공통 학습·시험 기간과 발표 수, 최근 변동성/EWMA·전통 정보 대비 오차 및 불확실성, 결측·지연 상태. 가격·전통 정보 모형 B와 확률 추가 모형 C를 같은 날짜로 비교한다.
- 상태: `ready`, `experimental`, `insufficient_data`, `stale`, `unsupported`, `pending`, `error`. 합성 자료만 있으면 `DEMO`를 추가한다.
- 포트폴리오: 자산별 위험의 가중합으로 공동 위험을 대신하지 않는다. 통화, 비중 합계, 동시 관측 기간이 맞지 않으면 계산을 중단한다.

첫 화면은 검증된 경우 큰 수치 하나와 “당시 어떤 확률·시장 상태가 관측됐나”를 설명하는 짧은 문장으로 시작한다. 기여도·백테스트·자료 출처는 펼치기에서 보여준다. 확률의 증가나 시계열 변동을 인과관계로 표기하지 않는다. C가 개선되지 않거나 검증 표본이 부족하면 ‘확률로 더 잘 맞힌다’는 문구를 표시하지 않는다.

## 공개 분석과 후속 커뮤니티

공개 가능한 사건 분석 리포트·검증된 예측은 가입 없이 볼 수 있게 한다.
외부 사용자 시험에서 실제 토론 요구가 확인되면 로그인 사용자의 리포트별
비동기 의견을 별도 설계한다. 이 의견은 **주주 인증 종목방이 아니며**
인증 주주로 표시되지 않는다. 향후 종목방은
제품 사용성·데이터 권리를 확인한 뒤 추가하며, **해당 종목 보유 인증이 유효한
경우에만** 방의 기록·실시간 구독·글쓰기를 허용한다. 화면에는 마지막 보유
확인 시각과 만료 여부를 함께 표시한다. 캡처 제출이나 수동 입력으로 `인증 주주`
표시를 하지 않는다. 상세 흐름은 [주주 인증 채팅 설계](shareholder-community-roadmap.md)를 따른다.

토론방 내용과 모델의 검증된 숫자는 시각적으로 분리한다. 모델 결과에서 방으로 이동한 뒤에도 타인의 주장이나 메시지를 공식 분석 근거처럼 보이게 하지 않는다. 신고·차단·운영자 조치, 보유 검증 취소와 재확인 UI를 출시 전에 마련한다.

## API와 화면 책임

향후 API 계약 후보:

- `GET /v1/risk/assets`: 분석 가능 종목·기간·지원 상태.
- `GET /v1/risk/assets/{instrument_id}?horizon=5`: 기준시각·모델·성과·상태가 포함된 검증 스냅샷.
- `POST /v1/risk/portfolios/evaluate`: 입력 비중의 공동 위험 계산. 로그인 없는 첫 버전은 저장하지 않는다.
- `GET /v1/risk/events`: 발표 일정과 이용 가능한 당시 거시 확률의 시점·상태, 검증된 경우에만 위험 전망의 입력 근거. 계약 정산 결과와 구분.
- 사건·자산 리포트 읽기 API: 허가된 자료의 관측·공개 시각, 최초 발표값, 고정 관측 구간과 과거 비교 결과. 평가 프로토타입 이후 설계.
- 리포트별 글/댓글·신고 API: 실제 토론 수요가 있을 때 공개 읽기, 로그인 쓰기와 시각·출처·수정 이력을 조건으로 별도 설계. 현재 미구현.
- 후속 커뮤니티의 인증·방·메시지 API는 별도 권한 계약 후 설계한다.

FastAPI는 스냅샷에서 검증된 숫자만 반환한다. Next.js는 계산을 새로 하지 않고 상태와 근거를 표시한다. 같은 화면의 카드들이 서로 다른 날짜·모델 버전이면 함께 비교하지 않는다. 요청 변경 시 이전 응답이 뒤늦게 새 결과를 덮지 않도록 한다.

## 디자인·점검

Next.js + Chakra UI v3 모바일 우선 카드형 화면을 목표로 한다. 밝은 배경 `#F6F7FB`, 흰 표면 `#FFFFFF`, 본문 `#182033`, 브랜드 강조 `#5848D5`를 출발점으로 삼는다. 어두운 테마와 360px 폭, 키보드/터치, 낮은 대비, 로딩 및 데이터 부재 상태를 검증한다. 상승·하락 색상만으로 위험 상태를 전달하지 않는다.

- [ ] 로그인 없이 검증된 분석 또는 정확한 미지원 상태를 볼 수 있다.
- [ ] 기간과 기준시각, 데이터의 실제 최신 시각이 표시된다.
- [ ] 기준선 대비 성능이 없는 실험 모델을 `ready`로 노출하지 않는다.
- [ ] 실자료와 합성 데모를 명확히 구분한다.
- [ ] 포트폴리오 결측·만료·통화 차이를 숨기지 않는다.
- [ ] 종목방의 구독·글쓰기·이전 메시지 조회 모두 보유 권한을 확인한다.
