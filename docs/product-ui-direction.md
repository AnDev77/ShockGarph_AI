# ShockGraph AI 제품·화면 설계 방향

작성일: 2026-09-22. 상태: 다음 UI 구현을 위한 설계, 실제 Next.js/Chakra UI 앱은 구현 전.

## 1. 핵심 결정: 지원 범위 안에서 사용자가 선택한다

사용자가 종목, 이벤트, 분석 기간을 선택하고 해당 조합에서 검증된 분석 결과를 본다.
모델 적용 범위와 사용자 선택은 함께 필요하다.

`configs/assets.yaml`에는 SPY, QQQ, TLT, HYG, GLD, UUP, XLE 등이 후보로 정의되어 있다.
이 목록은 학습 완료 목록이 아니다. 국내 ETF 항목도 실제 종목 코드가 아닌 슬롯이 포함되어 있다.
현재 학습 완료된 종목 예측 모델과 화면은 없다.

| 사용자 조작 | 목표 동작 |
|---|---|
| 종목 선택 | 해당 종목·이벤트·기간의 지원 상태를 조회한다. |
| 이벤트 선택 | CPI, FOMC 등 선택한 사건에 조건부인 결과를 표시한다. |
| 기간 변경 | 지원되는 거래일 분석 기간만 활성화한다. |
| 비중 입력 | 지원 자산의 시나리오 공동수익률로 포트폴리오 영향을 계산한다. |
| 미지원 종목 입력 | 분석 준비 중과 이유를 표시하고 수치를 생성하지 않는다. |
| 새로고침 | 기존 스냅샷 또는 새 검증 결과를 조회한다. 사용자 요청마다 재학습하지 않는다. |

지원 여부는 향후 `(asset_id, event_category, horizon, currency, model_version)` 단위로 관리한다.
추천 모델 구조는 이벤트 확률 보정 + 자산별 조건부 반응 + 포트폴리오 위험 계산이다.
모든 종목마다 독립적인 딥러닝 모델을 하나씩 학습하는 구조로 고정할 필요는 없다.

## 2. 사용자가 얻는 가치

제품의 첫 질문은 **“이번 경제 뉴스가 내 관심 종목에 어떤 영향을 줄까?”**다.
첫 화면에서 사건 하나를 고르고 관심 자산을 선택해 확률·영향·근거를 빠르게 읽게 한다.

핵심 사용 흐름:

1. 오늘의 이벤트 카드에서 CPI 또는 FOMC 선택
2. 지원 자산 중 관심 종목 선택
3. 발표 후 1/5/20거래일 중 지원 기간 선택
4. 확률·예상 수익률·불확실성을 확인
5. 왜 이런 결과인지 과거 사례와 가정 확인

첫 MVP는 로그인 없는 체험으로 시작한다. 관심 자산은 브라우저 로컬 저장을 사용할 수 있고
삭제 기능을 제공한다. 계정 동기화와 실제 자산 계좌 연결은 기존 MVP 범위 밖이다.

## 3. 결과 카드의 정보 구조

| 표시 요소 | 의미 | 주의할 구분 |
|---|---|---|
| 이벤트 확률 | CPI 구간/금리결정 등 사건 발생확률 | 자산 상승확률과 별도 표시 |
| 자산 상승확률 | 지정 기간 수익률이 0보다 클 추정확률 | 기간·통화·대상 종목 명시 |
| 기대수익률 | 동일 기간 수익률 평균 추정 | 최빈값·목표주가와 다름 |
| 95% 추정 신뢰구간 | 평균 또는 확률 추정의 불확실성 | 미래 수익률 예측구간과 다름 |
| 독립 이벤트 수 | 근거가 된 독립 사건의 수 | 스냅샷 행 수와 구분 |
| 기준시각 | 분석에 사용한 정보의 시점 | 현재 시각과 다를 수 있음 |
| 근거 보기 | 가정, 모델, 표본, 유사 사례 | 검증된 수치만 설명 |

방향 표시는 조건부 상승/하락 가능성으로 표현한다. 기대수익률 구간이 0을 포함할 때는
“방향 불확실”을 표시하는 MVP 규칙을 제안한다. 규칙은 API에서 일관되게 적용한다.
상승확률 >50%와 기대수익률 >0은 서로 다른 조건이다.

## 4. 화면 구성

### 1. 발견: 이벤트 중심 홈

- 상단: 로고, 데이터 기준시각, 관심 자산 진입
- 헤드라인: “이번 발표, 내 관심 종목에는?”
- 주요 사건 1개를 큰 카드로, 나머지는 작은 일정 카드로 표시
- 사건 카드: 발표 일정, 측정 항목, 시장확률, “영향 살펴보기”
- 발표 일정 미확인 시 임의 카운트다운을 넣지 않는다.

### 2. 분석: 가장 먼저 구현할 핵심 화면

- 데스크톱: 이벤트/자산 선택 영역 + 넓은 결과 영역
- 모바일: 이벤트 → 종목 선택 칩 → 기간 → 주요 결과 → 근거 순서의 한 열
- 주요 결과: 큰 숫자 두 개(상승확률, 기대수익률), 구간, 독립 표본 수
- 시나리오 전환: 시장확률 혼합 / 특정 가정 시나리오
- 특정 가정을 고르면 “사용자 가정 시나리오”를 상시 표시한다.
- 근거: 유사 과거 사건, 분포, 자산 간 지연 연관성을 별도 상세로 제공

### 3. 내 구성: 포트폴리오 영향

- 자산과 비중을 입력하고 합계 100%를 검증한다.
- 누락된 종목을 제외한 채 나머지 비중을 몰래 재정규화하지 않는다.
- 원래 비중 대비 분석 가능 비중을 표시한다.
- 초기 MVP는 미지원 자산이 있으면 전체 포트폴리오 위험 계산을 중단하고 수정 안내한다.
- VaR/ES는 공동수익률·통화 변환 기준이 준비된 뒤 표시한다.

### 4. 이해하기: 용어와 근거

- “상승확률 60%는 수익률 60%가 아니다”처럼 한 가지 오해씩 설명
- 각 용어의 짧은 설명은 툴팁, 전체 설명은 상세 패널 또는 별도 화면
- 첫 화면에는 Brier, 아웃박스, 산출물 URI 같은 구현 용어를 노출하지 않는다.

## 5. Chakra UI 디자인 방향

Chakra UI는 디자인 시스템과 컴포넌트 기반이며 브랜드 완성도를 자동으로 보장하지 않는다.
공식 v3 카드, 분할 선택 컨트롤, 검색 선택 상자, 상세 패널, 로딩 자리표시자 등의 패턴을 활용하고
색상·타이포·간격·결과 카드 정보 구조를 프로젝트 전용으로 통일한다.
Pro 템플릿은 라이선스를 확보한 경우에만 소스를 사용한다.

| 요소 | 설계값 |
|---|---|
| 인상 | 밝고 차분한 금융 분석 서비스, 강조는 적게 |
| 기본 테마 | 시스템 설정을 따르는 밝은·어두운 테마, 시안은 밝은 테마 중심 |
| 밝은 테마 | 배경 `#F6F7FB`, 표면 `#FFFFFF`, 본문 `#182033` |
| 어두운 테마 | 배경 `#10131C`, 표면 `#1A2030`, 본문 `#F2F4FA` |
| 브랜드 | 남보라·보라 계열; 밝은 배경의 주요 동작 `#5848D5` |
| 방향 색상 | 한국 사용자 기본 상승 빨강·하락 파랑; +/−와 텍스트 병기 |
| 불확실 상태 | 중립 색상과 “방향 불확실”; 브랜드색을 상승 의미로 쓰지 않음 |
| 카드 | 모서리 반경 20~24px, 얇은 경계, 약한 그림자 |
| 간격 | 4/8px 단위, 모바일 바깥 여백 16~20px |
| 글자 | 한국어 가독성 우선, 본문 15~16px, 숫자 고정폭 정렬 |
| 움직임 | 입력 피드백 중심 150~200ms, 동작 줄이기 설정 대응 |
| 터치 | 주요 조작은 44px 이상, 마우스 올림 없이 근거 접근 |

의미 기반 토큰은 `surface`, `text`, `brand`, `direction.up`, `direction.down`,
`uncertainty` 등 역할별로 관리한다. 실제 조합의 명암비는 구현 단계에서 검증한다.

| 화면 요소 | Chakra v3 구성 후보 |
|---|---|
| 이벤트/결과 카드 | `Card.Root`, `Card.Header`, `Card.Body` |
| 기간 선택 | 공식 분할 선택 컨트롤의 `SegmentGroup` |
| 자산 검색 | `Combobox` |
| 탭과 시나리오 전환 | `Tabs`, `RadioCard` 또는 `SegmentGroup` |
| 근거 상세 | `Drawer`, `Accordion` |
| 입력/검증 | `Field`, `NumberInput`, `Alert` |
| 로딩/빈 상태 | `Skeleton`, `EmptyState` |
| 분포/추이 | Chakra Charts 기반 검토; 별도 의존성은 설치 시 결정 |

## 6. MZ 유입은 디자인 가설로 검증한다

연령만으로 취향을 단정하지 않는다. 초기 타깃 가설은 모바일로 경제 뉴스를 읽는
20~30대 투자 입문·초중급 사용자이며, 짧은 이해와 직접 선택을 중시하는지 확인한다.

| 가설 | 설계 | 측정 |
|---|---|---|
| 긴 가입 단계가 체험을 방해한다 | 로그인 없이 이벤트와 자산을 선택 | 첫 결과 도달률·소요시간 |
| 전문 용어가 이해를 방해한다 | 한 줄 요약 + 근거 펼치기 | 이벤트 확률/자산 확률 구분 정답률 |
| 내 관심 자산과 연결되면 다시 온다 | 로컬 관심 자산, 발표 전후 비교 | 실제 다음 발표 주기의 재방문 |
| 짧고 출처가 있는 설명은 공유하기 쉽다 | 후속 공유용 이벤트 요약 카드 | 공유 후 방문자의 분석 완료율 |

공유는 기준시각·기간·표본·가정을 포함한다. 포트폴리오 비중은 기본 공유 대상에서 제외한다.
합성 데이터는 항상 데모(DEMO)를 표시한다. 거래를 재촉하는 배지나 수익 경쟁 대신 이해와 비교를 중심으로 한다.
이 설계가 유입을 늘린다는 주장은 아직 검증 전이다.

## 7. API와 렌더링 책임: 후속 구현 계약

사용자 질문의 “렌더링 방식”은 어떤 분석 대상을 보여주느냐는 의미로 우선 해석한다.
브라우저 기술 측면의 제안은 Next.js 초기 화면 + 선택/차트 영역의 클라이언트 상호작용이다.
현재 SSR/CSR 구현은 없다.

- `/assets` 후보 계약: 종목 이름, 통화, 지원 이벤트·기간, 지원 상태
- `/analysis` 후보 계약: 자산·이벤트·기간·기준시점 조합의 검증 결과
- 결과 메타데이터: `model_version`, `dataset_snapshot`, `independent_event_count`, `observation_count`
- 결과 구간: 대상 통계량, 신뢰수준, 계산 방법, 하한·상한
- 응답 상태: `ready`, `insufficient_data`, `unsupported`, `stale`, `pending`, `error`

React는 JSON을 표현한다. Brier나 위험 계산을 컴포넌트에서 새로 수행하지 않는다.
입력 변경 시 이전 응답이 뒤늦게 새 결과를 덮지 않도록 요청 취소 또는 요청 식별자를 사용한다.
기준시각과 모델이 다른 자산 결과를 같은 표에서 무표시로 비교하지 않는다.

## 8. 구현 완료 점검표

- [ ] 360px 화면에서 핵심 내용을 가로 스크롤 없이 읽을 수 있다.
- [ ] 지원 자산·기간 선택이 요청과 결과를 함께 바꾼다.
- [ ] 합성 수치와 실제 분석 수치를 명확히 구별한다.
- [ ] 이벤트 확률과 자산 상승확률의 표시 이름을 구별한다.
- [ ] 표본 부족을 0% 또는 빈 그래프로 대체하지 않는다.
- [ ] 실제 종목 지원 목록은 설정 파일의 후보 목록과 분리한다.
- [ ] 결과마다 기간, 기준시각, 독립 표본 수, 구간의 의미를 확인할 수 있다.
- [ ] 신뢰구간을 미래 수익률 보장 범위로 표현하지 않는다.
- [ ] 새로고침·키보드·터치·어두운 테마·요청 역전 상황을 확인한다.
